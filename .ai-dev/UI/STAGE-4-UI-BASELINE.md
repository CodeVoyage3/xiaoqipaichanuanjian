# Stage 4｜UI/UX Pro Max 设计基线

- 状态：设计治理已形成，等待用户批准
- 适用阶段：S4-T05、S4-T06、S4-T07
- 技术栈：.NET 10 WPF，Windows 10 / 11
- 业务基线：S4-T01～S4-T04 已独立验收通过
- 设计参考：UI/UX Pro Max（Inventory & Stock Management、Data-Dense Dashboard、Flat Design、WPF accessibility/layout guidance）

## 1. 产品 UI 定位

这是门店员工长期使用的 Windows 生产工具，不是展示型 SaaS。界面服务于快速识别、连续录入、防误操作和明确恢复路径。

优先级固定为：

1. 信息识别速度。
2. 操作效率。
3. 状态清晰度。
4. 低学习成本。
5. 防误操作。
6. 长时间桌面使用舒适度。
7. 视觉美观。

整体方向：`数据密集 + 平面化 + 克制的 Windows 原生感`。采用浅色中性画布、白色工作表面、清晰边框、单一蓝色主操作和语义状态色；无装饰渐变、玻璃拟态、巨型数字卡墙、夸张大字、营销式色块或无业务含义动画。

UI/UX Pro Max 初次综合检索给出的 Bento Showcase、Exaggerated Minimalism、巨量留白和 GSAP 滚动揭示与本产品冲突，明确不采用。最终采用其更精确的 Inventory & Stock Management 与 Data-Dense Dashboard 建议：Flat Design + Minimalism、功能中性色、状态色、紧凑表格、固定表头、键盘可达和低动效。

## 2. 设计原则

- 一屏一个 Primary 操作；详情页唯一 Primary 为“完成排查”。
- 阶段、错误、重新确认和完成状态全部使用“颜色 + 文字”，不只靠颜色。
- 数据库加载失败、正常空数据、筛选无结果、Task 不存在必须是不同状态。
- 关键字段直接展示；正常批次等低频信息默认折叠。
- 鼠标和键盘均可完成核心流程；不依赖 hover、图标或隐藏手势。
- 表格以稳定列宽、清晰对齐和可扫描性优先，不过度卡片化。
- 使用 WPF `Grid` 的 Auto / `*` 布局，不使用 Canvas 绝对定位。
- 不新增字体、图标、动画或 UI 框架依赖。字体优先 Windows 系统字体；图标没有现成可靠资源时宁可使用清晰文字按钮。
- UI 只显示、收集输入、管理焦点和调用 Application；不得复制效期、Task、Draft、库存归零、版本、超库存或提交状态机。

## 3. 主窗口结构

```text
┌───────────────┬──────────────────────────────────────────────────────────┐
│ 软件名/标识    │ 页面标题 / 上下文动作 / 全局加载或错误状态                 │
│               ├──────────────────────────────────────────────────────────┤
│ 首页           │                                                          │
│ 待排查任务     │                    当前页面工作区                          │
│ 排查记录       │                                                          │
│ 数据导入       │                                                          │
│ 设置           │                                                          │
│               │                                                          │
│ 版本/数据状态   │                                                          │
└───────────────┴──────────────────────────────────────────────────────────┘
```

- 默认窗口建议：1280×760 DIP；最小可操作窗口：1024×600 DIP。
- Shell 为两列 Grid：左侧固定导航，右侧 `*` 主工作区。
- 宽屏（有效宽度 ≥1280 DIP）：导航 208 DIP，内容左右边距 24 DIP。
- 紧凑（1024～1279 DIP，覆盖 1366×768 在 125% 缩放下的约 1093×614 DIP）：导航 176 DIP，内容边距 16 DIP。
- 页面标题区高 56 DIP；全局反馈放在标题下方的固定行内区域，不以遮挡内容的浮动 toast 代替关键错误。
- 数据表填充可用宽度；1920 屏不把工作区强行限制到营销网站式窄栏，避免两侧大面积空白。
- 模态层仅用于确认或短表单；背景遮罩约 45%，模态框不超过可用窗口的 80% 宽高。

## 4. 导航规范

- 固定顺序：首页、待排查任务、排查记录、数据导入、设置。
- 导航项同时有文字与一致风格图标；若未建立可靠矢量图标资源，S4-T05 先用文字，不用 emoji。
- 默认项高 40 DIP；选中态使用 3 DIP 左侧主色指示条、浅蓝背景、加粗文字，三者共同表达。
- hover、pressed、focus、disabled 均需不同；键盘焦点为 2 DIP 高对比轮廓。
- Stage 5+ 尚未实现的目的地保留位置，但必须标明“后续阶段”或显示明确占位说明；不得做看似可用却无响应的导航。
- 从详情返回任务列表时恢复原搜索、筛选、页码与滚动位置。

## 5. 首页 Dashboard

页面采用三段式，不做满屏 KPI 卡墙：

```text
页面标题：门店效期排查                         [导入最新 Excel]
数据新鲜度条：最近导入时间 / 超过7天警告 / 加载失败
待排查 23   过期 4   收仓 6   2折 8   5折 5   [查看全部]
最紧急任务表：阶段 | 商品 | 编码 | 批次数 | 库存 | 最近有效日期 | 去排查
```

- “导入最新 Excel”为首页上下文主要入口，但不与“完成排查”跨页面竞争。
- 数据新鲜时使用普通次级文字；超过7天使用警告底色、警告图标与“数据已超过7天未更新”文字，不使用红色阻断样式。
- 待排查总数和四阶段为一行紧凑统计条，每项约 112～148 DIP 宽；点击阶段只导航到已带对应筛选的任务列表，不在 UI 重新计算阶段。
- 过期、收仓、2折、5折按风险从左到右，始终显示文字。
- 紧急任务列表直接复用 S4-T01 `UrgentTasks`，最多20条；不在 UI 再排序。
- 无任务时显示“当前没有待排查任务”，保留“刷新”和真实可用的数据导入入口。

### Dashboard 契约缺口

当前 `InspectionDashboardResult` 不含最近成功导入时间，仓库也没有职责匹配的轻量 Dashboard 导入状态查询。`ImportUndoEligibilityService` 会执行撤销资格及文件校验，不应只为显示时间而调用。

S4-T05 创建前必须明确最小解决方式：优先在现有具体只读查询边界增加“最新成功导入确认时间”普通 DTO 字段或最小方法，使用 `AsNoTracking` 与稳定排序；不得让 ViewModel/code-behind 直接查询 EF，不得调用撤销资格服务绕路，也不得伪造“7天未更新”。

当前也没有真实 WPF 数据导入页面。“导入最新 Excel”只有在存在真实导航目标时才能启用；不得交付无响应按钮。数据导入完整 UI 不得借 S4-T05 越界扩展。

## 6. 待排查任务列表

```text
待排查任务                                      共 126 个商品
[搜索商品名称/编码/条码________________] [搜索]
[全部] [过期] [收仓] [2折] [5折]          [清空筛选]
┌ 阶段 ┬ 商品名称/编码 ┬ 批次数 ┬ 库存 ┬ 最近有效日期 ┬ 操作 ┐
│ 过期 │ 某商品         │   3   │  12  │ 2026-08-20  │去排查│
└──────┴───────────────┴───────┴─────┴─────────────┴──────┘
第 1 / 3 页                                      [上一页] [下一页]
```

- 字段固定：商品名称、商品编码、最高阶段、待排查批次数、当前库存、最近有效日期、去排查。
- 商品名称 14 DIP Medium，为主视觉；编码 12 DIP 次级文字置于名称下方，不抢层级。条码用于搜索，不强占默认列。
- 列优先级：阶段、商品、最近有效日期、去排查最高；批次数与库存右对齐并使用等宽数字对齐。
- 行高 44 DIP，表头 36 DIP；行间使用 1 DIP 分隔线，不做每行卡片。
- 搜索回车触发；`Ctrl+F` 聚焦搜索框。筛选切换回第1页；页大小固定50，不向用户暴露选择器。
- 加载中保留表头和列宽，显示6～8行静态 skeleton 或进度条，避免布局跳动。
- 搜索无结果：“没有符合当前条件的任务”并提供“清空筛选”。
- 正常空库：“当前没有待排查任务”。
- 查询失败：“待排查任务加载失败”+简短原因+“重试”，绝不能显示为空任务。
- 整页不横向滚动；极窄紧凑模式可隐藏非核心辅助信息，但阶段、商品、最近有效日期和操作始终保留。DataGrid 自身只有在 DPI/系统字体增大导致确实无法容纳时才允许横向滚动。

## 7. 排查详情布局

详情页使用固定头部、可用高度内批次 DataGrid、默认折叠的正常批次和固定底部操作条：

```text
[返回任务列表]  商品名称                 [过期]  库存 12  批次 3 [修正库存]
商品编码 SKU-001 ｜ 条码 690... ｜ 草稿：已保存
检查人 [__________]   检查日期 [2026-08-28]   保存状态
┌生产日期┬有效日期┬阶段┬累计到货┬上次排查┬本次件数┬状态/动作────────┐
│   —    │08-20  │过期│   5   │ 0 / 日期 │ [ 0 ]  │已填写            │
│07-01   │09-03  │2折 │   8   │ 3 / 日期 │ [ 3 ]  │需重新确认 [确认] │
└────────┴───────┴────┴───────┴────────┴────────┴─────────────────┘
[其他正常批次（4） ▸]
未填写 1｜需重新确认 1                                      [完成排查]
```

- 商品头部始终高可见，名称、阶段、有效库存、待排查批次数和修正库存入口不随批次滚动消失。
- 商品编码/条码可换行但不隐藏；生产日期 null 显示 `—`。
- 检查人和检查日期使用可见标签，不用 placeholder 代替。检查日期默认当天属于 UI行为，但最终合法性只认 Application。
- 待排查批次 DataGrid 占剩余高度；表头固定。表头 40 DIP，普通行 48 DIP，重新确认行最少56 DIP。
- 列建议：生产日期 92、有效日期 92、阶段 76、累计到货 80、上次排查 126、本次件数 108、状态/动作 `*`（最小220）。
- `CheckedQty` 数字框视觉值严格区分空白、0、正数；禁止默认填0。输入框建议宽 88、高32 DIP，右对齐。
- 当前编辑行使用浅蓝背景和2 DIP焦点边框；错误行使用浅红底 + 错误文字，不只红框。
- 上次排查显示“数量 + 日期”，无记录显示“无”；详情不引入 Stage 5 编辑入口。

## 8. 正常批次

- 默认折叠，标题固定为“其他正常批次（X）”。
- 展开后只读显示生产日期、有效日期、当前阶段、累计到货；不提供 CheckedQty、重新确认或提交操作。
- 展开区最大高度约180 DIP，超过后区域内部滚动；不得把待排查表压缩到少于3个可见数据行。
- 正常批次的阶段仍显示文字，但使用更低视觉权重；`none` 显示“正常”。

## 9. 草稿与自动保存

状态显示在检查信息行右侧，安静且持续：

- `正在保存…`：小型进度符号 + 文字。
- `已保存 10:32`：成功图标 + 次级文字。
- `保存失败，请重试`：错误图标 + 文字 +“重试”按钮。
- `有未保存更改`：中性提示，不冒充已保存。
- 恢复既有 Draft 时在页头显示“已恢复未完成草稿”。

不得为每次成功保存弹 toast。建议输入停止约600ms或字段失焦后排队保存，同一 Task 的请求必须串行，避免旧请求晚到覆盖新值。

### SaveDraft 调用门禁

- 每次 SaveDraft 必须携带当前 TaskId、ProductId、BusinessDate、SavedAtUtc、当前 InspectorName、当前 CheckDate。
- `Items` 只包含本次 dirty TaskItem，但每项必须携带 TaskItemId、BatchId、页面观察到的 AttentionVersion 与 CheckedQty。
- 顶部 InspectorName/CheckDate 在现有 API 中是当前值写入，不是省略即保持；行自动保存不得传 null 而意外清空用户已填顶部字段。
- 保存失败时保留屏幕输入和 dirty 状态；未成功落库前不得显示“已保存”。
- 点击“完成排查”前必须先等待/刷新当前保存队列成功，再调用 S4-T04。S4-T02 readiness 只用于提示，不是提交授权。
- “清空草稿”为 Tertiary 低频动作，放在更多/次级区域；执行前确认“将清空当前未提交内容”，默认焦点在取消。只调用 S4-T02 ClearDraft。

## 10. RequiresReconfirmation

- 对应行使用浅紫提示底、更新图标和完整文字：“效期阶段或到货情况已更新，请重新确认”。
- 已填写 CheckedQty 原样显示，不清空、不自动变0。
- “未填写”使用中性/错误提示；“已填写但需重新确认”使用紫色更新提示，二者视觉和文案不同。
- 行内提供 Secondary“重新确认”按钮；仅当 CheckedQty 非空时可用。
- 点击只调用 S4-T02 `ReconfirmItem`，传当前 TaskItem/Batch/AttentionVersion；普通编辑或 SaveDraft 绝不能清除状态。
- 陈旧确认被拒绝后重新加载 GetDetail，保留明确说明，不解析异常字符串猜版本。

## 11. 库存修正

- 当前库存默认只读；“修正库存”为 Secondary，位于商品头部库存旁。
- 弹窗字段：当前库存只读、新库存数字输入、说明文字；新库存必须由 UI解析为非负整数后调用 S4-T03。
- 正库存：`取消` + `保存修正`。同值结果显示“库存未变化”，不伪造成功记录。
- 输入0时先进入危险二次确认，不先调用 API：

  > 库存修正为0后，将结束该商品所有批次的效期跟踪。此操作会系统关闭当前任务并使草稿失效。

- 二次确认按钮文案固定“确认修正为0”，使用 Danger；“取消”是默认焦点，Danger 不响应默认 Enter。
- 确认后只调用 S4-T03，`ConfirmProductTermination=true`。成功后必须重新加载详情；若 Task 已 system_closed，切换到关闭状态页，不继续显示编辑表单。

## 12. 超库存警告

S4-T04 返回 `RequiresOverStockConfirmation` 时显示警告确认，不表现为阻断错误：

```text
排查件数超过当前库存
当前库存：10    排查合计：12    超出：2
[返回修改排查件数] [修正库存] [确认仍然提交]
```

- 使用 Warning 琥珀色，不使用 Danger 红色。
- 默认焦点在“返回修改排查件数”。
- “修正库存”打开库存修正流程；完成后关闭警告并重新调用无确认的 Submit，让后台按新库存判断。
- “确认仍然提交”再次调用 S4-T04，只传上次结果返回的 ConfirmedEffectiveStockQty 与 ConfirmedTotalCheckedQty。
- 若后台返回新的警告事实，原地更新三个数字并明确提示“库存或排查数量已变化，请重新确认”，旧确认不能继续。

## 13. 正式提交

- 页面唯一 Primary 为“完成排查”，放在固定底部操作条右侧。
- 保存草稿是自动行为；重新确认/修正库存为 Secondary；返回/展开/清空筛选为 Tertiary；清空草稿为低权重破坏性文字动作；库存归零确认才是 Danger。
- 点击完成前，UI只做可用性提示：列出未填写批次、检查人、检查日期和需重新确认项，并将焦点移动到第一个问题。最终授权必须调用 S4-T04重新读库。
- 多问题时底部显示摘要：“还有2个批次未填写，1个批次需重新确认”，各问题可定位到对应行；字段旁仍显示具体原因。
- 提交中禁用会造成重复提交的操作，按钮显示“正在提交…”。失败时恢复可操作状态并给出明确重试路径。
- 不提供键盘快捷键直接正式提交，避免误操作；只能聚焦按钮后 Space/Enter执行。

## 14. 成功、关闭与异常状态

### Submitted

- 显示紧凑完成页：“排查已完成”+提交时间/商品名称+“返回待排查任务”。
- 立即关闭编辑能力并刷新列表；不做庆祝动画。

### AlreadySubmitted / completed

- 显示“该任务已完成排查”，可返回任务列表；不得恢复旧编辑表单或清理异常草稿。

### system_closed

- 显示“该任务已由系统结束”。若 `CloseReason == product_stock_zero`，补充“商品库存已归零，全部批次效期跟踪已结束”。
- 提供“返回待排查任务”，不显示完成按钮。

### not_found

- 显示“任务不存在或已不可访问”，提供返回列表；不得显示数据库错误文案。

### 后台状态变化

- Save/Reconfirm/Adjust/Submit 失败后重新调用 S4-T01 GetDetail 判断当前状态。
- 只能依据 GetDetail 的 `open / completed / system_closed / not_found` 和批准的 CloseReason 映射页面；禁止解析异常字符串推导业务状态。

### 数据加载失败

- 显示“数据加载失败”+可理解的安全摘要+“重试”+“返回任务列表”。
- 不把异常吞成空列表、not_found 或 system_closed。

## 15. 阶段视觉规范

阶段始终显示中文文字，颜色只作辅助：

| canonical | 显示 | 前景 | 背景 | 边框 | 层级 |
|---|---|---|---|---|---|
| `expired` | 过期 | `#A4262C` | `#FDECEC` | `#E5A3A8` | 最高风险 |
| `withdraw` | 收仓 | `#9A3412` | `#FFF0E5` | `#F2B58B` | 次高风险 |
| `discount_20` | 2折 | `#7A5900` | `#FFF8D6` | `#E5CE70` | 中风险 |
| `discount_50` | 5折 | `#1D4ED8` | `#EAF2FF` | `#9FC1F5` | 较低风险 |
| `none` | 正常 | `#475569` | `#F1F5F9` | `#CBD5E1` | 正常批次只读 |

阶段徽标高24～26 DIP，圆角4 DIP，文字12 DIP Semibold。不得设计为营销促销标签，不用“打折”图标。

## 16. 设计 token 建议

不建立复杂 Design System 框架；S4-T05 只需在 WPF资源字典中以语义资源集中定义。

### 颜色

| Token | 值 | 用途 |
|---|---|---|
| Canvas | `#F5F7FA` | 窗口背景 |

### 字体与尺寸

- FontFamily：`Segoe UI, Microsoft YaHei UI`，使用系统回退；不引入 Inter/Noto 字体包。
- 页面标题：24/32 DIP，Semibold。
- 区块标题：18/26 DIP，Semibold。
- 正文/表单：14/22 DIP，Regular。
- 表格正文：13/20 DIP，Regular；商品名称使用14 Medium。
- 标签/辅助：12/18 DIP，Regular或Semibold。
- 数量、库存、日期列启用 tabular/lining numerals，右对齐数量。

### 间距、圆角与高度

- 间距：4、8、12、16、24、32 DIP。
- 控件圆角：4 DIP；面板/弹窗：6～8 DIP；禁止大面积胶囊和过度圆角。
- 常规按钮高36 DIP；低频小按钮最小32×32 DIP；主要/危险动作高36～40 DIP。
- 输入框高32～36 DIP；任务列表行44 DIP；排查录入行48～56 DIP。
- 常规表面无阴影；仅弹窗使用轻微单层阴影，依赖边框建立主要层级。
- 交互过渡0～150ms，仅用于 hover/展开/状态淡入；尊重系统减少动画设置，不做列表入场动画。

## 17. 表格、表单与键盘规范

- Tab顺序与视觉顺序一致；导航 → 页面头动作 → 筛选/表单 → 表格行 → 底部动作。
- 排查表中 Tab 移到下一可编辑件数或重新确认按钮；Shift+Tab反向。
- Enter 提交当前数字单元格、触发保存排队并移动到下一待排查件数；Shift+Enter移动上一行。
- Esc只取消当前单元格未提交编辑，恢复最近屏幕/保存值；绝不清空整个草稿。
- `Ctrl+S`只触发/重试草稿保存，不正式提交。
- `Ctrl+F`在任务列表聚焦搜索框。
- 当前单元格、当前行和键盘焦点必须同时可见；焦点轮廓不随鼠标模式永久消失。
- 提交错误后滚动并聚焦第一个问题；重新确认成功后焦点移到下一待处理行。
- 输入只接受UI层可解析的非负整数；不在每次按键时弹错，失焦/提交时显示行内错误。
- 只读值与 disabled 控件视觉不同：只读仍保持正常可读对比度，disabled降低强调并不可交互。

## 18. 1366 / 1920 与 DPI

### 1366×768，100%

- 使用紧凑布局：导航176、内容边距16、表格紧凑列宽。
- 商品头信息允许两行；底部完成条固定可见。
- 整页无横向滚动，详情 DataGrid 可在必要时自身横向滚动。

### 1366×768，125%

- 按约1093×614有效DIP设计，窗口最小1024×600可完整操作。
- 页面标题、商品头和检查信息保持 Auto 高度；表格占 `*`，至少保留3个可见录入行。
- 正常批次默认折叠；展开区限制高度。

### 1920×1080

- 导航208、内容边距24，DataGrid充分扩展；不把内容收窄成1200网站栏。
- 可增加可见任务行数和状态列宽，但不得增加另一套交互或隐藏关键动作。

### DPI门禁

- 当前仓库未发现 PerMonitorV2 manifest。后续 WPF实现前必须核对实际应用DPI awareness；如需补充 manifest，应在相应任务卡明确授权并独立验证，不得在本治理文档中修改项目。
- 必测100%、125%、150%字体与控件裁切，至少覆盖1366与1920；不得使用依赖物理像素的Canvas定位。

## 19. Loading / Empty / Error 状态矩阵

| 状态 | 文案与表现 | 必须动作 | 禁止 |
|---|---|---|---|
| Loading | 保留页面骨架/列宽，“正在加载…” | 可取消页面导航 | 空白冻结 |
| Empty | 当前没有待排查任务 | 刷新/真实导入入口 | 当作错误 |
| FilterEmpty | 没有符合当前条件的任务 | 清空筛选 | 伪装空库 |
| Error | 数据加载失败 | 重试/返回 | 显示“暂无任务” |
| Saving | 正在保存… | 等待 | 弹窗轰炸 |
| Saved | 已保存 + 时间 | 无 | 持续强提示 |
| SaveFailed | 保存失败，请重试 | 重试 | 冒充已保存 |
| NeedsReconfirmation | 已填写但状态更新，需显式确认 | 重新确认 | 自动清除 |
| OverStockWarning | 当前库存/合计/超出量 | 返回修改/修库存/确认 | 红色阻断错误 |

| SystemClosed | 任务已由系统结束 | 返回任务列表 | 伪装 completed |

## 20. S4-T05 / S4-T06 / S4-T07 UI 门禁

### S4-T05

- 只实现 Shell、首页、待排查列表及其加载/空/错误/筛选/分页状态。
- 必须复用 S4-T01 查询 DTO和后台排序，不复制阶段优先级。
- 开工前解决或明确延期 Dashboard 最近成功导入时间的 Application 只读契约缺口；ViewModel/code-behind不得直查EF。
- “导入最新 Excel”必须有真实导航目标才启用；不得扩展完整导入UI来填补按钮。
- 不实现排查详情编辑、草稿、库存修正或提交。

### S4-T06

- 实现详情只读展示、正常批次折叠、检查人/日期/件数录入、草稿恢复/自动保存/清空、RequiresReconfirmation和库存修正。
- 严格调用 S4-T01/S4-T02/S4-T03；不得在 ViewModel 复制版本、库存0或生命周期规则。
- 自动保存队列必须串行，明确 dirty/saving/saved/failed，遵守顶部字段与Item patch契约。
- 不实现正式提交事务或超库存确认。

### S4-T07

- 实现完成排查、页面问题定位、S4-T04结果映射、超库存确认、提交成功、AlreadySubmitted/system_closed/not_found及真实列表刷新。
- 提交前只做UI可用性提示，最终门禁只认S4-T04。
- 0件批次停止、HandledAttentionVersion、Draft删除和Task completed均不得进入UI代码。
- 必须执行真实WPF人工验收：连续键盘录入、自动保存恢复、重新确认、库存修正、超库存三选项、0件停止、成功后不可编辑及列表刷新。

### 全阶段共同门禁

- 一个 WPF应用项目和测试项目，不新增UI框架/主题/字体依赖。
- ViewModel不得持有DbSet/IQueryable或tracked entity；Application异常不吞成空状态。
- 不在code-behind写业务规则；code-behind只允许纯视图焦点/窗口行为，且有明确边界。
- 所有阶段徽标使用同一 token与中文映射；所有页面使用同一按钮层级和状态语言。
- 1366×768、1920×1080、125%缩放、键盘焦点和对比度必须在每张前端卡验收。
- S4-T05未获批准前不得创建或实现；本基线获得用户批准后才允许创建第一张前端任务卡。

## 21. 主要设计风险

1. Dashboard 导入时间缺少职责匹配的只读 Application DTO；若不先治理，极易诱发 ViewModel直查EF或误用撤销资格服务。
2. 当前数据导入没有WPF页面，首页主要入口可能成为死按钮或诱发S4-T05越界。
3. 自动保存的顶部字段是当前值写入、Items是patch；调用参数组合不当会清空检查人/日期或产生乱序覆盖。
4. 详情页同时包含录入、重新确认、库存修正和提交，若按钮同权或状态语言不统一，会增加误操作。
5. 1366×768在125%缩放下有效高度有限；固定头/底过高会压缩录入表，因此必须使用紧凑高度并让正常批次默认折叠。
6. 当前未发现PerMonitorV2 manifest；DPI表现需要在前端任务内实测治理。
7. Application拒绝多为异常；UI不得解析异常字符串判断业务状态，应重查GetDetail并保留通用可恢复错误。

## 22. 批准建议

本基线建议批准作为 S4-T05～S4-T07 的统一 UI 门禁。批准进入 S4-T05 前，任务卡必须显式处理 Dashboard 最近成功导入时间的最小只读契约，并把“导入最新 Excel”限定为真实可用导航；除此之外不需要新增设计系统、依赖或业务状态。
