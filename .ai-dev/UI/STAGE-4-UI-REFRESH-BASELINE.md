# Stage 4｜核心 UI 重构定稿基线

- 状态：用户定稿，S4-T10 视觉权威基线
- 日期：2026-08-29
- 技术栈：.NET 10 WPF，Windows 10 / 11
- 业务基线：Stage 2 导入、Stage 3 生命周期、S4-T01～S4-T04 Application 能力及 S4-T05～S4-T09 已实现交互
- 适用页面：首页、待排查任务、排查详情（折叠/展开）、数据导入及共用 Shell

## 1. 权威顺序

```text
现有业务规则 / Application 事实
> S4-T10 功能边界
> 本文登记的用户定稿图
> 开发者个人判断
```

定稿图决定视觉层级、布局密度和交互位置，不得覆盖业务规则、伪造 DTO 数据或扩大 Stage 4 功能。

## 3. 必须保持的业务与交互事实

- UI 只调用现有 Application 能力；不得在 ViewModel/code-behind 推算阶段、生命周期、提交授权或异常业务状态。
- `ProductCode` 仍是商品唯一业务主体；Barcode 只展示和参与既有搜索。
- `CheckedQty` 保持 `null / 0 / 正数` 三态；Reconfirm 只调用既有用例。
- 正式提交仍由 S4-T04 唯一授权；超库存、0 件停止、Task completed、Draft 删除均不得在 UI 重写。
- Excel 仍是局部增量数据，不是全量快照；缺失行不得被 UI解释为删除。
- 不新增 schema、migration、业务状态、UI/MVVM/图标框架或第三方依赖。
- 排查记录、设置仍属后续阶段；导航保留但必须明确 disabled/后续阶段。

## 4. 统一视觉与可访问性

- 浅灰画布、白色内容区、轻边框、低饱和蓝主操作、高密度表格、6～8 DIP 克制圆角、少阴影。
- 禁止 Bento、玻璃拟态、大面积渐变、大阴影、满屏巨大按钮和新增品牌元素。
- `Language="zh-CN"`；固定中文优先 `Microsoft YaHei UI`，西文回退 `Segoe UI`；不得运行时繁转简业务数据。
- 页面标题约 22 DIP，区域标题 16～18，正文/表格 14，辅助文字 12～13。
- 间距只用 4 / 8 / 12 / 16 / 24 / 32；表格行高约 46～50。
- 蓝=主操作，红=危险/过期，橙=警告/收仓/2折，绿=成功/正常/5折；颜色必须配文字。
- 所有图标按钮必须有文字或 `AutomationProperties.Name`；Tab 顺序与视觉顺序一致，焦点始终可见。
- 图标如必须匹配定稿图，只允许复用/新增少量 WPF `PathGeometry` 资源；不得引入图标包。

## 5. Shell

- 固定左导航、右工作区；页面标题和上下文主操作位于右侧顶部。
- 统一产品名“门店效期排查软件”。定稿图中“效期排查系统”等差异不构成品牌改名授权。
- 导航顺序：首页、待排查任务、排查记录、数据导入、设置。
- 1024～1279 DIP 使用紧凑导航和 16 DIP 内容边距；≥1280 使用正常导航和 24 DIP 边距。

## 6. 首页

- 标题、说明和右上“导入数据”；搜索支持商品名称 / 商品条码 / 商品编码。
- 紧凑一行显示待排查、过期、收仓、2折、5折统计；不得恢复大 KPI 卡墙。
- 数据状态压缩成轻量一行，显示真实导入时间/状态；不存在的数据不得伪造。
- “优先处理”直接使用 Application 排序结果；表格字段：阶段、商品名称、商品条码、库存、最近有效期、操作。
- 首页按用户定稿不强制显示商品编码；“排查 →”为轻量按钮。
- 首页搜索复用既有 `SearchOpenTasks`，不在 UI重新过滤/排序。
- 定稿图中的当前商品/批次总数缺少现成 Dashboard DTO；允许对 `InspectionDashboardResult` 最小增加只读 `ProductCount`、`BatchCount`，只读现有表，不新增业务逻辑或 schema。
- “查看导入记录”没有当前 Stage 4 页面，不实现死入口。

## 7. 待排查任务

- 不显示“导入数据”；搜索名称/条码/编码。
- 阶段筛选固定：全部 / 过期 / 收仓 / 2折 / 5折。
- 字段：阶段、商品名称、商品条码、商品编码、批次数、库存、最近有效期、操作。
- 固定 50 条/页；只显示上一页 / 当前页 / 下一页。
- `SelectionUnit=Cell`；商品名称、编码、条码 `Ctrl+C` 只复制当前单元格。
- 保留现有 Application 搜索、过滤、分页和排序，不在 UI重复实现。

## 8. 排查详情

- 商品名称为主标题；条码在编码前；显示当前库存、待排查批次、排查人、排查日期。
- 待排查表字段：阶段、生产日期、有效日期、累计到货、上次排查、本次排查数量、状态/操作。
- Reconfirm 使用 Warning，不用 Danger；输入和状态必须保留 `null / 0 / 正数` 差异。
- “其他正常批次”默认折叠；展开字段：阶段、生产日期、有效日期、累计到货；第一列统一绿色“正常”，全部只读。
- 底部固定：草稿状态、清空草稿、修正库存、完成排查；“完成排查”是唯一 Primary。
- 折叠与展开只改变正常批次区，不改变商品、草稿或提交状态。

## 9. 数据导入

- 三段式：选择文件 → 导入预览 → 正在导入/完成。
- 预览只显示当前 Application 已提供的真实商品、批次、变更和异常事实。
- 点击确认后立即显示“正在导入，请稍候…”和 Indeterminate ProgressBar；禁止重复确认、假百分比和人为延时。
- 成功明确显示“导入成功”；失败只显示稳定安全提示，保留现有 Retry。
- 定稿图中的 `.xls`、20MB、导入记录或“基于导出数据”等文字不得覆盖现有 Stage 2 契约；本轮不新增 `.xls` 支持、文件限制或历史页。

## 10. 兼容性门禁

- 1024×600 基本可用；125% 缩放可用；不得提高窗口最小宽度规避问题。
- 首页/表格区域鼠标滚轮无死区；DataGrid 自身可滚动时保持自身滚动，到边界再交给父容器。
- 详情 Tab 可连续录入；固定底栏始终可达；正常批次展开不得遮挡底栏。
- 导入 Loading 明确；库存确认和超库存区域不裁切。
- Luna 与 Sol 均不操作 GUI；最终 Release GUI 由用户本人验收。

## 11. 明确非目标

- 不实现排查记录、设置、导入历史、提醒、导出、安装、备份恢复或 Stage 5。
- 不重构 Application/Domain，不重写现有 ViewModel 架构，不新增通用 Design System 工程。
- 不因定稿图示例数据修改用户商品名称、编码、条码或数据库内容。
