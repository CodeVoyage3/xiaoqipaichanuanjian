# 测试策略

## 原则

- 状态机与数据一致性优先于 UI 截图。
- 每个 Luna 编码任务至少留下一个能在命令行运行、失败时返回非零退出码的检查。
- 所有导入、提交、修改、归零和恢复测试均验证事务失败后的数据库状态。
- 真实 Excel 和真实 Windows 行为必须单独验收，不能用 mock 结果替代。

## 分层

1. Domain：纯函数/状态转换测试，不启动 WPF、不访问文件。
2. Integration：临时 SQLite 数据库，执行真实迁移、约束、事务和查询计划。
3. Excel round-trip：真实匿名样表，验证解析、预览、哈希校验、最后三列回填及格式保真。
4. Windows runtime：安装、托盘、关闭隐藏、退出、自启动、休眠恢复、提醒和覆盖升级。
5. Performance：10 万批次 + 30 万历史记录，记录硬件、数据种子、耗时和查询计划。

## 必须覆盖的高风险组

- 局部增量导入不触碰未出现商品/批次。
- 商品/批次唯一键与冲突行。
- 两套食品规则全部边界日。
- 当前最高阶段、商品级聚合、未完成任务升级和幂等生成。
- 批次 0 件、商品库存归零、旧批次永久不恢复、合法重新到货。
- 累计到货历史最高值下降/回升/突破。
- 草稿重新确认与失效。
- 仅最近一次正式记录修改影响当前状态。
- 日期回拨不降级。
- 导入/提交/恢复/迁移故障注入后的回滚。
- 导出只使用最新原始 Excel 和最近一次正式结果。

## 性能验收基线

- 至少使用 10 万批次 + 30 万历史排查记录。
- 启动不得全量扫描历史批次。
- 首页、待办、搜索、详情保持流畅。
- 大批量导入后台执行，界面不得假死或出现 Windows“未响应”。
- 测试必须记录硬件、数据种子、冷/热启动条件、耗时和查询计划；Stage 8 根据实测数据形成可复核的量化结果，不在 Stage 0 编造用户未指定的毫秒阈值。

## Stage 0 验收

- 文档完整、无业务代码。
- 仓库事实可复核。
- 技术方案覆盖桌面、数据、Excel、提醒、迁移、备份、扩展和测试。
- 未知项明确列出，不把推断写成已验证事实。
