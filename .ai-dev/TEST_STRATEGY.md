## 分层原则

1. Domain：纯计算与状态转换，不启动 WPF、不访问文件或数据库。
2. Integration：临时真实 SQLite，执行 migration、约束、事务、回滚和查询计划。
3. Excel：真实 `.xlsx` 与构造样本，验证表头规范化、共享字符串/日期/空值、重复冲突、预览、哈希和格式保真。
4. Windows runtime：真实 EXE/安装目录验证启动、托盘、关闭隐藏、退出、自启动、休眠恢复和提醒。
5. Performance：10 万批次 + 30 万历史排查记录，记录硬件、种子、冷/热条件、耗时和查询计划。

## Stage 2 必须先覆盖的高风险组

- Excel 为局部增量：文件完全缺少某历史商品，或包含商品但缺少其历史批次时，未出现记录的所有字段、任务和跟踪状态保持逐字段不变。
- 表头先 Trim；真实样表中带前导空格的 `该商品门店库存总数` 必须正确识别；规范化后重名列整份拒绝。
- 食品只按规范化后的 `商品大类 == 食品` 识别；非食品跳过且不影响已有食品数据。
- 商品编码唯一主体；空编码行异常；名称/条码变化只更新当前值。
- 两种批次唯一键；完全重复行忽略；同键冲突整组异常，不擅自选行。
- 同商品库存值冲突时不更新该商品库存、不触发归零，但其其他正常批次仍可按批准规则处理。
- Excel 最后三列即使有值，也不得生成正式排查记录。
- 选择文件只解析和预览，不写业务表；确认前文件哈希变化必须拒绝。
- 正式确认导入必须故障注入：任一步失败整次回滚，不允许半次导入；导入前快照失败不得开始写库。
- 同一文件无变化、同日多次导入、异常行与正常行并存、最近两份工作簿边界、最近一次撤销资格均需独立验证。

## 后续状态机高风险回归

- 一个商品最多一条开放任务，只生成当前最高阶段，不补历史阶段。
- 正式排查 0 件停止批次；商品库存归零结束商品全部批次，二者不得混淆。
- 累计到货只有突破历史最高值才是新到货；下降/回升不触发。
- 批次 0 件后的恢复必须同时满足商品从未归零、当前库存大于 0、累计到货突破历史最高值。
- 商品归零后的旧批次永久不恢复；库存恢复只跟踪真正新批次。
- 草稿重新确认/失效、仅最近正式记录修改影响当前状态、日期回拨不降级。
