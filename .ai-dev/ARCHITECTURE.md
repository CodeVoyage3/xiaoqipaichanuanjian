# 架构事实与 Stage 0 方案

> 当前仓库尚无业务实现。本文件记录已批准的设计基线，不冒充已完成代码事实。

## 运行形态

```text
WPF 主进程
├─ UI：窗口、托盘、提醒、进度与用户交互
├─ Application：导入预览/确认、排查提交、任务查询、备份恢复用例
├─ Domain：效期阶段、跟踪生命周期、商品任务聚合、状态优先级
└─ Infrastructure
   ├─ SQLite + EF Core migrations
   ├─ Excel 解析/回填
   ├─ 本地文件、日志、备份
   └─ Windows 自启动与电源恢复事件
```

- 不运行本地 HTTP 服务。
- 不把 Excel 当数据库。
- 不在窗口事件里实现业务规则。
- 大文件导入、备份、恢复和迁移使用后台任务，数据库写入仍由明确事务包围。
- 单实例运行，避免两个进程并发迁移或写库。

## 核心调用方向

`UI → Application → Domain`

`Application → Infrastructure`

Domain 只接收值对象/DTO，不依赖 WPF、EF Core 或 Excel 库。

## Excel 流程

1. 选择文件，只做只读解析。
2. 校验文件级字段；必要列缺失则拒绝。
3. 规范化行并分成正常、完全重复、冲突、行级异常、暂不支持品类。
4. 仅用本次出现的正常行与数据库比对，生成预览；未出现记录不参与变更集。
5. 用户确认后，先创建导入前数据库快照，再在单个数据库事务中应用变更并保存原始工作簿 BLOB 与哈希。
6. 同一事务只保留最新、上一份两个原始工作簿；任一步失败均整次回滚。
7. 导出时从数据库取出最新原始 Excel 的副本，只回填最后三列，不拼接历史记录。

解析、变更规划、事务应用是三个独立步骤。预览结果携带源文件哈希；确认前重新校验哈希，防止预览后文件被替换。

## 任务与状态机

- 批次触发，商品聚合；同一商品最多一条开放任务。
- 批次只计算当前最高阶段，不补历史阶段。
- 阶段推进或真正新到货会推进批次的 `attention_version`。
- 开放任务中的对应批次项原位升级，不创建重复商品任务；已有草稿标记需重新确认。
- 正式提交 0 件停止批次跟踪；大于 0 则等待下一阶段。
- 商品明确库存为 0 的优先级最高，结束该商品当前生命周期并自动关闭任务。
- 商品发生库存归零后，通过商品 `lifecycle_generation` 隔离旧批次；库存恢复只允许数据库从未出现过的新批次进入当前代。
- 时间回拨只告警，不允许任务降级或改写历史。

## 启动与提醒

- 启动只查询 `tracking_status = active AND next_trigger_date <= today`。
- 首次成功导入前不生成任务、不提醒。
- 启动、休眠恢复、成功导入后运行到期检查。
- `last_reminder_date` 持久化，每个本地自然日最多主动提醒一次。
- 首页“7 天未更新”只读取最近成功导入日期，不弹系统窗。

## 本地数据布局

```text
%LOCALAPPDATA%/StoreExpiryInspector/
  data/app.db
  backups/
  logs/
```

最近两份原始 Excel、设置和全部业务数据均在 `app.db`；手动完整备份由用户选择目标路径。路径命名是暂定值，Stage 1 首任务锁定后不得随意更改。
