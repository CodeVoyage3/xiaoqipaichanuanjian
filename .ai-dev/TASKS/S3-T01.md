## 目标

实现一个完全确定性的食品效期计算能力。调用方显式提供业务日期、有效日期、保质期值和保质期单位；计算当前唯一阶段及与该阶段严格对应的下一触发日期。

本卡只实现纯 Domain 计算和对应自动测试，不读取系统当前时间，不访问数据库，不修改任何持久化实体状态，也不生成任务或生命周期事件。

- 已有正式命名是 Batch 的 `current_stage` / `CurrentStage`、ProductTask 的 `highest_stage` / `HighestStage`，以及 TaskItem/Inspection 的 `stage` / `stage_snapshot`。
- 已有唯一持久化阶段代码约定：

- `highest_stage`、任务项和排查快照只允许后四种待排查阶段；正常阶段 `none` 不生成开放任务，因此不属于这些字段的值域。

## 输入契约

调用方必须显式提供：

- `businessDate`：业务日期，使用 `DateOnly`。
- `expiryDate`：有效日期，使用 `DateOnly`。
- `shelfLifeValue`：保质期值，必须大于 0。
- `shelfLifeUnit`：保质期单位，只接受严格大写 `D`、`M`、`Y`。

不得把生产日期加入必需输入，不得由有效日期和保质期反推生产日期。

不得读取或间接读取 `DateTime.Now`、`DateTime.Today`、`DateTime.UtcNow`、`DateOnly.FromDateTime(DateTime.Now)` 或任何系统时钟。相同输入必须始终得到相同结果。

## 总保质期换算

- `D`：原值。
- `M`：值乘以 30。
- `Y`：值乘以 365。
- `9M` 必须等于 270 天，因此使用短效期规则。

输入拒绝规则：

- `shelfLifeValue == 0`：明确拒绝。
- `shelfLifeValue < 0`：明确拒绝。
- 单位不是严格大写 `D/M/Y`，包括空、空白、小写或其他值：明确拒绝。
- 换算乘法超过 `Int32` 可表示范围：明确抛出溢出错误，不得截断、回绕、饱和或回退到其他规则。

生产 API 必须使用清晰、稳定的参数/溢出异常；测试应固定非法值与算术溢出的行为。

## 当前阶段规则

先以自然日计算：

`remainingDays = expiryDate - businessDate`

业务日期等于或晚于有效日期时直接为 `expired`。

### 总效期小于等于 270 天

| 剩余天数 | 当前阶段代码 |
|---|---|
| `> 30` | `none` |
| `<= 30 && > 14` | `discount_50` |
| `<= 14 && > 7` | `discount_20` |
| `<= 7 && > 0` | `withdraw` |
| `<= 0` | `expired` |

### 总效期大于 270 天

| 剩余天数 | 当前阶段代码 |
|---|---|
| `> 90` | `none` |
| `<= 90 && > 60` | `discount_50` |
| `<= 60 && > 14` | `discount_20` |
| `<= 14 && > 0` | `withdraw` |
| `<= 0` | `expired` |

节点当天立即进入新阶段。同一输入只能命中一个阶段。

本能力只计算当前结果：调用方离线跨越多个阶段时，直接返回当前最高阶段，不回放、不返回阶段历史、不生成历史任务或事件。

## 下一触发日期规则

结果必须同时包含 `NextTriggerDate`，并与本次返回的当前阶段严格对应。

### 总效期小于等于 270 天

| 当前阶段 | 下一触发日期 |
|---|---|
| `none` | 有效日期前 30 天 |
| `discount_50` | 有效日期前 14 天 |
| `discount_20` | 有效日期前 7 天 |
| `withdraw` | 有效日期当天 |
| `expired` | `null` |

### 总效期大于 270 天

| 当前阶段 | 下一触发日期 |
|---|---|
| `none` | 有效日期前 90 天 |
| `discount_50` | 有效日期前 60 天 |
| `discount_20` | 有效日期前 14 天 |
| `withdraw` | 有效日期当天 |
| `expired` | `null` |

除 `expired` 外，返回的下一触发日期必须严格晚于当前业务日期；不得返回已经过去的边界日。
