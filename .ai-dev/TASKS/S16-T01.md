## 风险口径

业务日为本次查询的 `businessDate`。每个阶段节点必须来自现有 `ExpiryPolicyCalculator.CalculateStageDates`，不得复制阈值或另建规则。

- 一个节点命中窗口当且仅当 `businessDate < effectiveDate <= businessDate + N`，其中 N 为 7、14、30；今日节点不算“未来”，第 N 天包含，第 N+1 天不包含。
- 候选只包含：`Batch.TrackingStatus == active`、`Product.EffectiveStockQty > 0`、商品为 `Managed`、policy/version 为现有受支持 V1、且对应 scope baseline 已完成。
- 每个矩阵单元格按 `ProductId` 去重计“风险商品数”，与现有 `ProductTask` 按商品聚合口径一致。同一商品多个批次命中同一单元格仍只计 1；明细也只显示 1 行，因此点击数字必须等于明细总行数。
- 同一商品因真实不同阶段节点出现在不同阶段列，或因 7/14/30 为累计窗口出现在多个时间行，属于合同语义，不是重复计算。
- 同一单元格内多个批次命中时，以目标节点日期最早、再以 `BatchId` 最小者作为该商品明细代表批次；“当前阶段”与“预计进入日期”必须来自这一批次和同一 policy 计算。
- 明细默认按预计进入日期、商品编码、`ProductId` 稳定排序。
