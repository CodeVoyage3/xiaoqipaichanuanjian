## 目标

只实现固定系统 `.xlsx` 模板的只读解析能力：读取工作簿首个工作表，计算源文件 SHA-256，规范化并校验表头，把本卡批准的列读取为与 EF 实体隔离的普通 DTO。

本卡不访问数据库，不做食品、重复、冲突、库存、增量或状态判断，不形成导入预览，不写入任何业务记录。

## 必须实现

### 1. 最小读取入口

- 提供一个具体、可直接调用的只读读取类；不要为单一实现创建接口。
- 输入为 `.xlsx` 文件路径。
- 使用 Open XML SDK 只读打开，正确释放文件句柄；不得修改、保存或重写源工作簿。
- 文件不存在、不是可读 `.xlsx`、没有工作表、首个工作表不存在或表头非法时，使用清晰的标准异常（优先 `FileNotFoundException` / `InvalidDataException`），不建设异常类型层级。
- 固定读取工作簿顺序中的首个工作表；不做工作表名称配置、自动猜测或反射扫描。
- 使用流式读取或等价的有界方式遍历行，不为 3,712 行样表建立多份完整工作簿对象副本。

### 2. 文件身份

- 使用 .NET 标准库计算源文件 SHA-256。
- 输出固定为 64 位小写十六进制。
- DTO 至少保存源文件名、SHA-256、工作表名、规范化表头和数据行。
- 哈希计算和解析均不得改变文件内容、时间戳或文件长度。

### 3. 表头规范化和必要列

- 表头必要规范化只做首尾空白 Trim；不要擅自做大小写、全半角、标点、内部空格、同义词或模糊匹配。
- Trim 后的空表头按文件级错误拒绝。
- 任意两个原始表头 Trim 后同名时，整份文件以 `InvalidDataException` 拒绝，并在消息中列出重复的规范化列名；不得任选一列。
- 缺少任一必要列时整份拒绝，并在消息中一次列出全部缺失列。
- S2-T01 必要列固定为：
  - `商品大类`
  - `商品编码`
  - `商品条码`
  - `商品名称`
  - `生产日期`
  - `有效日期`
  - `保质期`
  - `保质期单位`
  - `是否该做临期折扣`
  - `该批次累计到货数量`
  - `该商品门店库存总数`
- 允许工作簿存在其他列；本卡不解释其他列的业务含义。

### 4. 普通解析 DTO

- DTO 不得引用 EF、DbContext、Domain 实体或 WPF 类型。
- 每一数据行保留真实 Excel 行号。
- 行 DTO 至少包含上述 11 个必要列的原始文本值；空单元格使用 `null`，不要在解析层判定是否合法。
- 不把日期转换为 `DateOnly`，不把库存、保质期或累计到货转换为整数；业务解析和校验属于 S2-T02。
- 不在 DTO 中增加新增/更新、食品、重复、冲突、异常、任务或生命周期字段。

### 5. 商品编码和条码的标识文本语义

- `商品编码`、`商品条码` 输出类型必须为 `string?`，不得为 `long`、`double`、`decimal` 或其他数值类型。
- 共享字符串、内联字符串和普通字符串必须按文本原样读取。
- 对数值单元格不得先转换为 `double`；必须从 Open XML 原始值生成稳定文本，避免二进制浮点或默认科学计数格式造成精度损失。
- 原始数值采用科学计数法时，若其表示整数标识，输出必须为不含指数符号的完整十进制文本；转换不得经过 `double`。
- 前导零文本标识必须逐字符保留，例如 `001234567890` 仍为 `001234567890`。
- 不建设完整 Excel 自定义数字格式渲染器；本卡只承诺保留文本前导零，以及将原始科学计数整数安全展开为十进制标识文本。

### 6. 行读取边界

- 按实际单元格引用处理稀疏行，不能把缺失单元格造成的列位移当成下一列值。
- 表头之后的完全空白行不产生 DTO。
- 非空行只做读取，不因字段空白、非食品或数值格式异常而在 S2-T01 分类为业务异常。
- 共享字符串、内联字符串、布尔、普通字符串和数值单元格至少能安全读取；样表无公式，本卡不计算公式。
