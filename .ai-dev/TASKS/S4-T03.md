## 一、目标

只在 Application 层实现：

`读取当前 Product → 明确修正整数 → 写 InventoryAdjustment → 更新当前有效库存`

修正为 0 时必须先取得调用方明确二次确认，并在同一 SQLite 外层事务内复用已经验收的 `ProductStockZeroLifecycleUseCase`：

`Adjustment + Product 库存为 0 → SaveChanges → S3-T04 商品归零 → 统一 Commit`

本卡不接 WPF，不解析文本框，不实现正式排查提交，不创建第二套商品归零规则。

## 二、开工前仓库事实

任务卡创建时已重新核对：

- Product 当前 Excel 库存为 `ExcelStockQty`，当前有效库存为 `EffectiveStockQty`，来源为 `EffectiveStockSource`；人工来源既有事实值为 `manual`。
- Product 商品级历史字段为 `IsStockZeroTerminated` 与 `LifecycleGeneration`；库存恢复不得清除或回退它们。
- InventoryAdjustment 只有 `Id`、`ProductId`、`ExcelStockQtySnapshot`、`AdjustedStockQty`、`AdjustedAtUtc` 五个字段。
- `inventory_adjustments.product_id → products.id` 为 NoAction FK；两个库存字段都有非负 CHECK。
- LifecycleEvent 有 `SourceAdjustmentId`；其 FK 只证明 Adjustment 存在，不能在数据库层证明与事件 Product 相同。
- S3-T04 请求为 `ProductStockZeroRequest(ProductId, OccurredAtUtc, SourceImportId?, SourceAdjustmentId?)`。它要求当前事务可见的 EffectiveStockQty 为 0，并显式校验 Adjustment 存在、同 Product 且 AdjustedStockQty 为 0。
- S3-T04 在存在外层事务时加入而不提交；上游必须先 SaveChanges，使 Product=0 和 AdjustmentId 当前事务可见。
- Stage 2 合法 Excel 库存更新会同时更新 `ExcelStockQty`、`EffectiveStockQty`、`EffectiveStockSource=excel`，且不得因库存为 0 自行执行生命周期。
- S3-T05 只把累计到货首次突破历史最高视为真正新增到货；商品曾归零后的旧 existing Batch 永久不自动恢复，只有真正新批次键可进入 Product 当前 generation。
- 当前仍为 17 张业务表、17 个实体/配置/DbSet、8 条 migration；现有 schema 足以表达本卡，不新增字段或 migration。

如实现发现上述结构不能可靠承载任务，立即停止并报告 Sol，不得猜字段、扩表或改 migration。

## 三、最小 Application 契约

新增一个具体用例，例如 `ManualInventoryAdjustmentUseCase`，不得创建接口加单实现、Repository、UnitOfWork、库存框架或通用状态机。

请求最少包含：

- `ProductId`：正整数。
- `CorrectedStockQty`：调用方已经解析完成的非负整数，不接受 nullable、字符串或小数。
- `ConfirmProductTermination`：修正为 0 时必须为 true。
- `AdjustedAtUtc`：调用方显式提供的 UTC 时间。

返回普通 record，至少表达：

- `Changed` / `NoChange`。
- 本次 `AdjustmentId`；无变化时为空。
- `PreviousEffectiveStockQty`。
- `CorrectedStockQty`。
- `ProductTerminated`，取 S3-T04 本次返回的真实事实，不自行推导。

可直接包含 S3-T04 的最小计数结果；不得返回 tracked entity、DbSet 或 IQueryable。

## 四、输入、时间与同值门禁

任何写入前验证 ProductId > 0、CorrectedStockQty >= 0、AdjustedAtUtc 为 UTC、Product 存在；修正为 0 时 ConfirmProductTermination 必须为 true。

零库存确认优先于同值判断：当前库存已经为 0，请求 0 但未确认仍拒绝；已确认后才可返回同值无变化。

Application 不读取系统时间，不解析 UI 字符串。当前实体与 S3-T04 没有批准额外业务时间下限，本卡不得增加复杂回溯规则；Adjustment、Product 更新时间及 S3-T04 OccurredAtUtc 使用同一个已验证时间。

重新读取当前 Product 后，如果 CorrectedStockQty == EffectiveStockQty：

- 返回 NoChange，AdjustmentId 为空。
- 不创建 InventoryAdjustment，不修改 Product 或时间戳，不调用 S3-T04。
- Batch、Task、Draft、Inspection、LifecycleEvent 全部不变。

## 五、普通正库存修正

CorrectedStockQty > 0 且与当前有效库存不同，事务内只执行：

1. 新建 InventoryAdjustment：ProductId 为当前商品，ExcelStockQtySnapshot 取当前 Product.ExcelStockQty，AdjustedStockQty 与 AdjustedAtUtc 取请求事实。
2. Product 只更新 EffectiveStockQty、EffectiveStockSource=`manual`、UpdatedAtUtc。
3. SaveChanges 并按事务所有权提交。

不得修改 Product.ExcelStockQty、LastSeenImportId、IsStockZeroTerminated、LifecycleGeneration 或其他 Product 字段。

不得修改或创建 Batch、Task/Item、Draft/Item、Inspection/Item/Revision、LifecycleEvent；不得调用 S3-T05、S3-T06，库存上升不等于新到货。

商品曾归零后修正为正数时，只更新上述当前库存事实并保留 Adjustment：不得清除归零历史、恢复旧 Batch、重开旧 Task、恢复失效 Draft或改写旧 Batch generation。

## 六、连续手工修正

Product.ExcelStockQty=10 时，`Effective 10 → manual 8 → manual 6` 应留下两条 InventoryAdjustment；两条 ExcelStockQtySnapshot 都为最近一次有效 Excel 事实 10，AdjustedStockQty 分别为 8、6，Product 最终 EffectiveStockQty=6、来源 manual。

不得把第一次修正后的 EffectiveStockQty=8 错写成第二条 ExcelStockQtySnapshot，不得覆盖或删除第一条历史。

## 七、确认后的 0 库存编排

CorrectedStockQty == 0、已确认且与当前有效库存不同，必须：

1. 开启自有事务或加入当前外层事务。
2. 创建本次 InventoryAdjustment，快照仍取当前 Product.ExcelStockQty。
3. 把 Product.EffectiveStockQty 设为 0、EffectiveStockSource 设为 `manual`、UpdatedAtUtc 设为 AdjustedAtUtc。
4. 调用 SaveChanges，使 AdjustmentId、Adjustment.ProductId/AdjustedStockQty 与 Product=0 在当前事务可见。
5. 只调用 `ProductStockZeroLifecycleUseCase.Execute`，传入相同 ProductId、相同 UTC 时间、`SourceAdjustmentId=本次 Adjustment.Id`，SourceImportId 为空。
6. 由 S3-T04 重新查询并校验 Adjustment 存在、属于目标 Product且修正值为 0。
7. 最外层事务统一 Commit。

S4-T03 不得手工设置 Product 归零标志/generation，不得停止 Batch、关闭 Task、失效 Draft 或写 LifecycleEvent。

S3-T04 已负责首次商品级归零、所有历史/当前 Batch 终止、开放 Task system_closed、有效 Draft 原地失效保留，以及批准的 product/task/draft LifecycleEvent。

## 八、Adjustment 来源安全

本卡请求不接受调用方传入 AdjustmentId。0 库存流程只能把本次事务刚创建、ProductId 为当前目标、AdjustedStockQty 为 0 的 AdjustmentId 传给 S3-T04。

S3-T04 必须继续复核 Adjustment 存在、Adjustment.ProductId == 请求 ProductId、AdjustedStockQty == 0，且 SourceImportId/SourceInspectionId 为空。测试必须保留跨商品、非零值和不存在 Adjustment 调用 S3-T04 被拒绝的组合证据，不能只依赖 FK。

## 九、已归零商品与后续库存恢复

- 当前 EffectiveStockQty 已为 0：确认后的 0 请求按同值 NoChange，不增加 Adjustment/generation/event，不改终态时间。
- Product 曾归零但当前库存已变为正数：正库存修正只改变当前库存，不清除 IsStockZeroTerminated，不恢复旧事实。
- Product 曾归零、当前正库存再次修正为 0：创建 Adjustment 并调用 S3-T04；S4-T03 不解释关联状态，S3-T04 只修复尚未满足的批准终态且不重复推进 Product generation/product_stock_zero 事件。
- 后续真正新批次及其任务只由 S3-T05 使用明确 Import new/existing 事实处理。

## 十二、事务与失败清理

普通正库存修正的 Adjustment + Product 更新必须同一事务。0 库存的 Adjustment + Product 当前库存 + S3-T04 Product/Batch/Task/Draft/Event 状态必须同一 SQLite 外层事务。

- 无当前事务时，本用例拥有事务，成功统一提交；任一步失败统一 rollback 并清理 ChangeTracker。
- 已有外层事务时加入而不 commit/rollback；失败不得抢夺所有权，调用方必须回滚外层事务。本用例需清理或恢复本次 tracked 变化，不能伪装成功。
- 不允许嵌套独立提交，不允许 Adjustment 永久提交后才调用 S3-T04。
- 使用真实 SQLite trigger 等故障注入证明 Adjustment insert、Product update、S3-T04 Event/Task/Draft 中途失败整体回滚。
