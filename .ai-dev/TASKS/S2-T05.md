## 目标

在正式导入事务开始前，使用 SQLite 原生在线备份能力为当前业务数据库创建一致、独立、可验证的 `pre_import` 快照。只有快照创建、结构核对、完整性检查、只读打开和哈希计算全部成功，才返回允许后续导入继续的纯内存结果。

本卡只创建并验证快照文件，不执行导入，不修改当前业务数据库，不写入 backups 或 imports。快照元数据仅以内存 DTO 返回，供 S2-T06 在正式事务中持久化关联。

## 最高安全边界

- 当前数据库使用 WAL，严禁用 `File.Copy(app.db)` 充当安全快照；必须使用已安装的 `Microsoft.Data.Sqlite` 在线 `BackupDatabase` API，确保包含 WAL 中已提交内容并获得一致视图。
- 任何创建、验证、哈希或最终落位失败都必须返回阻断结果；不得留下“可继续导入”的契约。
- 源数据库连接必须只读；快照流程不得调用 SaveChanges、执行 INSERT/UPDATE/DELETE、migration 或任何业务写入。
- 成功和失败两条路径都不得改变源数据库任何业务、审计或元数据字段。
- 临时快照与最终文件必须在同一目标目录；临时文件验证成功后使用同卷原子改名发布。

## 输入与路径规则

一个具体 `PreImportSnapshotService` 接收：

- 当前源数据库文件路径。
- 快照目标目录。

规则：

- 两者必须非空；源路径和目标目录均先 `Path.GetFullPath` 固化。
- 源文件必须存在且是普通文件；目标目录不存在时允许创建。
- 目标目录不得解析成源数据库文件路径；生成的临时/最终路径不得与源文件相同。
- 快照文件独立命名：`pre-import-{UTC时间}-{随机唯一后缀}.db` 或等价稳定格式；同一时刻连续创建不得碰撞或覆盖已有文件。
- 临时文件使用同名隐藏后缀或 `.tmp`，与最终文件处于同一目录；不得覆盖任何既有文件。
- 失败清理只能删除本次服务自行生成并已精确记录的临时/最终候选，不得使用通配符、递归删除或触碰源数据库及其他快照。

## SQLite 在线快照

- 使用 `Microsoft.Data.Sqlite.SqliteConnection` 打开源数据库，连接模式明确为只读。
- 使用单独目标连接创建临时数据库并调用 SQLite 在线 `BackupDatabase`；不手工复制 `.db`、`-wal`、`-shm`。
- 备份完成后关闭写连接，再以 SQLite `Mode=ReadOnly` 打开临时快照进行验证。
- 源库不存在、无法打开、被独占、不是合法 SQLite、在线备份失败或目标创建失败，均返回失败结果并阻断后续导入。
- 不为快照切换源库 journal mode、不 checkpoint、不 vacuum、不 migrate。

## 成功验证门禁

临时快照必须全部通过：

1. SQLite 只读连接可正常打开。
2. `PRAGMA quick_check` 或更强完整性检查精确返回 `ok`。
3. `PRAGMA foreign_key_check` 无结果。
4. 源库与快照的非 `sqlite_%` 表名集合完全一致。
5. 当前 17 张关键业务表和 `__EFMigrationsHistory` 均存在。
6. 源库与快照 `__EFMigrationsHistory` 的 migration ID 有序集合完全一致、非空；当前基线为 8 条。
7. 源库与快照的关键 schema 元数据可读取，快照 `page_count > 0`。

验证失败不得发布最终快照。全部通过后才：

- 计算快照文件 64 位小写 SHA-256。
- 将临时文件原子改名为最终 `.db`。
- 确认最终文件存在、大小大于 0且 SHA 与验证前一致。
- 返回成功结果与纯内存元数据。

## 纯内存结果与元数据

结果至少提供：

- `CanProceed` / 等价布尔值；失败时永远为 false。
- 稳定结果代码和安全摘要。
- 成功时唯一的 `PreImportSnapshotMetadata`，失败时必须为 null。

成功元数据至少包含：

- `BackupType = pre_import`。
- 源数据库绝对路径。
- 最终快照绝对路径。
- 快照 SHA-256。
- UTC 创建时间。
- `VerificationStatus = verified`。
- 快照文件大小。
- 已验证的 migration ID 只读集合。

这些字段与现有 `backups` / `imports.pre_import_snapshot_path` 后续写入口径对齐，但本卡不得实例化或写入 `BackupRecord` / `ImportRecord`。源路径只用于内存追溯，不要求修改现有 schema。

失败代码至少区分：

- `source_missing`。
- `source_unavailable`。
- `destination_unavailable`。
- `snapshot_failed`。
- `verification_failed`。

不向安全摘要泄露堆栈、连接字符串或敏感系统细节。

## 必须测试

### 真实 WAL SQLite 成功路径

- 使用 `SqliteTestDatabase` 应用全部 migration 并写入至少 Product、Batch、Import、Backup、Task/Lifecycle 中的代表数据。
- 保持 WAL 场景并确保存在已提交数据，调用在线快照；不得先用普通文件复制或主动 checkpoint 掩盖风险。
- 成功结果 `CanProceed = true`，元数据类型、路径、SHA、verified、大小和 8 条 migration 正确。
- 以 SQLite 只读模式直接打开最终快照，`quick_check = ok`、外键检查为空、17 张业务表和 migration history 存在，代表数据逐字段等于源库。
- 最终快照能够在独立 context/connection 中查询，不依赖源库 `-wal` / `-shm` 文件。

### 源库绝对不变

- 快照前后使用全新 context 对所有业务表行数进行比较。
- 对代表 Product、Batch、Import、Backup、Task、Lifecycle 的全部字段逐字段比较。
- 源数据库主文件、WAL/SHM 是否存在不作为业务字段变化判断；不得声称文件级 hash 必然不变。
- 源库中不得新增 BackupRecord 或 Import；ChangeTracker 无本服务引入的写状态。

### 局部失败与故障注入

- 源文件不存在：`source_missing`，无最终文件、无元数据。
- 源文件被 `FileShare.None` 独占或无法打开：`source_unavailable` / `snapshot_failed`，阻断后续。
- 目标目录路径被普通文件占用、目标不可创建或不可写：`destination_unavailable`，不修改源库。
- 源文件是损坏/非 SQLite 内容：在线打开或备份失败，返回 `source_unavailable` / `snapshot_failed`。
- 使用可打开但缺少关键表/migration history 的真实 SQLite：备份可完成但验证返回 `verification_failed`，不发布最终文件。
- 验证失败后没有 `.db` 最终快照，只有本次临时文件被清理；其他预存文件保持逐字节不变。
- 连续成功创建两份快照：路径不同、两份均有效，不能覆盖第一份。

### 结构与边界

- 源与快照表集合、migration IDs 精确一致；缺关键表或 migration 不得标记 verified。
- 成功 SHA 对最终文件重新计算一致；篡改最终文件后独立验证必须失败，不能继续使用旧元数据冒充有效。
- 源码搜索证明使用 `BackupDatabase`，没有 `File.Copy` 复制数据库，没有 SaveChanges、INSERT/UPDATE/DELETE、BackupRecord/ImportRecord 实例化、checkpoint、VACUUM、恢复替换或 Excel 逻辑。

所有测试目录必须唯一且可清理；不得使用真实用户数据库或默认 `%LOCALAPPDATA%` 路径，不得提交生成的 `.db`、`-wal`、`-shm`、`.tmp`。
