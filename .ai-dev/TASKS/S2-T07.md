## 目标

在 S2-T06 已有成功导入事务内建立一个不变量：数据库只保留最近两次 `Succeeded` 正式导入对应的原始 Excel 工作簿；所有 Import 事实和其他业务历史永久保留。

本卡只裁剪旧 `ImportWorkbook` 行。当前 `content` 为非空 BLOB 且一条 Import 最多一条 Workbook，schema 不允许把 Content 置空，因此最小合法实现是删除旧 Workbook 子记录，不修改或删除其 Import。

最小实现：在 S2-T06 当前事务内保存新 Workbook 后、Commit 前，查询全部带 Workbook 的 `Status == Succeeded` Import，按 `ConfirmedAtUtc DESC, Id DESC` 排序，保留前两条并删除其余 ImportWorkbook；删除和新导入必须由同一事务一起提交或回滚。

## 固定保留规则

一次成功事务完成后的结果必须为：

- 第 1 次成功导入：1 条 Import、1 条 Workbook。
- 第 2 次成功导入：2 条 Import、2 条 Workbook。
- 第 3 次成功导入：3 条 Import、只保留第 2、3 条 Workbook。
- 第 4 次及以后：所有 Import 继续累积，Workbook 始终只保留最近两次成功导入对应的两条。

“最近”必须使用正式 Import 事实排序：

1. `Status == ImportStatuses.Succeeded`。
2. `ConfirmedAtUtc` 降序。
3. 时间相同时以 `Id` 降序稳定决胜。

禁止使用 SourceFileName、Workbook.SavedAtUtc 单独排序、文件系统时间、文件名中的时间、目录枚举顺序或当前查询偶然顺序。

本卡不定义 `Undone` Import 是否占用名额、是否保留或恢复 Workbook。裁剪查询只处理当前成功链路产生的 `Succeeded` Import；不得主动触碰其他状态的历史行。该语义留给 S2-T08。

## 事务边界

- 新 Workbook 必须先在 S2-T06 既有事务内成功写入，再基于包含本次 Import 的正式顺序计算应裁剪项。
- 旧 Workbook 删除必须发生在同一事务 Commit 前；不得 Commit 新 Import 后再启动第二个“尽力清理”事务。
- 裁剪应删除第 3 新及更早的 ImportWorkbook 行，可一次清理历史遗留的多余行；不得删除保留集合内的最新两条。
- 裁剪 SaveChanges、SQLite DELETE、最终 Commit 任一失败，必须回滚本次 Import、BackupRecord、Product/Batch、Issue、新 Workbook 以及本事务内的旧 Workbook 删除。
- 失败后原有两份 Workbook 的 ImportId、文件名、Content、SHA、SavedAtUtc 必须逐字段不变。
- 快照文件仍遵循 S2-T06 规则：事务失败时保留；本卡不删除快照文件。
- Commit 成功后不新增可能把已提交结果报告为失败的生产后置校验。

## 数据不变量

- 裁剪只删除 `import_workbooks` 子记录；旧 `imports` 行必须继续存在，字段逐项不变且可查询。
- 最新两份 Workbook 的 ImportId 必须分别关联排序后的最新、上一条成功 Import。
- 两份保留 Workbook 的原始字节、SHA-256、OriginalFileName、SavedAtUtc 均保持本次确认契约事实，不得重写或压缩。
- 所有 ImportIssue、BackupRecord、Product、Batch 及其他历史表行数和字段不得因裁剪改变。
- 裁剪不得更新 Product/Batch 的 `last_seen_import_id` 或时间戳；这些变化只能来自本次正常导入计划本身。
- 不生成 Task、Draft、Inspection、InventoryAdjustment 或 LifecycleEvent。

## 非成功流程

以下流程不创建 Succeeded Import / Workbook，因此不得触发裁剪或改变现有保留顺序：

- 完全无变化。
- 解析或文件内校验失败。
- 确认失败、文件变化/缺失/锁定。
- 快照失败、计划陈旧、正式事务任一步失败或 Commit 失败。

执行器只在已开始的成功导入事务内运行裁剪，不提供可由上述失败流程单独调用的公共清理入口。

## 故障处理

- 不为故障注入新增生产接口或 callback。
- 测试优先使用 SQLite `BEFORE DELETE ON import_workbooks` trigger 抛错，精确命中裁剪节点。
- 裁剪失败必须返回 S2-T06 既有 `transaction_failed`，Import ID 为空，ChangeTracker 清理，已验证快照仍存在。
- 失败后用全新 context 证明第三次 Import 及其所有关联写入均不存在，原两次成功 Import/Workbook 与业务数据完整保留。

### 保留内容与其他历史

- 对每次确认契约保存预期 byte[] 和 SHA；最终两条 Workbook 逐字节、SHA、OriginalFileName、SavedAtUtc、ImportId 全部正确。
- 被裁剪的旧 Workbook 查询不到，但对应 Import、BackupRecord、ImportIssue（如有）仍存在。
- 导入涉及的 Product/Batch 只发生其各自计划变化；裁剪不触碰未出现历史商品/批次及其 last_seen、状态、生命周期或时间戳。
- Task、Draft、Inspection、InventoryAdjustment、LifecycleEvent 无新增。

### 非成功不影响顺序

先建立两份成功 Workbook，再至少覆盖：

- 源文件在确认后变化/缺失造成执行失败；原两份 Workbook 逐字段不变，Import 排序不变。
- 完全无变化由 S2-T04 拒绝确认，不调用正式执行器；原两份不变。
- 正式事务在新 Workbook 写入前失败；原两份不变。

### 裁剪故障原子性

先完成两次成功导入并冻结所有相关行；第三次导入前创建 `BEFORE DELETE ON import_workbooks` 失败 trigger：

- 新 Import、BackupRecord、Product/Batch 增量、Issue、新 Workbook 全部回滚。
- 原两条 Import 和 Workbook 全部字段、字节、SHA、关联不变。
- Workbook 总数仍为 2，不出现 1、3 或其他错误集合。
- 执行结果失败、Import ID 为空、ChangeTracker 不会二次提交，快照文件存在且有效。
- 移除 trigger 后重新执行第三次导入成功，最终正确保留第 2、3 次 Workbook。
