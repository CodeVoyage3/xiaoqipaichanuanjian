# S5-T03｜排查历史只读 UI

## 目标

在 S5-T01 已完成正式排查历史只读查询、S5-T02 已完成 Revision 查询基础之上，把历史能力接入现有 WPF：

- 提供“排查历史”入口；
- 展示正式排查历史列表；
- 展示单条正式排查详情；
- 展示对应 InspectionItem 的 Revision 修改历史；
- 全部只读，不提供历史修改入口。

本任务只做历史查看 UI，不修改 Stage 3 / Stage 4 权威写逻辑，也不实现 S5-T02 编辑用例的 UI 调用。

## 实施前必须核对仓库事实

Luna 开始前必须读取并确认：

1. `.ai-dev/STAGES/STAGE-5-HANDOFF.md`
2. `.ai-dev/ACCEPTANCE/S5-T01.md`

7. 当前 `master` / HEAD / `git status`

不得为了本任务重新设计 Stage 4 已验收页面。

## 核心范围

### 1. 历史入口

在现有 Shell / 导航体系中增加“排查历史”入口。

要求：

- 使用现有导航模式；
- 不新增第二套 Shell；
- 不改变现有首页、待排查、导入等已验收入口语义；
- 文案使用 zh-CN。

### 2. 历史列表

展示正式完成的 Inspection 历史记录。

数据必须来自 S5-T01 的历史查询，不允许 ViewModel 重新拼装业务规则。

列表至少展示：

- 商品名称
- 商品条码（若正式快照已有）
- 商品编码
- 正式排查时间
- 明细 / 批次数量

排序沿用 S5-T01：

`SubmittedAtUtc DESC, InspectionId DESC`

要求：

- 无数据时有明确空状态；
- 不显示 Draft；
- 不显示未 completed 的记录；
- 不依据当前库存、当前 Batch 或当前 Excel 状态决定历史是否显示。

### 3. 历史详情

用户选中一条历史记录后，可查看该次正式排查详情。

详情至少展示：

- 正式排查记录基础信息；
- 当次全部 InspectionItem；
- 每条明细的正式排查数量；
- S5-T01 / S5-T02 查询能够可靠提供的正式快照字段。

禁止：

- 用当前 Product / Batch 数据覆盖历史快照；
- 重新运行 ExpiryCalculator 推导历史阶段；
- 使用 Draft 值覆盖正式值。

### 4. Revision 历史只读展示

对于存在 Revision 的 InspectionItem，提供只读修改历史展示。

至少能够展示：

- 修改前数量；
- 修改后数量；
- 修改时间。

顺序严格沿用后端 Revision 查询结果。

无 Revision 时应显示“无修改记录”或等价空状态，不制造虚假初始 Revision。

### 5. 交互边界

本任务只读。

不得出现：

- 编辑数量输入框；
- 保存修改按钮；
- 回滚 Revision；
- 删除 Revision；
- 撤销正式提交。

若详情页需要按钮或操作区域，只允许与“返回 / 查看 / 展开收起”等只读导航相关操作。

## UI 规则

继续沿用 Stage 4 已验收视觉基线：

- Windows 原生 WPF
- zh-CN
