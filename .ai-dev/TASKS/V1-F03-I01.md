## 2. 唯一目标

从当前数据库的合法 open ProductTask 生成新的“今日排查计划 Excel”：支持全部合法任务或精确选择部分 TaskId；一批次一行；同商品多批次展开；文件可填写、可打印，并携带 I02 所需稳定系统身份和导出快照。

本卡只实现 Application 查询与 Excel 文件生成。不接 WPF，不读取排查结果，不写 Draft/Inspection 或任何数据库业务事实。

## 3. 最小实现边界

优先复用现有权威，不建立第二套任务或 Excel 框架：

- 资格判断复用 `ExpiryManagementStatus`、`ExpiryPolicies.Version1`、批准 policy 集合、已完成 `ScopeBaseline`、canonical Stage 和当前实体关系。
- Excel 只使用现有 `DocumentFormat.OpenXml 3.5.1`。
- 大类中文显示扩展/复用现有 `ProductCategoryScopes` 单一权威；不得另建独立 Category 映射表。
- 不为导出增加 Repository、接口/工厂、配置系统、ExportRecord、数据库表或依赖。

允许新增最少的 Application 导出请求/DTO/查询用例、Open XML writer、CategoryCode 中文显示入口及一份 I01 专项测试文件。若一个生产文件即可清楚承载查询与写出，不为“以后”拆更多层。

## 4. 导出请求契约

建议最小请求形态：

`TodayInspectionPlanExportRequest(OutputPath, TaskIds)`

冻结语义：

- `TaskIds == null`：导出当前全部合法任务。
- 非 null：必须是至少一个唯一正数 TaskId，表示精确选择。
- 空集合、非正数或重复 TaskId：请求级拒绝；不得规范化后静默继续。
- TaskId 输入顺序不影响结果。
- 精确选择中任一 Task 不存在、非 open 或不合法：整次拒绝、零输出；不得忽略非法项后导出其余项。
- 当前没有任何合法任务：明确失败、零输出。

输出行顺序固定为：

`ProductCode (Ordinal) → TaskId → BatchId → TaskItemId`

序号按最终顺序从 1 连续生成。

## 5. 合法导出资格

查询必须 `AsNoTracking` 重读当前事实，并对每个目标 Task 全量验证：

- Task 存在且 `Status == open`；
- Product 存在且 Task/Product 关系一致；
- Product 为 Managed；
- `PolicyVersion == 1`，PolicyCode 属于现有批准的 Food/Pet/GeneralLong；
- 存在与 `CategoryCode + PolicyCode + PolicyVersion` 完全匹配且已完成的 ScopeBaseline；
- Task 至少一个 TaskItem；
- TaskItem 的 TaskId/ProductId 与 Task 一致；
- Batch 存在，BatchId/ProductId 与 TaskItem 一致；
- Batch 当前为 `active`；
- TaskItem Stage 是 canonical 可排查 Stage，且与 Batch.CurrentStage 一致；
- TaskItem.AttentionVersion 与 Batch.AttentionVersion 一致且非负；
- 当前/历史累计到货、商品有效库存及版本字段满足既有非负契约。

任何关系、状态或 policy 异常都使整次导出失败。Excluded、Unresolved、未知/非法 policy、无完成 ScopeBaseline 或 stopped Batch 不得进入文件。

查询和写出前后均不得调用 `SaveChanges`，不得生成 ExportRecord、ImportRecord、Task、Draft、Inspection、LifecycleEvent、Revision 或修改时间戳。

## 6. Excel V1 固定列契约

工作表名：`今日排查计划`。

### 6.1 可见业务列 A～L

1. `序号`
2. `商品编码`
3. `条码`
4. `商品名称`
5. `大类`
6. `生产日期`
7. `有效日期`
8. `当前阶段`
9. `当前批次累计到货`
10. `历史累计到货最大值`
11. `商品当前库存`
12. `本次排查数量`

规则：

- `本次排查数量` 数据单元格保持空白，是唯一预留给门店填写的业务列；I01 不解析、不校验、不回写。
- 商品编码和条码按文本写入，保留前导零与长数字。
- 生产日期为空时保持空白；有效日期必填。日期使用 Excel 数值日期和 `yyyy-mm-dd` 样式，不写成模糊本地化字符串。
- 序号、到货量、MaxArrivalQty、库存使用数值单元格。
- “大类”由 canonical CategoryCode 经 `ProductCategoryScopes` 中文显示权威生成。
- “当前阶段”写当前 TaskItem canonical Stage；未来回导不得依赖该显示列定位。

### 6.2 隐藏系统列 M～Y

13. `格式版本`
14. `TaskId`
15. `TaskItemId`
16. `ProductId`
17. `BatchId`
18. `AttentionVersion`
19. `Task更新时间UTC`
20. `TaskItem总数`
21. `Batch当前状态`
22. `Stage快照`
23. `当前批次累计到货快照`
24. `历史累计到货最大值快照`
25. `商品当前库存快照`

规则：

- 格式版本固定为 `inspection_plan_v1`。
- SQLite long 主键按不丢精度的文本单元格写入，不依赖 Excel 浮点数精度；AttentionVersion 和 TaskItem 总数按数值写入。
- Task 更新时间以 UTC round-trip (`O`) 文本写入。
- Stage、tracking status 及各数量快照逐行重复，供 I02 将来校验；I01 不提前实现回导或陈旧判断。
- M～Y 全部隐藏但实际存在；禁止仅依靠商品名、条码、行号或阶段显示文字作为未来身份。

## 7. Excel 填写与打印体验

至少实现并由测试读取确认：

- 标题行清楚且冻结首行；
- A1:L末行启用筛选；
- A～L 合理固定列宽，M～Y 隐藏；
- 横向打印；
- 单页宽度适配，纵向页数不强制为 1；
- 打印时重复标题行；
- 日期、数值、文本单元格类型符合 §6；
- 一批次一行，无合并数据行；
- 生成文件可由 `SpreadsheetDocument.Open(path, false)` 重新打开并读取。

不修改、不覆盖或另存原始商品源 Excel；只生成用户指定的新 `.xlsx` 文件。

## 8. 输出路径与失败契约

- OutputPath 必须非空、绝对路径、扩展名为 `.xlsx`。
- 目标父目录必须已经存在；本卡不猜测或自动创建用户目录。
- 已存在同名文件：明确失败，绝不覆盖、截断或删除原文件。
- 使用目标同目录的唯一临时文件完成写出，成功后以不覆盖方式移动到目标路径；失败时只清理本次精确临时文件。
- 路径非法、目录不存在、目标已存在/占用、无权限、磁盘或 Open XML 写入失败：抛出明确异常，目标文件不存在或原文件保持原样，不返回伪成功结果。
- 不使用宽泛 glob 或递归清理，不删除其他文件。
