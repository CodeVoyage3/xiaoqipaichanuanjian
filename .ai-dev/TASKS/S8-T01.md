## 目标

在测试项目中建立可重复、可核验、完全隔离的 SQLite 高规模压测基座，并记录现有系统的真实读路径与备份 snapshot 基线：

- `batches = 100,000`；
- 正式历史 `inspections = 300,000`，并具备与之关联、可查询的 `inspection_items`；
- 保留代表性的 open ProductTask、TaskItem、有效/无效 Draft、ScopeBaseline、Revision 和 Reminder 候选数据。

本卡只测量，不对慢路径做性能优化。

## 最小实现形态

- 优先只新增一个独立的 S8-T01 测试/压测文件，并复用现有测试项目、EF Core、Microsoft.Data.Sqlite、`DatabaseInitializer` 与现有 Application 入口。
- 允许增加一个很薄的本地运行脚本，前提是它只负责显式启用压测、选择 `%TEMP%` 隔离目录和输出结果；不得创建新项目或引入 benchmark/ORM/SQLite 依赖。
- 高规模 seed 可用参数化 SQL + 单事务批量写入，以免把 EF 逐行插入成本误当查询基线；数据必须满足现有 FK、唯一键、check constraint 与业务身份。
- 压测不得默认拖慢普通 Release 全量。必须有显式启用门禁；未启用时不得创建大库。专用运行命令和输出路径必须清楚、可重复。

## 隔离与安全门禁

1. 数据库及备份输出只能位于本轮新建的 `%TEMP%\StoreExpiryInspectorS8T01\<GUID>`（或同等唯一临时目录），并带 `S8-T01` marker。
2. 运行前拒绝空路径、相对路径、默认正式数据库路径、默认正式备份目录、仓库目录及不含本轮 marker 的目录。
3. 不读取、复制、打开、迁移、备份、恢复或修改 `%LOCALAPPDATA%\StoreExpiryInspector\data\app.db` 及正式备份目录。
4. 生成后必须核对 `PRAGMA integrity_check = ok`、FK 违规为 0、migration=9、目标行数和数据库文件大小。
5. 失败、timeout、lock、crash 或 OOM 必须如实记录；不得缩小数据后写成 100k/300k 达标。
6. 不执行 destructive cleanup 到宽泛目录；只允许清理本轮带 marker 的唯一临时目录。可选择保留数据库以便 Sol 复验，并明确路径。

## 必测路径

使用生产 Application / ViewModel 实际入口或与其完全一致的调用组合，至少测量：

1. Dashboard。
2. 待排查任务首次加载。
3. 待排查分页（第一页与深页）。
4. 搜索。
5. Stage 筛选。
6. 大类筛选。
7. 搜索 + Stage + 大类组合；必须覆盖当前 ViewModel 的实际内存交集与 `PageSize=int.MaxValue` 行为，不能只测一个理想化 SQL。
8. 任务详情。
9. 今日排查初次加载及大类筛选。
10. 历史列表。
11. 历史详情与 Revision。
12. ProductTask 查询/既有聚合入口的代表性无变化路径。
13. Reminder 正式候选与预提醒候选。
14. 使用既有 SQLite `BackupDatabase` 权威链创建大库 snapshot 的基础耗时；输出到同一隔离根，不登记或触碰正式库。

每条路径先预热，再进行足够的重复测量；记录 median 以及 p95 或 max，不设通过阈值。冷/热条件、运行次数、数据命中形状和页码必须写入结果。

## SQL 与诊断证据

对数据库查询路径记录：

- 实际 SQL（参数值可结构化记录，敏感值无需存在）；
- 每次业务调用的 SQL command 数；
- `EXPLAIN QUERY PLAN` 输出及是否出现 `SCAN`、临时 B-tree；
- 现有索引清单；
- 由命令数和代码/结果能够确认的 N+1、过度 materialization、全量加载、内存排序/筛选；不能证明时写 `not_proven`；
- elapsed、median、p95 或 max、进程 working set/managed allocation 的可获得快照，以及 timeout/lock/crash/OOM。

基线结果必须是机器可读 JSON，同时在测试输出中给出摘要。结果需包含 commit、OS、CPU、逻辑处理器、总内存、.NET、SQLite provider、数据库路径/大小、seed、规模、时间与冷/热条件。不得写入真实商品或用户数据。

## 正确性护栏

- 压测前后重新核对关键表计数、代表行、integrity/FK；只读路径不得改变业务表。
- ProductTask、Stage、Reminder、History/Revision、Excel、Backup/Restore 的既有语义不得为压测便利而改写。
- seed 中 Managed/Excluded/Unresolved 与“应季搭配 / 赠品小样”必须符合现有规则；Excluded 数据不得产生 open Task 或 Reminder。
- 测试代码不得把“当前实现很慢”变成失败；仅结构、隔离、安全、规模和结果完整性不满足时失败。
