## 商品差异规则

### 商品身份与文件内一致性

- 只按商品编码查找 Product；名称或条码变化不能产生新商品，不按名称/条码合并不同编码。
- 同商品多个正常批次的商品名称或条码规范值一致时作为本次商品值，包括明确的 `null`。
- 若同商品多个正常批次出现多个不同名称或条码值，不选择第一/最后一行；分别生成 `ambiguous_product_name` / `ambiguous_product_barcode` 预览问题。
- 对已有商品，有歧义的字段保持数据库值，不列入更新；其他无歧义字段及正常批次仍可规划。
- 对新商品，有歧义的可空名称/条码在计划中为 `null` 并报告问题；商品编码、合法库存和正常批次仍可规划。

### 新增商品

- 数据库中不存在商品编码、至少有一个正常批次且商品库存为合法非冲突单值时，生成一条新增商品计划。
- 建议值：商品编码、无歧义的名称/条码、`CategoryCode = food`、`PolicyCode = food_v1`、Excel/Effective 库存均为本次库存、`EffectiveStockSource = excel`。
- 不在计划中生成数据库 ID、时间戳、LastSeenImportId、LifecycleGeneration、IsStockZeroTerminated 或其他状态字段。

### 已有商品更新与无变化

- 只比较本次可安全确定的 `CurrentName`、`CurrentBarcode` 和合法非冲突库存。
- 合法库存与数据库当前值不同时，更新计划明确列出 `ExcelStockQty`、`EffectiveStockQty` 和 `EffectiveStockSource = excel` 的前后值；即使值为 `0`，也只表示库存字段差异，不生成归零或状态动作。
- 库存冲突时，3 个库存字段都不得出现在更新字段中，也不得从冲突值选择 `0` 或其他值；名称/条码和批次仍独立比较。
- 至少一个允许字段不同即进入商品更新；全部可比较字段一致则进入商品无变化。
- 计划 DTO 使用明确字段或小型 field-change DTO 表达前后值；不要做通用反射 diff。

## 批次差异规则

### 唯一键查找

- 使用 `ExcelBatchKey` 的结构化字段和 Product ID 匹配，不拼接字符串键。
- 有生产日期和无生产日期必须走对应唯一键语义；停止跟踪的历史批次仍是已有批次，不得当作新增。

### 新增批次

- 数据库中不存在该键时生成一条新增批次计划。
- 建议值：键、正整数保质期、单位、当前累计到货、历史最高累计到货初始等于当前累计到货、折扣参考。
- 不生成 ProductId、BatchId、时间戳、LastSeenImportId、LifecycleGeneration、TrackingStatus、StopReason、CurrentStage、AttentionVersion 或其他状态建议值；持久化卡按已验收 schema 默认值处理。

### 已有批次更新与无变化

- 比较 `ShelfLifeValue`、`ShelfLifeUnit`、`CurrentArrivalQty`、`SourceDiscountReference`。
- `MaxArrivalQty` 只做数据维护：计划值为 `max(数据库 MaxArrivalQty, 本次 CurrentArrivalQty)`；不得据此生成恢复、任务、阶段、草稿或生命周期动作。
- 上述任一字段不同即进入已有批次更新，并列出前后值；全部相同则进入批次无变化。
- 不比较或修改 TrackingStatus、StopReason、StoppedAtUtc、CurrentStage、NextTriggerDate、AttentionVersion、HandledAttentionVersion、LifecycleGeneration、LastSeenImportId 或时间戳。
