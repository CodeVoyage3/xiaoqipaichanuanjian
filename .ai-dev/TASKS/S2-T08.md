## 目标

建立 V1“撤销最近一次导入”的只读资格判断与快照关联基础：唯一确定当前候选 Import，验证其原始导入前安全快照，判断恢复该快照是否会覆盖 Import 后产生的正式业务事实，并返回明确结果。

本卡不执行恢复、不改变 Import 状态、不删除或覆盖任何数据库文件，也不建设 UI、通用审计框架或备份恢复系统。

## 当前仓库事实与固定口径

- 当前正式 Import 成功排序已由 S2-T07 固定为 `Status == Succeeded`、`ConfirmedAtUtc DESC`、`Id DESC`。
- `imports` 已有 `PreImportSnapshotPath`、`IsUndone`、`UndoneAtUtc`；`backups` 已有类型、路径、SHA-256、创建时间和验证状态，但两者之间没有 FK。
- S2-T06 在同一正式事务中保存 Import 的快照路径与对应 `pre_import` / `verified` BackupRecord；S2-T05 `PreImportSnapshotService` 已能只读打开快照并验证 SQLite 完整性、外键、17 张表和 8 条 migration。
- 当前 Stage 1 业务表包含：`tasks`、`task_items`、`drafts`、`draft_items`、`inspections`、`inspection_items`、`inspection_item_revisions`、`inventory_adjustments`、`lifecycle_events`；这些表均不由 Stage 2 导入写入。
- Product/Batch 会被候选 Import 本身增量写入，不能把它们与导入前快照的差异直接当作阻断；两者已有 `UpdatedAtUtc`，本次正式导入写入时间等于确认事实时间，可用于识别候选 Import 之后的直接修改。
- Import 自身产生的 `imports`、`import_issues`、`import_workbooks`、`backups` 是导入基础设施事实，不属于“Import 后业务操作”，不得作为阻断表。
- `settings`、`app_state` 是设置/运行状态而非当前定义的正式业务记录，本卡不以其变化阻断导入撤销资格；实际整库恢复及恢复前安全备份仍属于后续阶段。
- 当前全量测试基线为 136 项；本卡不得修改 schema、migration 或依赖。

## 候选 Import 规则

资格判断器不得接受 Import Id、Import 实体或任意历史选择参数。唯一候选必须由当前数据库内部确定：

1. `Status == ImportStatuses.Succeeded`。
2. `IsUndone == false`。
3. `ConfirmedAtUtc != null`。
4. `ConfirmedAtUtc DESC`。
5. 时间相同时 `Id DESC`。
6. 只取第一条。

没有符合条件的 Import 时返回正常结果 `no_candidate`（名称可等价），`CanUndo=false`、Candidate 为空；不得抛出业务异常。

不得提供按 Id 检查/选择旧 Import 的生产 API。旧 Import 即使快照存在，也只能因后来成为上述唯一最新候选才可能被判断，不能绕过顺序直接指定。

## 快照关联与验证

候选必须同时满足：

- `PreImportSnapshotPath` 非空且能规范化为文件路径。
- 路径对应文件真实存在；缺失返回 `snapshot_missing`。
- 当前库中恰有一条 `BackupType == pre_import`、`VerificationStatus == verified` 且规范化路径与 Import 快照路径一致的 BackupRecord。
- BackupRecord 创建时间不得晚于候选 `ConfirmedAtUtc`；SHA-256 格式合法。
- 快照实际 SHA-256 与 BackupRecord 一致。
- 快照能以 SQLite 只读方式独立打开，quick/integrity、外键、必要表、`__EFMigrationsHistory` 和当前 8 条 migration 验证通过。

BackupRecord 缺失/重复、类型或状态错误、路径关联不一致、时间倒置、SHA 不一致、SQLite 损坏、结构或 migration 验证失败，均返回不可撤销；关联类错误使用 `snapshot_association_invalid`，内容/结构类错误使用 `snapshot_invalid`（名称可等价，但结果必须可区分缺失和验证失败）。

不得以当前数据库、其他备份或临时复制重新创建“类似快照”代替原始导入前快照。资格判断不得修改、重命名、复制或删除快照文件。

## 后续业务变化阻断

### 固定阻断表

必须审查且不得只检查其中一张：

- `tasks`：正式商品任务及关闭/状态变化。
- `task_items`：正式任务批次项及状态数据。
- `inspections`：正式排查记录。
- `inspection_items`：正式排查明细及数量修改后的当前事实。
- `inspection_item_revisions`：正式排查修改历史。
- `inventory_adjustments`：库存修正事实。
- `lifecycle_events`：生命周期与正式业务状态事件。
- `drafts`、`draft_items`：草稿明确属于阻断项。理由是总纲规定完整备份包含草稿且整库恢复不做合并；Import 后创建、修改、失效或删除的草稿会被恢复覆盖，不能静默丢失。

最小且可靠的判断方式：候选快照就是该 Import 事务开始前的持久化事实。快照验证成功后，将当前数据库与该快照的上述固定表逐表、逐列、双向比较；任一插入、更新或删除即返回 `subsequent_business_changes`，并至少返回首个/全部发生变化的表名供明确提示。

该比较必须满足：

- Import 前已经存在且当前逐字段未变化的业务记录不阻断。
- Import 后新增、修改或删除任一阻断表记录均阻断。
- 不使用文件修改时间、当前内存时间、目录顺序或跨表主键大小推断先后。
- 不将 Import 基础设施表的必然差异误判为业务变化。
- 固定表比较失败、当前/快照表无法可靠读取或结果不确定时，保守返回 `business_state_unverifiable`，不得误报可撤销。

可使用固定表名常量和少量参数化/安全引用 SQL；不得把它扩展成通用审计框架、反射扫描器、事件总线或可配置表比较平台。

### Product / Batch 补充门禁

Product/Batch 的导入前后差异属于候选 Import 本身的预期结果，因此不得直接逐表比较。必须只读检查当前 Product/Batch 是否存在 `UpdatedAtUtc > Candidate.ConfirmedAtUtc`：若存在，说明候选 Import 之后发生了无法由本卡安全剥离的直接业务修改，返回 `subsequent_business_changes`。

如果现有持久化事实无法可靠判断某种 Product/Batch 同时刻覆盖或无留痕直接写入，不得宣称已准确识别；在结果/测试/回报中明确该 schema 限制。生产业务仍必须按 Stage 1 规则通过正式排查、修正、任务或生命周期记录留痕，这些记录由固定阻断表可靠捕获。

## 结果契约

普通内存结果至少包含等价信息：

- `CanUndo`。
- `CandidateImportId`（无候选时为空）。
- `ConfirmedAtUtc`（无候选时为空）。
- 已关联快照的路径、SHA-256、BackupRecordId（验证前可按安全原则只返回必要字段）。
- 稳定结果码与中文安全说明。
- 发生后续变化时的阻断表名集合或等价明细。

至少区分：

- `no_candidate`。
- `snapshot_missing`。
- `snapshot_association_invalid`。
- `snapshot_invalid`。
- `subsequent_business_changes`。
- `business_state_unverifiable`。
- `eligible`。

只有候选、关联、快照验证和所有业务门禁均通过时才允许 `CanUndo=true`。

## 必须测试

所有测试使用真实临时目录、真实 migration SQLite、真实 S2-T05 快照；结果查询使用全新 context/只读连接，不能依赖 ChangeTracker 假象。

1. 无 Import：返回无候选，不抛异常。
2. 一次 Succeeded Import + 唯一 verified BackupRecord + 合法原始快照：可撤销。
3. 多次成功 Import：只选择 `ConfirmedAtUtc DESC, Id DESC` 的最新未撤销候选；增加相同确认时间的 Id 决胜。
4. 旧 Import 即使快照存在，也没有按 Id 选择入口且不会被选中。
5. 最新 Import 快照路径为空/文件缺失：不可撤销，结果为 snapshot_missing 或明确关联缺失。
6. 最新 Import 快照字节损坏、SHA 错误、非 SQLite、结构/migration 异常：不可撤销且区分验证失败。
7. Import 后新增正式 Inspection（其必要父记录可在快照前建立）：不可撤销。
8. Import 后新增/修改 InspectionItemRevision：不可撤销。
9. Import 后新增 InventoryAdjustment：不可撤销。
10. Import 后新增或修改 LifecycleEvent、ProductTask、ProductTaskItem 中至少各一项：不可撤销。
11. 上述正式业务记录存在于 Import 前快照且当前逐字段不变：不应错误阻止；至少覆盖 Inspection、Revision、Adjustment、Lifecycle/Task 代表记录。
12. Import 自身新增的 Import、ImportIssue、ImportWorkbook、BackupRecord：不阻断。S2-T07 已裁剪旧 Workbook 时也不因基础设施差异阻断最新候选。
13. 资格判断前后当前数据库 17 张业务表逐字段完全不变；ChangeTracker 不新增 Modified/Added/Deleted，快照文件哈希不变。
14. Import 后新增、修改、删除 Draft/DraftItem：均阻断；Import 前已存在且未变化的草稿不阻断，明确证明草稿口径。
15. Import 后 Product 或 Batch 的 `UpdatedAtUtc` 晚于确认时间：阻断；候选 Import 自身在确认时间写入的 Product/Batch 不阻断。
16. 快照关联 BackupRecord 缺失、重复、类型/状态错误、路径不一致、创建时间晚于 Import：均不可撤销。
17. 任一固定表比较无法可靠执行：保守不可撤销，不得抛出未处理异常或误报 eligible。

同时继续执行 S2-T01～S2-T07 全量回归。
