# S14-T01｜新版 v1.0.5 简化在线更新

S14-T01 = `GOVERNANCE_FROZEN / READY_FOR_IMPLEMENTATION_AUTHORIZATION / NOT_IMPLEMENTED`

实施尚未授权。实现者不得据本卡自行开工、创建 Terra、build、测试、生成候选或发布。

## 产品规则

1. 取消强制升级。联网检查或更新失败均不得阻止门店进入和使用普通业务。
2. 软件先创建并显示主界面，再独立尝试创建托盘；更新检查只能在普通启动完成后后台异步执行。
3. WPF UI 主线程不得以 `.Result`、`.Wait()`、`.GetAwaiter().GetResult()` 或等效同步等待更新检查、下载或安装准备任务。
4. 网络检查使用现有合理超时；timeout、DNS、HTTP、限流、metadata 异常只记录并结束本次检查，不退出、不锁业务、不删除托盘。
5. 发现更高 stable 版本时，初始提示只给“立即更新 / 稍后提醒”。
6. 点击“稍后提醒”后再显示一次：`当前版本暂时可以继续使用，请尽快完成升级。旧版本后续可能停止支持，届时可能无法继续使用软件。`；点击“知道了”后继续正常使用。
7. 托盘与每日提醒为两个失败域。提醒读取/初始化/启动失败不得 dispose 托盘或改变已成功的托盘退出语义；托盘失败只记录并保留主界面，提醒可独立尝试。
8. 安装器不得仅因 `DisplayVersion` 与 `app/StoreExpiryInspector.exe` 文件版本不同而判定安装树损坏；其余 AppId、路径、卸载器、名称、普通目录和 EXE 可读性校验保留。
9. 新版 v1.0.5 从 v1.0.4 产品树重新实现。禁止直接恢复或 cherry-pick 已废弃的强制升级代码。
10. 发布前完成技术候选验收；正式 v1.0.4 -> 新 v1.0.5 在线升级只在发布后执行一次，不作为未发布候选门禁。
11. 正式 v1.0.4 -> 新 v1.0.5 的切换事务归 v1.0.4 安装目录自带的旧 Updater 所有。新包内 Updater 无法反向修复这次已开始的事务；兼容责任落在新 v1.0.5 App 自身的普通启动。

## 最小实现范围

- `App.xaml.cs`：拆分托盘、每日提醒和更新检查启动；主窗已显示后先独立尝试托盘，再启动不阻塞的后台检查；提醒独立初始化。应用退出只取消更新任务，不在 UI 线程同步等待网络/下载任务。
- `UpdateCheckRuntime` / `GitHubReleaseUpdateChecker`：优先复用现有 fire-and-forget 生命周期与 5 秒 linked-token 超时；只有专项证明缺口时才做最小修正，不新增调度器或持久状态。
- `MainWindow.xaml.cs`、`WpfDialogService.cs`、`UpdateNotificationViewModel.cs`：保留现有下载/验签/准备链；初始更新提示为两项选择；稍后提醒追加固定二次告知。下载中的取消仅是正在执行任务的取消动作，不得成为初始第三种产品选择。
- 新 v1.0.5 App 的普通启动：兼容旧 v1.0.4 Updater 无 normal-launch token 的启动方式及切换完成窗口，必须可靠完成普通启动，优先显示真实主界面并创建托盘；后台检查不参与启动门禁，不得形成“进程/Mutex 存在但无界面、无托盘”。不得把新版 Updater 修正写成这条路径的直接保障。
- `StoreExpiryInspector.Updater/Program.cs`：为 `v1.0.5 -> 后续版本` 从 v1.0.4 当前代码重新实现最小 same-schema 收口，让新版 Updater 的 `Committed` 路径复用现有 `NormalLaunchHandshake` 并在可信 Loaded/ACK 后才进入 `Completed`；不得新增 phase、协议文件、字段或另一套状态机。此项不反向改变旧 v1.0.4 Updater。
- `installer/StoreExpiryInspector.iss`：移除 `DisplayVersion + '.0' == AppVersion` 的严格等值损坏判定；继续用可读取的 EXE 版本和既有注册表身份执行防降级与路径安全检查。
- 版本/候选元数据仅调整到 `1.0.5`，正式 source range 为 `1.0.4 -> 1.0.5`，migrationCount 保持 9。
- 添加覆盖本卡分支逻辑的最小专项测试；不为已由现有测试充分覆盖的签名、ZIP、rollback 或业务规则复制测试。

## 明确不做

- `ForcedUpdateRequired`、24 小时强制联网宽限、`AutoContinue`、启动业务锁死、断网退出、6 小时强制复检、跨版本路径图或自动连跳。
- 新升级状态机、数据库表/migration、配置中心、后台服务、额外依赖、遥测、服务端组件或“为了安全”增加的新门禁。
- 恢复旧 v1.0.5/v1.0.6 分支、提交或候选；修改 v1.0.4 Release/tag/资产。
- 发布前伪造正式 Release/网络入口，或要求用户重复执行自动化已能证明的检查。
- 声称新 v1.0.5 Updater 能修复或接管已经由旧 v1.0.4 Updater 开始的 `v1.0.4 -> v1.0.5` 事务。
