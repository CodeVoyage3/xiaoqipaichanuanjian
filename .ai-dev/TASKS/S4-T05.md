## 四、最近一次成功导入时间

在现有具体只读查询边界做最小补充，优先为 `InspectionDashboardResult` 增加 nullable UTC 时间字段，命名遵循现有 record 风格。

查询必须：

- 仅访问 `Imports`，使用 `AsNoTracking`。
- 只认 canonical `Succeeded`、`IsUndone == false` 且 `ConfirmedAtUtc != null`。
- 按 `ConfirmedAtUtc DESC → Id DESC` 稳定取一条。
- 没有当前成功导入时返回 `null`。
- 保持 Dashboard 其他统计、紧急任务顺序和完全只读。

禁止 ViewModel 访问 `Imports`/DbSet、调用 `ImportUndoEligibilityService` 绕路、创建 Repository/ImportQueryFramework/新服务或修改 Stage 2 状态机。

## 五、Shell 与导航

替换当前 MainWindow 占位页，采用左侧固定导航 + 右侧 `*` 工作区。导航固定顺序：

1. 首页。
2. 待排查任务。
3. 排查记录。
4. 数据导入。
5. 设置。

本卡只有首页和待排查任务可进入。排查记录、数据导入和设置保留位置但必须明确 disabled/后续阶段，不得响应点击、进入空白页或弹“开发中”。

窗口最低可操作尺寸为 1024×600 DIP；重点适配 1366×768、1920×1080 和 Windows 125% DPI。核心页面不得依赖整页横向滚动，表格在极端尺寸下可自身滚动。

## 六、首页 Dashboard

首页真实调用 `InspectionTaskQuery.Dashboard`，只显示 DTO 已给出的事实：

- 最近一次成功导入时间和数据新鲜度。
- 待排查商品总数、过期、收仓、2折、5折。
- Application 已排序的最多20条紧急任务。
- “查看全部待排查任务”真实导航。

从未成功导入时显示“暂无导入数据”，不得显示过期或伪造时间。有成功导入时显示本地可读日期/时间；超过7天显示非阻断警告“数据已超过7天未更新”，不弹窗、不阻塞、不写后台状态。

阶段统计使用紧凑概览，不做巨型 KPI 卡墙；文字与语义色同时存在。不得在 UI 重新计算阶段、优先级或重排紧急任务。

紧急任务至少显示商品名称、最高阶段、待排查批次数和最近有效日期。当前不得显示“去排查”，也不得让行呈现可进入详情的假交互。

本卡首页禁止显示“导入最新 Excel”按钮、文件选择或任何数据导入入口。

## 七、待排查任务列表

真实调用 `InspectionTaskQuery.SearchOpenTasks`，展示：

- 商品名称。
- 商品编码。
- 当前最高阶段。
- 待排查批次数。
- 库存总数。
- 最近有效日期。

商品条码只需参与后台搜索，不要求占据核心表格列。本卡不显示操作列、“去排查”按钮或可进入详情的行交互。

搜索支持商品名称、编码、条码，必须把输入作为 `SearchText` 交给 Application，不得在 UI 对返回结果二次过滤。采用 Enter 或简单短延时触发；不得引入第三方 debounce 框架。

阶段筛选显示“全部 / 过期 / 收仓 / 2折 / 5折”，只做以下文案映射：

- 过期 → `expired`
- 收仓 → `withdraw`
- 2折 → `discount_20`
- 5折 → `discount_50`

不得复制阶段优先级、效期算法或生命周期规则。

分页固定 50 条，必须使用 Application 的 Page/PageSize，显示当前页、总数/总页数、上一页和下一页；不得一次加载全部记录后在 WPF 分页。

## 八、Loading、Empty、Error

首页和列表加载中必须显示“正在加载…”，不得把未完成加载显示为空库或无反馈冻结。

至少区分：

- `LastSuccessfulImportAtUtc == null`：暂无导入数据。
- 已有导入但无开放任务：当前没有待排查任务。
- 搜索/筛选无结果：没有符合当前条件的任务。
- 查询异常：数据加载失败，并提供重试。

查询异常不得吞成空集合、not_found 或业务空状态；UI 不解析异常 Message 推导业务状态。详细异常使用既有本地日志，界面只显示稳定安全文案。

## 九、最小 WPF/ViewModel 架构

允许建立具体、最小的 Main/Shell、Dashboard、PendingTasks ViewModel 和一个简单 `ICommand`/RelayCommand；不得发展成通用 MVVM、导航、消息、DI 或任务调度框架。

UI/ViewModel 只允许：导航、DTO 展示、搜索/筛选/分页状态、Loading/Empty/Error、纯文案映射和调用 Application。

业务规则不得进入 MainWindow code-behind、ViewModel、Converter 或 UI helper。Code-behind 仅允许 DataContext 初始化、纯焦点和窗口视觉行为。

数据库加载必须离开 UI 线程。每次后台操作必须在同一后台生命周期内创建、查询和释放自己的 `StoreDbContext`：

- 不在 UI 线程创建后跨线程使用。
- 不共享或长期持有 DbContext。
- ViewModel 不持有 DbSet/IQueryable/tracked entity。
- UI 最终只接收普通 DTO/result。

不得引入 ReactiveUI、Prism、CommunityToolkit MVVM、MediatR 或其他框架。
