# S5-T01｜正式排查历史只读查询基础

## 目标

建立 Stage 5 的第一块只读能力：基于 Stage 4 已经正式落库的排查结果，提供“历史记录列表 + 单条历史详情”的应用层查询能力，为后续历史 UI 与 Revision 修改追溯提供稳定入口。

本任务只读，不修改任何 Stage 4 的 Draft、Reconfirm、InventoryAdjustment、Submission、Lifecycle 逻辑。

## 实施前必须先核对仓库事实

Luna 开始实施前必须先读取并确认：

1. `.ai-dev/STAGES/STAGE-4-CLOSEOUT.md`
2. `.ai-dev/STAGES/STAGE-5-HANDOFF.md`
3. `.ai-dev/ACCEPTANCE/STAGE-4.md`
4. Stage 4 正式提交相关实体、DbContext、migration、service 与测试
5. 当前 `master` / HEAD / `git status`
6. 当前正式排查记录、明细实体的真实字段与关系

禁止仅凭任务卡假定实体名、字段名或数据库结构。

若仓库事实与本任务卡描述存在冲突，以已验收的 Stage 4 仓库事实为准，并在实现说明中记录差异；不得为适配任务卡而重写 Stage 4。

## 范围

### 1. 历史记录列表查询

为正式完成的排查记录提供只读列表查询。

最低要求：

- 仅返回已经正式提交成功的排查记录
- 默认按正式提交时间倒序
- 同一正式记录只出现一次
- 不把 Draft、未完成 ProductTask、已失效 Draft 当作历史记录
- 不依据 Excel 当前是否仍包含商品/批次来决定历史记录是否存在
- 不修改任何业务状态

返回字段必须以现有数据库能够可靠提供的事实为准。

列表至少应能够识别：

- 正式记录身份
- 商品身份
- 正式排查时间
- 本次正式排查所对应的批次/明细数量

若现有 Stage 4 已保存商品名称、条码等快照，可读取；若未保存，不允许本任务擅自新增“历史快照语义”。

### 2. 单条历史详情查询

能够通过正式记录身份读取该次排查的完整已落库明细。

必须：

- 读取该正式记录对应的全部正式明细
- 保持数据库中的原始正式结果
- 不重新运行当前 ExpiryCalculator 推导历史阶段
- 不使用当前 Draft 覆盖历史结果
- 不使用当前库存反推历史检查数量
- 不调用任何会改变生命周期的 Stage 3 / Stage 4 写操作

### 3. 查询边界

本任务不实现复杂筛选器。

如果现有架构已有通用搜索能力，可在不扩大范围的前提下复用；否则本任务只需完成稳定的列表与详情查询接口。

## 明确不做

- 不做 WPF 历史页面
- 不做历史记录修改
- 不做 Revision
- 不做删除历史
- 不做撤销正式提交
- 不改 Stage 4 提交流程
- 不改 Draft / Reconfirm
- 不改 InventoryAdjustment
- 不改 ProductTask / Batch 生命周期
- 不新增提醒逻辑
- 不改 Excel 导入规则
- 不创建 Stage 6 内容
- 不为“历史展示方便”直接修改既有正式记录

## 数据与兼容性要求

- 优先复用 Stage 4 已存在的正式记录和明细结构
- 只有仓库事实证明无法完成 Stage 5 必需的只读查询时，才允许提出最小数据层调整
- 若确需 migration，必须先由 Sol 单独审查必要性，不得 Luna 自行扩展
- 本任务默认目标是 `migration` 数量保持 8

## 测试要求

至少覆盖：

1. 无历史记录时返回空集合
2. 单条正式记录可查询
3. 多条正式记录按正式时间倒序
4. Draft 不进入历史结果
5. 未正式提交的任务不进入历史结果
6. 单条历史详情返回全部正式明细
7. 查询不存在记录时返回既定的 not-found 语义
8. 查询过程不产生数据库写入
9. Stage 4 Submission / Lifecycle 既有测试全部继续通过

测试命名、目录和架构遵循仓库现状，不新建平行体系。

## 验收门禁

Luna 完成后由 Sol 独立验收：

- 审查 diff 与范围
- S5-T01 新增/修改测试全部通过
- Stage 4 回归全部通过
- Stage 3 回归全部通过
- Release 全量测试通过
- Release build：0 warning / 0 error
- EF model：无意外漂移
- migration：预期仍为 8
- dependency diff：无非必要变化
- `git diff --check` 通过
- 工作区状态明确
- 无 Stage 5 后续 Task 越界实现

## GUI

本任务没有 GUI 验收。

不得为了验收本任务启动或修改 WPF UI。

## 完成定义

只有当：

- 正式历史列表查询可用
- 单条正式历史详情查询可用
- 查询严格只读
- Stage 3 / Stage 4 权威行为无回归
- 全部门禁通过

才可将 S5-T01 判定为完成。

完成后停止，不创建或实施 S5-T02，等待 Sol / 用户下一步批准。
