## 2. 唯一目标与闭环

在现有 WPF 中新增与“数据导入”明确分离的“今日排查”入口，串接已经完成的权威能力：

`当前任务选择 → I01 导出 → I02 零写入 Preview → I02 原子 Draft 应用 → I03 集中正式提交 → 刷新首页/任务/详情/历史`。

本卡只做 WPF 接入、页面会话状态、交互表达和刷新编排；不得重写 I01～I03 的资格、Excel、陈旧、Draft、Submission、0 件停止或生命周期逻辑。

## 3. 最小实现形态

- 新增独立 `TodayInspectionViewModel`（或语义等价名称）承载 I04 页面会话；不得复用或扩写商品源 `ImportViewModel` 承载排查文件。
- `ShellPage`、`ShellViewModel` 和 `MainWindow.xaml` 只增加一个真实“今日排查”导航/page；现有“数据导入”继续只处理商品源 Excel。
- 标准 `SaveFileDialog` / `OpenFileDialog` 只负责路径选择；业务执行进入 ViewModel 注入委托，默认委托以短生命周期 `StoreDbContext` 调用 I01/I02/I03。
- 允许 code-behind 处理标准文件对话框、焦点和纯视图行为；不得在 code-behind 或 XAML converter 中加入业务判断。
- 复用现有 `RelayCommand`、`WpfDialogService`、样式、converter、阶段文字、日志和刷新方法；不增加 MVVM/UI/图标/Excel 依赖，不建设接口、工厂、事件总线或持久化 Preview。
- 长操作使用现有异步/防重入模式，Application 调用放到后台任务；操作中禁用冲突操作并保持 UI 可响应。

## 4. “今日排查”任务选择

- 使用现有 `InspectionTaskQuery.SearchOpenTasks` 权威结果加载当前 open Managed 任务；不在 WPF 复制 lifecycle、policy、Stage 排序或导出资格判断。
- 页面以高密度表格显示商品名称、编码、条码、最高阶段、待排查批次数、库存、最近有效期和是否已有 Draft，并为每个 Task 提供复选框。
- 支持全选当前已加载合法任务、取消全选、单选/多选和实时“已选择 N 项”；重新加载后只保留仍存在的已选 TaskId。
- 无选择时导出不可执行并显示文字提示。导出前将唯一正数 TaskId 集合传给 I01；任务在列表加载后完成/失效时，以 I01 整体拒绝为准，不静默忽略。
- 页面进入及提交后重载当前任务；Excluded/Unresolved 没有额外入口，最终资格仍由既有 Application 权威防御。

## 5. 导出交互

- 使用标准 `SaveFileDialog`，过滤 `.xlsx`，默认文件名包含业务日期，例如 `今日排查计划_yyyyMMdd.xlsx`；用户明确选择保存位置。
- 只调用 `TodayInspectionPlanExportUseCase.Execute(context, new(path, selectedTaskIds))`。
- 遵守 I01 目标目录存在、绝对路径、同名不覆盖和失败无残片契约；I04 不预删、不覆盖、不修改 I01 Excel。
- 成功显示任务数、批次数/行数及保存路径；失败显示可理解的安全摘要并保留选择以便重试，不显示伪成功。

## 6. 独立回导与零写入 Preview

- 使用独立标准 `OpenFileDialog` 选择 `.xlsx`；只调用 `InspectionPlanDraftApplyUseCase.Preview`，不得调用商品源 reader/parser。
- Preview 保持在当前 ViewModel 内存；换文件、重新读取或离开明确重置时丢弃，不持久化。
- 汇总至少显示涉及商品数、批次数、Task 数、可应用 Task 数、已填写数、空白数量、错误数量、陈旧/失效 Task 数。
- 明细一批次一行，显示商品/批次、TaskId、本次排查数量（空白显示“未填写”，`0` 显示 `0`，正整数原值）、文字状态和不可应用原因。
- 行错误直接显示 I02 `Errors`；Task 不可应用原因直接显示 I02 `TaskReasons`。UI 只排版/汇总这些权威结果，不解析异常字符串重新判断 Stage、AttentionVersion、库存、到货、TaskItem、tracking 或 completed。
- 正常、空白、错误、陈旧/失效必须有明确中文文字；颜色只作辅助。

## 7. 排查人、日期与 Draft

- Preview 后显示排查人和排查日期；排查人必填，最大长度沿用 I02；排查日期默认本地业务今天、必填且不得晚于今天。
- 复用现有详情页字段控件、日期格式、错误提示和最近一次当前会话输入体验；不得增加人员设置或新持久化。
- “保存待确认结果”只对 Preview 中全部 `ApplicableTaskIds` 调用一次 I02 `Apply`；不得由 UI 直接访问 Draft/DbContext 实体或逐 Task 自行提交。
- `Apply` 自带事务内二次复检；冲突显示 I02 返回的具体安全原因并提示重新导出最新计划，不把失败说成导入成功。
- 应用结果逐 Task 保存 `InspectionDraftReadiness`。有空白仍允许 Draft 成功，但页面必须显示“草稿已保存，仍有未完成排查项”，不得表现为排查完成。
- 仅 `IsDraftComplete == true` 的本次 Task 进入正式提交候选；任一 incomplete Task 必须有文字状态且不能被传给 I03。

## 8. 多 Task 正式提交与超库存确认

- “集中正式提交”只调用一次 `BulkInspectionSubmissionUseCase.Submit`，TaskIds 为本次 Draft 应用结果中全部完整 Task，InspectorName/CheckDate 与 Draft 相同，BusinessDate/SubmittedAtUtc 使用当前权威时间。
- ViewModel 不循环创建 Inspection、不完成 Task、不停止 Batch、不推进 HandledAttentionVersion，也不调用单 Task `InspectionSubmissionUseCase`。
- I03 返回 `RequiresOverStockConfirmation` 时，集中展示每个异常 Task 的商品名称、TaskId、当前商品库存、本次排查合计；按钮必须是明确的“返回检查”和“确认仍然提交”，默认不确认。
- 用户确认后把 I03 返回的完整 `OverStockConfirmation` 原样用于同一提交意图的第二次调用。`OverStockConfirmationStale` 必须展示最新集合并要求重新确认；旧事实不得自动沿用。
- `Submitted`、`AlreadySubmitted`、错误和 stale 均有不同文字状态；提交防重入。没有完整 Task 时正式提交禁用，并显示“仍有未完成排查项”。

## 9. 提交成功后的刷新

成功或权威 `AlreadySubmitted` 后，Shell 统一等待刷新：

- `Dashboard.LoadAsync()`；
- `TodayInspection.LoadAsync()`；
- `PendingTasks.LoadAsync()`；
- `History.LoadAsync()`；
- 若现有详情正指向本次 Task，调用现有详情重载以显示 completed/不可编辑状态。

任一刷新失败不得反转已完成的正式提交；页面明确提示“提交已成功，部分页面刷新失败，可手动刷新”，并记录异常。已完成任务必须从两个当前任务列表移除，历史使用现有查询显示新 Inspection。

## 10. UI/UX 与可访问性门禁

- 复用 UIUX-R03 / Stage 4 refresh 的浅灰画布、白色内容区、克制边框、低饱和蓝、表格优先和现有语义资源；不做全局重构。
- 导航中“今日排查”与“数据导入”是两个相邻但语义清晰的文字入口，收起导航时也有不同 `AutomationProperties.Name`/ToolTip。
- 1024×600、Windows 125% 下关键按钮可达，页面内容可滚动；汇总/表格占主要空间，不使用卡墙、玻璃、渐变或大留白。
- Tab 顺序符合视觉顺序，复选框、文件按钮、表单和提交按钮键盘可达；焦点可见；状态必须文字 + 视觉，不能只用颜色。
- 数量、日期列使用现有数字/日期对齐；空白明确显示“未填写”，不可显示成 0。

## 11. 异常与状态契约

- 无任务、无选择、文件取消、导出失败、错误格式、无合法 Preview、陈旧/身份变化、排查人空、未来日期、Draft 冲突、incomplete、超库存、确认陈旧、提交失败和刷新失败均有独立可恢复状态。
- UI 可以把常见文件/校验异常翻译为固定安全中文；业务原因优先展示 I02/I03 已返回的 reason/事实，不通过异常文字反推业务状态。
- 失败不得清除用户仍可重试的任务选择、Preview 或表单；换文件后必须清除旧 Draft 应用/提交状态，避免把旧确认用于新文件。
- 页面离开或应用退出不要求保存 Preview；不新增 ExportRecord、ImportRecord 或批量请求记录。
