## 必须实现

### 1. ProductTask → `tasks`

- `id`、`product_id`。
- `status`：`open / completed / system_closed`。
- `highest_stage`：`discount_50 / discount_20 / withdraw / expired`。
- `created_at_utc`、`updated_at_utc`、`closed_at_utc`、`close_reason`。
- SQLite 部分唯一索引：同一商品最多一条 `status = 'open'` 的任务；历史关闭任务可保留多条。
- 状态/关闭字段约束：开放任务不得有关闭时间；关闭任务必须有关闭时间；`system_closed` 必须有非空白关闭原因。

### 2. ProductTaskItem → `task_items`

- `id`、`task_id`、`batch_id`、`product_id`。
- `stage` 使用与任务相同的四个稳定代码。
- `attention_version >= 0`。
- `requires_reconfirmation`。
- `created_at_utc`、`updated_at_utc`。
- `UNIQUE(task_id, batch_id)`，一个任务内同一批次最多一项。
- 用复合外键或等价数据库约束保证：任务、任务项和批次必须属于同一商品；不得只依赖未来业务服务检查。

### 3. InspectionDraft → `drafts`

- `id`、`task_id`。
- `inspector_name`、`check_date` 可空，支持尚未填完的自动草稿。
- `is_invalid`、`invalid_reason`、`invalidated_at_utc`。
- `created_at_utc`、`updated_at_utc`。
- `task_id` 唯一：每条商品任务最多一个草稿。
- 有效草稿不得有失效原因或失效时间；失效草稿必须保存非空白原因和失效时间。

### 4. InspectionDraftItem → `draft_items`

- `id`、`draft_id`、`task_item_id`、`task_id`。
- `checked_qty` 可空：`NULL` 表示未检查，`0` 表示已检查且无库存，`>0` 表示现场仍有库存；负数必须由数据库拒绝。
- `confirmed_attention_version >= 0`。
- `UNIQUE(draft_id, task_item_id)`。
- 用复合外键或等价数据库约束保证草稿、草稿项和任务项属于同一任务。

### 5. 关系与迁移

- 所有关系使用 `DeleteBehavior.NoAction` 或等价非级联行为，不提供删除历史的捷径。
- 为外键和主要查询路径建立必要索引，不增加猜测性索引。
- 新增一条命名清晰的 migration，例如 `AddTasksAndDrafts`；migration、Designer、ModelSnapshot 必须一致。
- 现有 `InitialCreate` 文件内容与迁移 ID 不得变化。
