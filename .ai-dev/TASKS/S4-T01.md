## 一、目标

在 Application 层建立 Stage 4 UI 唯一的只读查询入口，为后续首页、待排查列表和排查详情提供稳定普通 DTO。

本卡只读：

- 不修改任何业务数据。
- 不接 WPF。
- 不实现草稿保存、库存修正或正式提交。
- 不重新计算或改变 Stage 3 已持久化的阶段、任务、版本和生命周期事实。

查询失败必须向调用方保留失败语义，不得吞异常或把失败降级为空结果。

## 二、开工基线与权威边界

- 当前单一 .NET 10 WPF 应用项目和单一测试项目保持不变。
- 当前 schema 为 17 张业务表、17 个实体/配置/DbSet、8 条 migration；S4-T01 不需要 schema 变化。
- `ProductTask.Status` 已能表达 `open / completed / system_closed`；每商品最多一条开放任务。
- `ProductTaskItem.Stage` 保存各批次自身实际阶段，`ProductTask.HighestStage` 只保存商品当前最高阶段。
- `InspectionDraft` 每 Task 最多一条；只有 `IsInvalid == false` 的 Draft 才是当前有效草稿。
- `InspectionDraftItem.CheckedQty` 的 `null / 0 / 正整数` 语义必须原样保留。
- Stage 3 的唯一阶段优先级实现是 `ExpiryStageCalculator.GetStagePriority`；本卡只能调用，不得复制。
- 当前 UI 仍是占位主窗；本卡不得修改 `App.xaml`、`App.xaml.cs`、`UI/MainWindow` 或创建 ViewModel。

若实现发现现有实体、关系或已验收 Stage 3 事实无法支持本卡，立即停止并报告 Sol；不得自行新增字段、migration、平行状态或变更业务语义。

## 四、Dashboard

提供首页所需数据：

- 当前开放待排查商品总数。
- `expired` 商品数。
- `withdraw` 商品数。
- `discount_20` 商品数。
- `discount_50` 商品数。
- 最紧急任务列表，固定上限 20。

同一商品只能按照当前开放 Task 的 `HighestStage` 计数一次；不得按 TaskItem 数量重复计数。

阶段优先级必须复用：

`ExpiryStageCalculator.GetStagePriority`

禁止字符串排序、在 Query 中再写一套 switch，或为未来 ViewModel 暴露需要再次解释的平行优先级。

紧急任务稳定排序：

1. 阶段优先级 DESC。
2. 当前 TaskItem 中最近有效日期 ASC。
3. 稳定唯一键 ASC。

不得提供用户自定义紧急列表数量、排序配置或通用排名框架。

## 五、SearchOpenTasks

只查询 `Status == "open"` 的当前任务。

支持搜索：

- 商品名称。
- 商品编码。
- 商品条码。

支持阶段筛选：

- 全部。
- `expired`。
- `withdraw`。
- `discount_20`。
- `discount_50`。

未知筛选值必须在查询前明确拒绝，不得静默当作“全部”。搜索空白按无搜索条件处理，不得修改数据库中的原值。

默认每页 50 条。页码、页大小等输入必须拒绝非正数；本卡不创建通用分页框架，也不提供用户自定义页大小 UI。

稳定排序：

1. 阶段优先级 DESC。
2. 当前 TaskItem 中最近有效日期 ASC。
3. 稳定唯一键 ASC。

阶段优先级仍只调用 `ExpiryStageCalculator.GetStagePriority`。为复用权威实现而进行的最小只读 materialize 可以接受，但不得顺带扫描 Batch/Inspection 全历史或复制 CASE/switch 优先级。

列表 DTO 至少返回：

- TaskId。
- ProductId。
- 商品名称。
- 商品编码。
- 商品条码。
- 当前最高阶段。
- 待排查批次数。
- 当前商品有效库存。
- 当前 TaskItem 中最近有效日期。
- 是否存在当前有效 Draft。

不得返回 tracked EF entity。

## 六、GetDetail

按 TaskId 查询任务真实状态和排查详情。

### 6.1 Task 状态语义

调用方必须能够区分：

- 当前开放任务。
- Task 不存在。
- Task 已正式完成。
- Task 被系统自动结束。

不得把 `completed` 和 `system_closed` 伪装为“查无任务”。当前 schema 已有的 `Status`、`ClosedAtUtc` 与 `CloseReason` 应作为事实使用；不得为查询新增字段或 migration。

### 6.2 Product

开放任务详情返回：

- 商品名称。
- 商品编码。
- 商品条码。
- 当前有效库存。
- TaskId。
- ProductId。
- 当前最高阶段。

### 6.3 当前待排查批次

每个当前 TaskItem 返回：

- BatchId。
- 生产日期，可空。
- 有效日期。
- TaskItem 保存的当前实际阶段。
- 当前累计到货数量。
- AttentionVersion。
- RequiresReconfirmation。
- 当前有效 Draft 对应 DraftItem 的 CheckedQty，如不存在则为 null。

每个批次必须保留自己的实际阶段，不允许全部显示成商品 `HighestStage`。生产日期的 null 原样保留，后续 UI 才负责显示 `—`。

### 6.4 正常活动批次

同一商品下同时满足以下条件的其他 Batch 作为“正常批次”返回：

- `TrackingStatus == "active"`。
- 当前没有进入该开放 Task 的 TaskItem。

返回：

- BatchId。
- 生产日期，可空。
- 有效日期。
- 当前阶段。
- 当前累计到货数量。

本卡只提供只读分组，不创建 UI 折叠状态，也不修改 Batch。

### 6.5 上次正式排查

对待排查批次和正常活动批次中的每个相关 Batch 查询最新正式 InspectionItem。

“最新”必须按可靠正式事实稳定选择：

1. 对应 Inspection 的 `SubmittedAtUtc` DESC。
2. Inspection 稳定主键 DESC。
3. InspectionItem 稳定主键 DESC。

不得取任意一条、依赖数据库自然顺序、文件时间或 WPF 缓存。

至少返回上次正式 CheckedQty；如为可靠表达最新事实还需要 InspectionId、InspectionItemId、SubmittedAtUtc，可作为最小 DTO 字段加入，但不得引入 Stage 5 历史编辑语义。

## 七、Draft 只读状态

若当前 Task 存在 `IsInvalid == false` 的有效 Draft，详情返回：

- 检查人。
- 检查日期。
- 各 TaskItem 已填写的 CheckedQty。
- 是否存在任一 RequiresReconfirmation。

S4-T01 只能读取。禁止：

- 自动创建 Draft。
- 自动补 DraftItem。
- 修改 ConfirmedAttentionVersion。
- 修改 CreatedAtUtc / UpdatedAtUtc。
- 自动清理、删除或失效草稿。
- 把无效 Draft 当作可恢复草稿。

正式提交后的 Draft 处置不是本卡范围，留到 S4-T04 前按已冻结治理门禁重新核验。

## 八、正常空结果、状态结果与加载失败

查询契约必须让调用方区分：

- Dashboard / Search 正常执行但结果为空。
- GetDetail 的 Task 不存在。

本卡不实现 UI 错误页，但不得 catch 后返回空集合、空 DTO、Task 不存在或成功结果。数据库加载失败必须作为失败传播，供 S4-T05 后续 UI 显示错误状态。
