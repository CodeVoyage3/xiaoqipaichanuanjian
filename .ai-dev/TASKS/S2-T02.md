## 分类顺序与隔离规则

分类必须使用确定、可测试的顺序，避免一行产生无关级联问题：

1. 先识别是否支持的食品行。
2. 对食品行执行批准的行级字段校验，并一次收集该行所有适用问题。
3. 只有没有行级问题的食品行才能进入完全重复、批次键和批次关键数据冲突分组。
4. 商品库存冲突作为独立商品级结果；它不得触发状态转换，也不得吞掉同商品可独立成立的批次分类结果。

暂不支持行不进入行级异常、重复、批次冲突或库存冲突计算，不得影响任何食品结果。

## 必须实现

### 1. 食品与暂不支持行

- `商品大类` 只做首尾 Trim；规范化后精确等于 `食品` 才属于 V1 食品。
- `null`、空白或任何其他值均分类为“暂不支持/跳过”，不是异常。
- 跳过结果至少保留 Excel 行号和原始商品大类值；不得产生 Product、Batch、Task 或其他业务对象。
- 非食品行即使其他字段为空或格式错误，也只计为跳过，不再产生行级问题。

### 2. 食品行级校验

对每个食品行一次收集全部适用问题，只允许以下行级问题：

- 商品编码 `null` / 空 / Trim 后空白：`missing_product_code`。
- 有效日期 `null` / 空 / Trim 后空白：`missing_expiry_date`。
- 有效日期非空但无法按本卡日期规则解析：`invalid_expiry_date`。
- 生产日期允许为空；非空但无法解析：`invalid_production_date`。
- 保质期 `null` / 空 / Trim 后空白：`missing_shelf_life`。
- 保质期单位 `null` / 空 / Trim 后空白：`missing_shelf_life_unit`。
- 保质期单位 Trim 后不是精确大写 `M`、`D`、`Y`：`invalid_shelf_life_unit`。

本卡不擅自增加商品名称、条码、库存、累计到货、保质期数值范围或其他行级错误；这些字段原始值继续保留供后续卡使用。

### 3. 日期解析

- 生产日期和有效日期成功后输出 `DateOnly?` / `DateOnly` 的规范值，供批次键比较；不得反推生产日期。
- 使用 .NET 标准库，不新增日期依赖，不使用当前机器区域设置形成不稳定结果。
- 必须支持固定模板中的 OLE Automation / Excel 1900 系统数值日期文本，例如真实样表中的整数序列值。
- 必须支持明确文本格式：`yyyy-M-d`、`yyyy-MM-dd`、`yyyy/M/d`、`yyyy/MM/dd`；首尾空白先 Trim。
- 非整数数值日期、越界数值、非法日历日期和其他不能明确解析的文本进入相应日期错误。
- 当前固定模板不是 1904 日期系统；S2-T02 不为未知模板建设日期系统自动探测或通用 Excel 格式引擎。

### 4. 批次唯一键

- 商品编码先 Trim；空编码行已在行级校验阶段排除。
- 有生产日期：`商品编码 + 生产日期 + 有效日期`。
- 无生产日期：`商品编码 + 有效日期`。
- 使用明确的不可变普通值对象/record 表达该键即可；不要拼接带分隔符的字符串键，不创建通用 Key 框架。
- 同一日期以数值序列或批准文本格式表达时，解析后的 `DateOnly` 相同即属于同一键。

### 5. 完全重复行

- 只在无行级问题的食品行内比较。
- 比较值先做本卡批准的规范化：商品大类、商品编码、条码、名称、保质期、保质期单位、折扣参考、累计到货和商品库存只 Trim；生产/有效日期使用解析后的规范日期。
- 11 个 S2-T01 字段的规范值全部相同，才是完全重复。
- 同一完全重复集合按 Excel 行号最小的一行作为内存代表，其余行分类为重复并保留代表行号/重复行号；不产生第二个批次候选。
- 最后三个人工排查字段不在比较范围。即使原 Excel 中这些列有不同值，也不能让两条其他数据完全相同的行变成不同业务行或正式排查记录。

### 6. 同一批次关键数据冲突

- 先按批次唯一键分组，再忽略已经确认的完全重复副本。
- 同一键下以下规范化关键数据有任一不同，整组为 `batch_conflict`：商品条码、商品名称、保质期、保质期单位、`是否该做临期折扣`、`该批次累计到货数量`。
- 商品库存总数是商品级字段，不参加批次关键数据冲突签名；它由独立库存冲突结果处理。
- 冲突结果必须保留批次键、全部相关 Excel 行号以及发生差异的字段名；不得选择第一行、最后一行或任意一行作为有效批次。
- 整组冲突不得进入正常批次结果；其他键的正常批次继续分类。

### 7. 同商品库存总数冲突

- 对食品行中商品编码有效的所有行按 Trim 后商品编码分组；暂不支持行不参与。
- 商品库存原始文本只做 Trim，`null` / 空白作为明确的“空值”参与同商品一致性比较，防止在一行空白、一行 `0` 时静默选中 `0`。
- 同一商品出现两个或以上不同库存文本值时，生成一个 `stock_conflict` 商品级结果，保留商品编码、全部不同值和对应行号。
- 冲突结果不得暴露“选中的库存值”；可使用 `null` 明确表示没有可用单值。
- 商品仅有一个一致库存值时可在普通商品库存结果中原样保存该单值，但本卡不得据此更新库存或执行任何状态判断。
- 库存冲突不删除、不停止、不归零、不创建任务，也不使该商品其他正常批次变成批次冲突。

### 8. 普通内存结果

结果对象至少应能稳定回答：

- 总解析行数、食品行数、跳过行数。
- 行级问题及其行号、问题代码、字段名和安全摘要。
- 正常批次组及其批次键/代表数据/来源行号。
- 完全重复行及代表行号。
- 批次冲突组、全部行号和差异字段。
- 每商品库存的一致单值，或库存冲突的全部值/行号且无选中值。

结果 DTO 不得引用 EF、DbContext、Domain 实体、WPF 或持久化状态；不增加新增/更新/任务/生命周期字段。
