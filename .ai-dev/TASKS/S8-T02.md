## 证据与目标

S8-T01 已关闭。真实规模 100,000 Batch / 300,000 Inspection / 300,000 InspectionItem；tasks=399,998，SQLite=225,427,456 bytes。Dashboard、待排查首载/深页/大类/组合、Today 和 Reminder 存在 `too many SQL variables`。Stage median 6631.67 ms，历史列表 887.29 ms。

## 必须覆盖

1. Dashboard：数据库 count/summary，最多读取实际展示的紧急任务；保持统计语义。
2. 待排查：首载、深页、搜索、Stage、大类及任意两项/三项组合；最终条件决定 TotalCount，数据库端稳定分页。阶段优先级→最近有效期→identity 保持权威主排序，空有效期仍排最后。
3. Today：首载/大类与实际使用链数据库端读取；消除全量列表后内存过滤；Draft、选择/导出、提交后刷新与生命周期语义不变。必要分页接线必须保持用户可访问全部任务，不能只截前 50 条并让剩余任务不可达。
4. Reminder：只优化候选读取，不构造超大 ID IN；每日、同日幂等、补提醒、预提醒日期、Excluded、调度规则不变。不能为下推重复实现或改变 Stage 计算权威；必要候选可流式消费，真实记录仍需应用权威计算的工作量。
5. 历史：数据库分页/排序/count，item count 只针对当前页聚合，避免 300k 全量 materialization 和放大的 correlated count；详情/Revision 不变。真实 UI 必须消费分页结果，不能仅新增无人调用的优化接口。

允许最小 Application / query implementation 重构和必要 ViewModel/分页操作接线；禁止把查询优化逻辑写入 ViewModel。没有全局 UI 重构，ComboBox、StageBadge、中文显示与主排序语义冻结。新增分页操作只可复用现有中性控件样式，不重做页面。
