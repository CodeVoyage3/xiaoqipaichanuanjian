## 目标

实现商品当前库存已经被调用方明确确认为 `0` 时唯一、可复用的 Application 生命周期用例：结束商品当前生命周期，停止其全部历史/当前 Batch，系统关闭开放 ProductTask，使其有效 Draft 失效，并写入批准范围内的 LifecycleEvent。

本卡只消费明确的商品归零事实，不解析或推断该事实为什么产生。后续 Excel 明确归零与 Stage 4 人工库存修正归零必须复用本用例，不得各自实现状态转换。

## 已核验的现有 schema 与 canonical 值

无需新增平行字段或 migration；必须复用：

- Product：`EffectiveStockQty`、`LifecycleGeneration`、`IsStockZeroTerminated`、`UpdatedAtUtc`。
- Batch：`LifecycleGeneration`、`TrackingStatus`、`StopReason`、`StoppedAtUtc`、`CurrentStage`、`NextTriggerDate`、`UpdatedAtUtc`。
- ProductTask：`Status`、`ClosedAtUtc`、`CloseReason`、`UpdatedAtUtc`。
- InspectionDraft：`IsInvalid`、`InvalidReason`、`InvalidatedAtUtc`、`UpdatedAtUtc`。
- LifecycleEvent：现有精确 9 字段与五类固定事件代码。

本卡固定使用以下既有稳定代码，不增加第二套命名：

- Batch 停止状态：`stopped`。
- Batch 停止原因：`product_stock_zero`。
- ProductTask 系统关闭状态：`system_closed`。
- ProductTask 关闭原因：`product_stock_zero`。
- Draft 失效原因：`product_stock_zero`。
- LifecycleEvent：`product_stock_zero`、`task_auto_closed`、`draft_invalidated`。

`CurrentStage` 保存归零前最后阶段作为当前记录痕迹，不重置为 `none`；`NextTriggerDate` 必须清空，确保 S3-T03 不再命中。

## 生命周期代 canonical 语义

现有实体与 Stage 1 数据底座已预留 Product/Batch 的 `LifecycleGeneration`，但此前治理没有唯一规定商品归零时的递增点。本卡固定后续共用语义：

- 首次从 `IsStockZeroTerminated == false` 执行正式商品级归零时，Product 的 `LifecycleGeneration` 使用 checked arithmetic 加 `1`，并将 `IsStockZeroTerminated` 置为 `true`。
- Product 的新代号表示下一次只允许数据库从未出现过的新批次键进入的新生命周期代。
- 归零时所有既有 Batch 仍属于它们原来被创建/跟踪的历史代，`Batch.LifecycleGeneration` 不改写；只停止跟踪并清空下一触发日。
- 后续库存重新大于 `0` 时，`IsStockZeroTerminated` 不得清回 `false`，Product 代号不得回退，历史 Batch 代号和停止状态不得改变。
- 对已经归零的 Product 重复执行不得再次递增 Product 代号。
- Product 代号为 `Int32.MaxValue` 且首次归零时必须明确拒绝并整体回滚，不得回绕。

该语义由本任务卡作为 Stage 3 后续 S3-T05 的唯一治理口径；不得另造“当前代/历史代”字段。

## 输入与前置条件

用例输入最少包含：

- `ProductId`：正整数且 Product 必须存在。
- `OccurredAtUtc`：由调用方显式传入，必须为 UTC；同时作为本次状态更新时间、停止/关闭/失效时间和事件时间。
- 可选 `SourceImportId` 或 `SourceAdjustmentId`：最多一个非空，用于将事件关联到已经持久化、当前事务可见的明确来源；允许二者均空。

前置条件：目标 Product 当前事务可见的 `EffectiveStockQty` 必须已经明确为 `0`。非零时拒绝执行且不得写入任何状态或事件。

本用例不修改 `ExcelStockQty`、`EffectiveStockQty` 或 `EffectiveStockSource`。库存事实由上游导入或人工修正用例在同一外层事务中先明确写入；S3-T04 只消费并执行生命周期结束。若上游刚修改库存或创建来源记录，必须在同一 DbContext/外层事务中先 `SaveChanges`，使归零事实和来源 ID 当前事务可见，再调用本用例，最终仍由外层事务统一提交或回滚。

来源校验：

- 非空 ID 必须为正数并存在。
- `SourceAdjustmentId` 对应的 InventoryAdjustment 必须属于目标 Product；不得依赖 schema 中仅“记录存在”的弱 FK。
- `SourceImportId` 必须存在；Import 没有商品归属字段，本用例不得伪造该关联。
- 两个来源不可同时传入。
- 本卡不接受或创造 SourceInspectionId；商品库存归零的当前批准来源为明确导入事实、人工库存修正或无单一持久化来源的直接系统调用。

不得读取系统当前时间。

## 状态转换

每次调用都按目标 Product 定向核对并修复应有终态，但只在真实变化时写字段或事件。

### Product

- 首次正式归零：`IsStockZeroTerminated = true`，`LifecycleGeneration = checked(old + 1)`，`UpdatedAtUtc = OccurredAtUtc`。
- 已归零：保持标记和代号，不重复递增；若其他关联状态已经是正确终态，整次返回幂等无变化。
- 不改商品编码、名称、条码、品类、策略、三个库存事实字段、LastSeenImportId 或 CreatedAtUtc。

### 全部历史/当前 Batch

必须按 ProductId 查询该商品所有 Batch，不只处理当前任务项或活动阶段：

- `TrackingStatus = "stopped"`。
- `StopReason = "product_stock_zero"`，商品级最高优先级原因覆盖此前当前停止原因。
- `StoppedAtUtc = OccurredAtUtc`。
- `NextTriggerDate = null`。
- `UpdatedAtUtc = OccurredAtUtc`。
- 保留 `CurrentStage`、`LifecycleGeneration`、到货数量、AttentionVersion、唯一键、Import 关联和其他历史字段。

完全已处于上述终态的 Batch 不得无意义更新时间；其他商品 Batch 不得被读取为目标集合或被修改。

### 开放 ProductTask

若存在 `Status == "open"` 的任务：

- 原地设为 `system_closed`。
- `ClosedAtUtc = OccurredAtUtc`。
- `CloseReason = "product_stock_zero"`。
- `UpdatedAtUtc = OccurredAtUtc`。
- 保留 Task、TaskItem 和正式 Inspection 历史，不删除、不伪装为 `completed`。

没有开放任务时正常完成，不伪造任务关闭动作或事件。历史已关闭任务不得修改。

### Draft

只处理本次实际关闭的开放任务所关联 Draft：

- 有效 Draft：`IsInvalid = true`、`InvalidReason = "product_stock_zero"`、`InvalidatedAtUtc = OccurredAtUtc`、`UpdatedAtUtc = OccurredAtUtc`。
- 保留 Draft 与 DraftItem、人员、日期、数量、版本和创建时间；不得物理删除或转换为正式排查。
- 已失效 Draft 不重复失效、不覆盖原失效原因/时间、不伪造事件。
- 无 Draft 时不创建 Draft，也不创建 Draft 失效事件。

## LifecycleEvent

仅记录实际发生的批准事实，所有事件 `ProductId` 为目标 Product、`BatchId = null`、`OccurredAtUtc` 与本次请求相同，并原样使用已校验的单一来源：

- 首次 Product 归零转换：一条 `product_stock_zero`。
- 本次实际关闭开放 Task：一条 `task_auto_closed`。
- 本次实际使有效 Draft 失效：一条 `draft_invalidated`。

各事件 `Reason` 使用非空白稳定值 `product_stock_zero`。没有对应实体/转换时不伪造事件；完全重复调用不生成重复事件。不得新增事件类型、事件工厂、通用事件框架或按 Batch 批量生成商品归零事件。

## 幂等与修复语义

- 完全相同归零事实重复调用：Product/Batch/Task/Draft 字段不变，不更新时间，不新增事件。
- Product 已标记归零但发现同商品存在错误新增的活动 Batch、开放 Task 或有效 Draft时，本用例仍执行最高优先级终态修复；不重复递增 Product 代号或补写第二条 `product_stock_zero`，但对本次实际关闭/失效的实体分别写对应事件。
- 库存后来恢复大于 0 时，本卡不自动调用自身、不恢复任何 Batch/Task；若在非零库存下误调用，明确拒绝。

## 事务边界与组合

Product、该商品全部 Batch、开放 ProductTask、Draft 和 LifecycleEvent 必须处于同一个 StoreDbContext 与数据库事务：

- 当前无事务时，本用例拥有事务并统一提交/回滚。
- 当前已有外层事务时，本用例加入该事务，不得嵌套提交；库存事实/来源记录与生命周期转换由调用方最终统一提交或回滚。
- 任一步失败时不得留下半更新；本用例自有事务必须回滚并清理 ChangeTracker，避免后续误提交。
- 外层事务由调用方负责最终回滚；本用例异常时不得擅自提交外层事务。
- 不在生产代码加入测试故障开关。使用真实 SQLite trigger/约束制造中途失败并用新 DbContext 验证整体回滚。
