# S7-T03｜本地备份 / 恢复 WPF 接入

## 目标

在 S7-T01 已完成安全备份、S7-T02 已完成安全恢复基础之上，把备份与恢复能力接入现有 WPF，形成用户可操作的本地数据保护闭环。

本任务只负责：

- 提供最小“数据备份 / 恢复”入口；
- 用户可手动创建安全备份；
- 用户可查看可用备份；
- 用户可选择一份已验证备份并执行受控恢复；
- 恢复成功后避免继续使用旧 DbContext / 旧运行状态；
- 全程复用 S7-T01 / S7-T02 已验收能力，不在 UI 重写备份或恢复逻辑。

本任务不做数据导出，不做自动备份策略扩展，不做备份自动删除，不做全局 UI/UX 重构。

## 核心范围

### 1. 数据保护入口

在现有应用内增加最小入口：

`数据备份与恢复`

位置必须沿用现有导航 / 设置体系，不创建第二套 Shell。

本 Task 不做全局导航重构。

---

### 2. 手动创建备份

用户可点击：

`立即备份`

行为：

1. 调用 S7-T01 已验收的备份用例；
2. 备份进行中禁止重复提交；
3. 成功后显示明确结果；
4. 刷新可用备份列表；
5. 失败时显示可理解错误，不伪装成功。

成功信息至少应能让用户知道：

- 已完成
- 创建时间
- 文件大小
- 备份身份 / 文件名

SHA-256 可以在详情中显示或复制，但不要求把完整哈希长期占据主界面。

UI 不自行复制数据库文件。

---

### 3. 可用备份列表

展示当前应用正式备份目录中可恢复的备份。

列表数据必须来自经过校验的 Application 查询 / S7-T01 元数据事实。

至少展示：

- 创建时间
- 备份文件名 / ID
- 文件大小
- 验证状态

如现有元数据能够稳定提供，可显示：

- SHA-256
- migration 状态

要求：

- 默认按创建时间倒序；
- 无备份时有明确空状态；
- 临时半成品不得进入列表；
- 校验失败 / 损坏备份不得显示为“可正常恢复”。

如果需要展示“不可用备份”，必须明确标识不可恢复，且恢复按钮禁用。

---

### 4. 恢复选择

恢复必须由用户明确选中一份备份后发起。

禁止：

- 默认选择并自动恢复最新备份；
- 启动应用时自动恢复；
- 单击列表行即直接恢复；
- 从任意外部 SQLite 文件绕过 S7-T02 验证。

本 Task 默认只恢复当前应用管理的备份集合。

---

### 5. 高风险确认

恢复前必须有明确二次确认。

确认内容至少表达：

- 当前数据会被所选备份替换；
- 系统会先创建恢复前保护备份；
- 恢复完成后当前应用需要退出 / 重启以重新加载数据；
- 此操作不可在当前运行态“无感撤销”。

不要求用户输入复杂确认文本，但必须是显式确认，不得只有一个容易误触的普通按钮。

---

### 6. 恢复前运行状态协调

恢复不能在普通业务仍持有旧数据库连接时强行执行。

UI / runtime 必须按 S7-T02 已验收契约进入安全恢复边界。

至少处理：

- 防止与正在进行的正式提交并发；
- 防止与备份并发；
- 暂停 / 停止会访问数据库的 Reminder scheduler；
- 释放需要关闭的 DbContext / connection；
- 不绕过 Stage 4 Draft / Submission 已有离开与保存门禁。

如果当前有未完成 Draft：

- 不得因恢复 UI 静默丢失；
- 应沿用既有保存 / 离开门禁；
- 不在本 Task 发明第二套 Draft 处理规则。

---

### 7. 恢复执行

用户确认后：

1. 进入恢复进行中状态；
2. 禁止重复点击；
3. 调用 S7-T02 Restore 用例；
4. 显示明确结果；
5. 不在 UI 自己进行文件替换、SHA、integrity 或 migration 判断。

S7-T02 是恢复权威。

---

### 8. 恢复成功后的应用行为

恢复成功后，禁止继续长期使用恢复前的旧 DbContext / ViewModel 数据。

优先产品行为：

1. 显示：
   `恢复成功，应用需要重新启动以加载恢复后的数据。`
2. 用户确认后正常退出当前应用；
3. 停止 scheduler；
4. 清理 Tray；
5. 进程归零；
6. 用户重新启动应用后，从恢复后的正式库重新初始化。

如果仓库已经存在安全、经过验证的完整 runtime reinitialize 能力，可由 Luna 提交事实给 Sol 决定是否复用。

未经明确证据，不得为了“体验顺滑”在本 Task 中自行实现复杂热重载。

---

### 9. 恢复失败

恢复失败时：

- 不显示成功；
- 显示 S7-T02 返回的主要失败语义；
- 如果 S7-T02 已确认原库安全回退成功，允许用户继续使用应用；
- 如果返回 `critical_restore_failure` / rollback failure：
  - 明确提示严重错误；
  - 不允许继续普通业务写入；
  - 引导退出应用；
  - 不伪装成普通失败。

具体文案可按仓库风格处理，但严重程度必须可区分。

## 正式数据保护

正式数据库不得用于 GUI 恢复测试。

当前正式基线：

- 大小：`299008 bytes`
- 历史已验证 SHA-256：
  `F3D423DF14B882D7BFE87780A81CF5879F074AF4880601CBEDB6B475A964F522`

由于本机既有 Junction 异常可能影响工具侧直接枚举 / 哈希读取：

- 能独立读取时必须重新核验；
- 无法读取时必须如实记录“本轮未重新确认”；
- 不得用历史值冒充本轮读取成功。

GUI 验收必须使用隔离数据库与隔离备份目录。

验收结束后：

- 应用进程 = 0
- 清理隔离 / 临时恢复环境
- 恢复正式运行环境
- 核对正式库大小
- 能读取时核对 SHA-256
- 无 WAL / SHM / journal / restore staging 残留
- 恢复后不要为了复看再次启动应用
