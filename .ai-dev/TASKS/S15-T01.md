# S15-T01｜在线更新进度界面简化

S15-T01 = `GOVERNANCE_FROZEN / IMPLEMENTATION_AUTHORIZED / NOT_IMPLEMENTED`

基线：fresh fetch 后 `main == origin/main == 7cfbcd340aec97c55da880002779177c5a27834e`；Stage14/S14-T01 已关闭，stable/latest = `v1.0.5`。主工作树既有用户文件必须原样保留。

## 实现要求

1. 发现新版：只保留标题、当前版本、最新版本和“稍后提醒 / 立即更新”；右上角 X 等同稍后提醒。移除初始取消更新、长 Release Body 和技术说明。
2. 立即更新后：只映射三种用户状态——下载中、更新中、安装中；内部签名、重验、准备、maintenance、ACK、journal 等只写日志，不直出 UI。
3. 下载中：显示 `下载中 N%` 和确定进度条；不显示 bytes，默认不显示 MB；完成后沿现有流程进入更新中。
4. 更新中：显示 `更新中…` 和不确定进度条，不伪造百分比。
5. 安装中：现有流程把控制权交给独立 Updater 前显示 `安装中…`，随后按既有安全流程退出；不改 Updater UI 或协议。
6. 取消：仅用户已点击立即更新且现有机制仍安全支持取消的下载阶段显示；更新中、安装中隐藏/禁用。关闭窗口复用同一现有安全边界，不新增确认链。
7. 原有稍后提醒二次文案和逻辑必须保持通过。

## 实现纪律

- 优先只改现有更新窗口/ViewModel/状态文案映射和最小直接测试；先追踪现有调用者与 cancellation 边界，再选择最小共享修正点。
- 从治理 push 后的 `origin/main` 创建全新隔离 worktree 和全新 Terra；Terra 只实现本卡并提交。
- 禁止接触正式 SQLite、正式数据根、备份与正式安装根。
- `NO_FULL`；完成最小专项和必要 Release build 后停止。不 tag、不 Release、不创建 v1.0.6 或 S15-T02。
