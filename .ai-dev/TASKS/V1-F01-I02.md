## 5. 管理状态与策略契约

### 5.1 强制不变量

- Managed：必须有非空 `PolicyCode + PolicyVersion`；
- Excluded / Unresolved：`PolicyCode + PolicyVersion` 必须为空；不得创建伪 policy；
- `policy_code` 不含版本号；V1 版本固定为 `1`。

### 5.2 六类通用长效组

`日用、美妆、家居、香氛香水、文具、潮流玩具`：

- 实际总效期 `> 180` 天：Managed，`general_long_expiry / 1`；
- 实际总效期 `<= 180` 天：Unresolved，policy/version 为空，并产生稳定、可审计的 `expiry_policy_unresolved` 导入提示；提示必须明确“规则未覆盖”，但该 Product/Batch 仍正常保存。

现有 Excel 总效期以正整数和 `D/M/Y` 表达。边界判定必须复用现有生命周期的总天数换算：`D = value`、`M = value × 30`、`Y = value × 365`；不得另建换算体系。`180D`、`6M` 必须命中 Unresolved。

同一 ProductCode 的有效行若推导出不同的 CategoryCode、管理状态或 policy identity（例如通用长效组同时出现 `<=180` 与 `>180`），按身份冲突处理，不得择一覆盖。

### 5.3 排除类

`应季搭配`、`赠品小样`必须正常保存 Product / Batch，标记 Excluded，policy/version 为空：

- 不是异常，不产生 ImportIssue；
- 不丢弃、不伪造成未知类别；
- 不进入 Stage、Task、Reminder 或后续首次冷启动。

## 6. 既有 ProductCode 身份冲突

ProductCode 仍是唯一业务身份。对于数据库中已有 ProductCode，入站推导的：

`CategoryCode + ExpiryManagementStatus + PolicyCode + PolicyVersion`

必须与持久化身份一致。任何不一致形成稳定、可审计的 `product_scope_policy_conflict` ImportIssue：

- 不静默改绑；
- 不复制 Product；
- 不导入该 ProductCode 的新 Batch / 库存事实；
- 不触发生命周期；
- 同一导入内同一 ProductCode 只生成确定性问题记录，定位到最早相关源行。

不得改变 ProductCode、BatchKey 或其他既有业务身份。
