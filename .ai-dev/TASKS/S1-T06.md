## 必须实现

### 1. `imports`｜长期导入记录

字段：

- `id`
- `source_file_name`
- `source_file_sha256`
- `parsed_at_utc`
- `confirmed_at_utc`（可空）
- `status`
- `product_count`
- `batch_count`
- `new_product_count`
- `new_batch_count`
- `updated_batch_count`
- `issue_count`
- `unsupported_category_count`
- `new_task_product_count`
- `pre_import_snapshot_path`（可空）
- `is_undone`
- `undone_at_utc`（可空）

约束与索引：

- 文件名、SHA-256、状态 Trim 后非空。
- SHA-256 必须为 64 位小写十六进制字符串；不设置唯一约束，重复文件如何记录由 Stage 2 决定。
- 所有计数字段均为非负整数。
- `is_undone = 0` 时 `undone_at_utc` 必须为空；`is_undone = 1` 时必须非空。
- 状态不锁死枚举，仅约束非空；状态值域与流转由 Stage 2 单一业务实现定义。
- 建立 `(status, confirmed_at_utc, id)` 普通索引及 `source_file_sha256` 普通索引。

### 2. `import_workbooks`｜原始工作簿 BLOB

字段：

- `id`
- `import_id`
- `original_file_name`
- `content`
- `sha256`
- `saved_at_utc`

约束与关系：

- `import_id` 唯一：一次导入最多保存一份原始工作簿。
- 文件名 Trim 后非空；`content` 必填且 BLOB 长度大于 0。
- SHA-256 使用与 `imports` 相同的 64 位小写十六进制约束。
- 外键引用 `imports(id)`，删除行为为 `NoAction/Restrict`，不得级联丢失工作簿。
- 不用数据库触发器限制总行数为 2，不把“成功导入”判断写进配置。

### 3. `import_issues`｜导入异常

字段：

- `id`
- `import_id`
- `row_number`（可空，文件级异常没有行号）
- `issue_type`
- `field_name`（可空）
- `safe_summary`

约束与关系：

- 行号存在时必须大于 0。
- `issue_type` 与 `safe_summary` Trim 后非空；`field_name` 可空。
- 外键引用 `imports(id)`，删除行为为 `NoAction/Restrict`。
- 建立 `(import_id, row_number, id)` 普通索引，保证单次导入异常稳定排序。
- 不在本卡定义异常类型枚举，不保存整行原始敏感内容。

### 4. 闭合既有导入来源关系

- `products.last_seen_import_id`、`batches.last_seen_import_id` 保持可空。
- 非空值必须引用 `imports(id)`，删除行为为 `NoAction/Restrict`。
- 不新增导航属性，不修改商品/批次业务字段。
- 迁移允许因 SQLite 增加外键而仅重建 `products`、`batches`；不得重建或修改其他既有业务表。

### 5. 架构边界

- 三个新实体分别使用独立 `IEntityTypeConfiguration<T>`；具体映射不得回到 `StoreDbContext`。
- 实体只承载数据，不新增解析、状态流转、哈希计算、BLOB 裁剪或事务方法。
- 不引入服务接口或文件抽象；Stage 2 出现真实用例时再实现。
