# Taste 第二审美层审查

> UIUX-R01 第二审。用途仅为识别 AI 模板化和机械化呈现风险，服务于既有原生 WPF 门店业务工具；不以营销站、Web SaaS、作品集或移动端视觉规则替换业务密度和可用性。

## 1. 审查结论

当前界面没有明显的 Bento、Glassmorphism、渐变背景、大阴影、霓虹紫、营销 Hero 或夸张动效，基础方向是可信的浅色 Windows 工作台。需要治理的不是“换一种潮流风格”，而是减少局部实现带来的模板感：每个区块都包 Border、每个数字都做图标卡、每页都重复标题/副标题/卡片外壳、状态被圆点和色块机械复制。

审美结论：保留低饱和蓝、浅灰画布、白色表面、原生控件和表格优先；通过层级、对齐、节奏和有意的降权建立个性。变化度 3、动效 2、密度 8 不变。

## 3. 仍像 AI 模板的地方

### 3.1 机械卡片化

1. 首页摘要把多个统计数字做成带图标的独立格子，形式像通用 SaaS Dashboard，即使数据本身是真实的，也会诱导用户先看装饰性数字。
2. 导入页三步编号、五格摘要和预览容器同时出现，形成“步骤卡 + 指标卡 + 表格卡”的标准生成式布局。
3. 详情页商品头、排查信息、批次表、正常批次和底部动作若全部使用相同 8 DIP 圆角 Border，会像套模板，而不是按任务风险分层。
4. 历史和备份页若每个说明都包独立圆角面，视觉重量会比数据和后果更大。

处理：保留必要的工作面边界，减少装饰性外壳；同一页最多使用一个主工作面和少量状态面，依靠标题、分隔线、对齐和内边距形成层级。

### 3.2 机械间距与对称

1. 所有区域都使用相同的顶部/底部留白，会让高频表格与低频说明获得同样优先级。
2. 工具栏、结果说明、表格和分页若均匀铺开，用户难以判断搜索、数据和动作的主次。
3. 以“每区一个图标 + 标题 + 描述”重复表达，会产生组件拼装感。

处理：主表内部采用 8/12 DIP 密集节奏，页面区段采用 16/24 DIP；在标题、主表和动作栏之间留出可识别但不过量的节奏。变化来自信息密度和任务顺序，不来自任意不对称或装饰形状。

### 3.3 层级与状态模板化

1. 用一个小色点表达草稿、正常、成功或在线状态，信息不足且像模板 Dashboard。
2. 把所有错误、空数据和筛选无结果都放在同一大块中央空白，会丢失下一步动作。
3. Hover 才显示复制、详情或风险说明，会把桌面表格变成不稳定的探索式界面。

处理：状态采用“文字结论 + 语义色 + 位置/动作”；空、筛选空、错误和锁定各自有原因与下一步；条码、编码、阶段和关键结果首屏可见，复制反馈是短时辅助而非唯一入口。

## 4. 吸收的 Taste 建议

以下建议与 Windows 长期桌面操作和现有验收基线一致，纳入设计方向：

- 建立单一且稳定的语义资源体系，不让每一页自创颜色、圆角、按钮或状态图形。
- 通过真实业务字段、短中文动作名、准确状态文本和完整文件/条码信息建立产品个性，不用假数据、装饰插画或营销文案。
- 让主要层级来自排版、对齐、边框、留白节奏和内容优先级，而不是颜色堆叠、渐变和阴影。
- 保持必要的不重复：标题说明缩短，低频辅助信息降权，重复的图标说明不再占据同等视觉空间。
- 统一焦点、选中、禁用、错误和危险确认的反馈；操作结果应在用户触发处附近可确认。
- 表格和详情明细使用一致的列线、行高、数字对齐、截断和复制反馈，避免同一产品有多套数据语言。
- 动效只用于短暂状态变化和加载可见性，默认不让动效承担品牌表达或业务解释。

## 5. 因业务定位拒绝的 Taste 建议

以下方向即使在营销站或通用 Web 产品中可能有审美价值，本项目明确拒绝：

| 拒绝项 | 原因 |
|---|---|
| Bento / 不规则拼贴网格 | 会把可扫描的任务表拆成视觉模块，损害列对齐和密度。 |
| Glassmorphism / 半透明模糊 | 原生 WPF 表格、焦点和文本对比不稳定，也不符合可信内部工具。 |
| 大留白、巨型标题、Hero 叙事 | 牺牲 1024x600 与 125% 下的主表和主要动作，增加滚动和寻找成本。 |
| 所有模块卡片化、卡片套卡片 | 造成层级噪声，信息价值被容器形状取代。 |
| 强渐变、发光、霓虹紫、装饰性插画 | 与门店操作、风险确认和现有低饱和语义色冲突。 |
| 营销页话术、品牌宣言、转化型 CTA | 用户要完成排查、导入和恢复，不需要营销叙事。 |
| Web-first 响应式重排、移动底部导航、滑动手势 | 产品边界是 Windows 桌面，键盘、DataGrid 和固定工作区优先。 |
| GSAP、连续滚动、复杂转场、自动轮播 | 引入 WPF 不需要的技术和延迟，无法提升高频业务判断。 |
| 以 hover、颜色或图标隐藏关键内容 | 条码、编码、有效期、数量和阶段必须可见、可复制、可读。 |
| 为追求极简而移除表格分隔线 | 本工具的横向扫描依赖适度边界和对齐，不能照搬长文档页面的无边框规则。 |
| 强制改用展示字体或暗色主题 | 中文桌面长用、既有 WPF 资源和当前用户基线优先，不以换字体制造差异。 |

## 6. 三类代表页的审美二审

### Dashboard

- 吸收：用新鲜度结论、优先表和短摘要建立叙事顺序；主动作只有“导入数据”。
- 修正：摘要从五个图标卡收敛为一条紧凑信息带；不要用趋势图、空洞 KPI 或大数字制造首屏气氛。
- 保留：真实优先任务表、商品条码、库存、有效期和详情动作。

### 待排查列表

- 吸收：搜索作为第一焦点，表格作为视觉主角，复制和状态在可见位置完成。
- 修正：不使用卡片包裹每一行；阶段筛选和分页降权但不隐藏；表头与行线承担阅读节奏。
- 保留：固定 50 条分页、Application 查询顺序和加载/真实空/筛选空/错误的区分。

### 排查详情

- 吸收：商品身份、库存风险、批次表和固定动作栏形成明确三段层级；正常批次渐进披露。
- 修正：不把每个操作做成同等按钮或彩色卡；“完成排查”唯一 Primary，危险后果在原生确认中明确。
- 保留：空白/0/正数量语义、重新确认、草稿状态、超库存、已完成、系统结束和任务不存在状态。
