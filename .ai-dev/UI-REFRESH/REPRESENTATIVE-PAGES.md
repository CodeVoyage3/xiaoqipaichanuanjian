# 三类代表页提案

> UIUX-R01 代表页方向稿。三页用于验证整体视觉语言，不授权全应用重构。现有业务查询、草稿、重新确认、库存修正和提交用例保持唯一权威。

## 1. 共同验收约束

三页都遵守以下规则：

- 商品名称、商品条码、商品编码、阶段、库存、有效期和数量按任务需要可见；条码和编码可直接复制，不能只在 Tooltip、详情页或悬停中出现。
- 表格是主工作面，优先保证表头、列对齐、行状态、复制反馈、键盘焦点和滚动边界；不用卡片堆叠替代数据表。
- 颜色与文字共同表达状态；阶段、正常、警告、重新确认、保存和错误不能只有色点或色块。
- 主动作命名清楚。详情页“完成排查”是唯一 Primary；清空草稿、修正库存、重新确认、返回等为次级或条件动作。
- 1024x600 DIP 和 125% DPI 先保证主信息、主表和当前动作；次级说明可压缩，但不隐藏业务身份或风险。
- 不新增排序、分页、阶段计算、导入删除、库存终止、草稿生命周期或提交授权逻辑；页面只呈现现有 ViewModel/Application 返回的事实。

## 2. Page A: Dashboard / 首页

### 2.1 仓库事实与当前问题

现有 `MainWindow.xaml:373-592` 已实现页面标题、导入数据按钮、名称/条码/编码搜索、摘要统计、最近导入信息和“优先处理”表格。数据来自 `InspectionTaskQuery.Dashboard`，`Stage4ViewModels` 负责加载状态和导航。

当前主要问题：

1. 摘要区的多个图标/数字格容易被读成通用 KPI 墙，不能快速回答“数据是否可用、现在先处理什么”。
2. 标题、数据新鲜度、优先表和“查看全部”层级接近，主路径不够短。
3. 搜索是跨首页进入待排查任务的重要入口，需和摘要、表格保持明确的工作关系。

### 2.2 目标布局结构

```text
┌ 页面标题 + 一句用途说明                         [导入数据] ┐
├ 搜索商品名称 / 条码 / 编码                               ┤
├ 数据新鲜度与可用性结论                                    ┤
├ 待排查摘要：总量 | 阶段分布 | 批次数 | 库存事实             ┤
├ 优先处理                         [查看全部待排查任务]      ┤
│ 阶段 | 商品名称 | 条码 | 库存 | 最近有效期 | 查看详情       │
└ 加载/空/错误或表格                                       ┘
```

- 页面标题区保持短，不使用 Hero、宣传语或大面积留白。
- “导入数据”位于标题动作位，是首页的明确 Primary；进入任务列表是表格区的次级链接动作。
- 数据新鲜度在摘要之前给出事实结论，例如最近成功导入时间、无导入数据或读取失败；不使用伪趋势图。
- 摘要只保留帮助判断工作量的数字，采用一条紧凑的水平信息带，减少每个数字独立成卡。
- 优先表使用 DataGrid，阶段、商品身份、条码、库存、最近有效期和详情入口保持稳定列。

### 2.3 信息优先级

| 层级 | 信息 | 视觉处理 |
|---|---|---|
| 第一 | 数据是否可用、待排查数量、优先任务的阶段/商品/条码/库存/日期 | 深色正文、表头清楚、靠前且不折叠。 |
| 第二 | 导入时间、阶段摘要、批次数、搜索入口 | 次级文字和紧凑分隔，始终可读。 |
| 降权 | 图标、辅助描述、版本或装饰性说明 | 小号次级文字或移至边缘，不使用大卡片和强阴影。 |

### 2.4 组件组合与操作层级

- `PageHeader` + `PrimaryButton(导入数据)`。
- `SearchBox`，占据主要工具栏宽度，支持名称/条码/编码和 Ctrl+F 路径。
- `FreshnessStatus`，使用 Success/Warning/Error 语义色加结论文字。
- `SummaryStrip`，使用统一表面和分隔，不使用五个独立彩色 KPI 卡。
- `DataGrid` + 阶段文本标签 + 详情次级按钮；详情按钮不隐藏在整行 hover。
- 操作层级：导入数据 -> 查看优先任务详情 -> 查看全部待排查任务 -> 其他辅助信息。

### 2.5 状态表达

| 状态 | 页面表达 | 可执行动作 |
|---|---|---|
| 加载中 | 表格位置保留，显示“正在加载”并避免伪造数据 | 暂不展示结论性空状态。 |
| 无导入数据 | 中性标题 + 说明数据尚未导入 | 引导“导入数据”。 |
| 无待排查任务 | 明确“当前没有待排查任务” | 可进入导入或任务列表，不显示空表假行。 |
| 读取错误 | ErrorSurface + 原因 + 重试 | 重试不改变搜索或已提交数据。 |
| 有任务 | 新鲜度、摘要和优先表同时可见 | 进入详情或全量列表。 |

### 2.6 1024x600 与 125% 行为

- 1024 DIP 下保留标题动作、搜索、新鲜度和优先表；摘要可减少内部间距，但不隐藏条码、库存或日期。
- 优先表操作列保持可见；若列宽不足，使用可预测横向滚动，不把身份字段压缩到不可读。
- 125% 下保持 13-14 DIP 正文和 1/2 DIP 焦点边界；长商品名、条码和日期截断时提供 Tooltip 或表格访问。
- Dashboard 内嵌 DataGrid 到滚动边界时，滚轮仍可把页面继续滚动，符合现有 `MainWindow.xaml.cs` 的滚轮转发行为。

### 2.7 预期视觉效果

第一眼得到“数据是否新鲜、现在有多少任务”；第二眼直接扫描优先表；第三眼进入详情或完整列表。页面像一张可操作的工作台，而不是统计大屏。

## 3. Page B: 待排查任务列表

### 3.1 仓库事实与当前问题

现有 `MainWindow.xaml:598-836` 有搜索、阶段筛选、清空筛选、DataGrid、加载/错误/空状态和分页。`PendingTasksViewModel` 使用 `FixedPageSize = 50`，并通过 `InspectionTaskQuery.SearchOpenTasks` 查询。

当前主要问题：

1. 搜索、阶段筛选、结果说明和清空动作都在工具区，缺少“先搜索、再筛选、最后看结果”的阅读顺序。
2. 1024 DIP 下列数较多，必须优先保护商品身份和任务判断字段，不能靠缩小字体解决。
3. 真实为空、筛选无结果和读取错误的页面动作不同，视觉上需要固定组件语法。

### 3.2 目标布局结构

```text
┌ 页面标题 + 用途说明                                  [刷新] ┐
├ 搜索商品名称 / 条码 / 编码     阶段筛选       [清空筛选]   ┤
├ 结果说明：共 N 条 / 当前页 / 当前筛选                       ┤
├ DataGrid                                                     ┤
│ 阶段 | 商品名称 | 商品条码 | 商品编码 | 批次数 | 库存 | 日期 | 详情 │
├ 分页：上一页                         第 x / y 页       下一页 ┤
└ 加载/空/筛选空/错误                                      ┘
```

- 搜索框是第一焦点；阶段筛选紧邻但视觉权重低于搜索；清空只重置当前筛选。
- 结果说明使用一行紧凑元数据，不占用独立大卡片。
- DataGrid 保留阶段、商品名称、商品条码、商品编码、批次数、库存、最近有效期和详情动作；可复制字段不依赖 hover。
- 分页区固定在主表之后，保持每页 50 条的现有语义，不添加客户端排序。

### 3.3 信息优先级

| 层级 | 信息 | 视觉处理 |
|---|---|---|
| 第一 | 搜索结果中的商品名、条码、编码、阶段、库存、最近有效期 | 表格主列，稳定宽度和清晰表头。 |
| 第二 | 批次数、结果总数、当前页、筛选条件 | 紧凑辅助信息和分页。 |
| 降权 | 清空、刷新、筛选说明、非当前页信息 | 次级按钮或文字动作，不与详情入口同权。 |

### 3.4 组件组合与操作层级

- `PageHeader` -> `SearchBox` -> `StageFilter` -> `ResultMeta` -> `DataGrid` -> `Pagination`。
- 阶段标签使用低饱和语义色加现有中文阶段文案；不增设颜色图例造成额外认知负担。
- 单元格复制后在邻近位置显示短时“已复制”文本或焦点反馈；字段本身始终可见。
- 操作层级：搜索/筛选 -> 查看详情 -> 清空筛选/刷新 -> 分页；没有批量删除、批量提交或隐式行操作。

### 3.5 状态表达

| 状态 | 页面表达 | 可执行动作 |
|---|---|---|
| 加载中 | 保留表头或表面骨架，显示加载文字 | 禁止重复查询或误点旧动作。 |
| 真实为空 | “当前没有待排查任务” | 可返回首页或导入数据。 |
| 筛选无结果 | “当前筛选没有匹配任务” | 显著显示“清空筛选”。 |
| 读取错误 | 错误标题、原因、重试 | 保留搜索与筛选，重试后重新查询。 |
| 有结果 | 表格和分页完整 | 进入选中任务详情。 |

### 3.6 1024x600 与 125% 行为

- 1024 DIP 下优先保留搜索、阶段、名称、条码、编码、库存、日期和详情；批次数可收紧列宽但不能消失。
- 表格可横向滚动时，滚动边界、焦点和列头仍可判读；不通过把整行变成卡片来逃避密度。
- 125% 下表头和单元格保持可读；长名称、条码和编码按现有截断/Tooltip 规则处理，复制仍作用于完整值。
- Ctrl+F 聚焦搜索并全选；Tab 从工具栏到表格到分页顺序稳定；Enter/Esc 不产生隐式提交。

### 3.7 预期视觉效果

列表第一眼像一张可检索的任务表，第二眼判断阶段和库存风险，第三眼进入详情。工具栏不抢表格注意力，密度高但列线、对齐和状态让长时间扫描不疲劳。

## 4. Page C: 排查详情

### 4.1 仓库事实与当前问题

现有 `MainWindow.xaml:1570-1998` 展示商品身份、库存、待排查批次、正常批次折叠区、草稿状态、库存修正和底部完成动作。`InspectionDetailViewModel.cs` 通过 Application 用例处理保存、重新确认、清空、库存修正和正式提交，并区分 Open、Completed、SystemClosed、NotFound、Error。

当前主要问题：

1. 商品身份、库存风险、批次表、草稿状态和底部动作都重要，若都使用同等圆角面板，阅读顺序不够强。
2. 自定义批次表与 DataGrid 的行高、焦点、状态边界需要同一套表格语言。
3. 清空草稿、修正库存、重新确认和完成排查的风险/优先级必须明显不同。

### 4.2 目标布局结构

```text
┌ [返回待排查任务]  商品名称                                  ┐
├ 条码：可复制     商品编码：可复制      当前库存   待排查批次 ┤
├ 排查人 / 排查日期 / 数据状态       [必要时修正库存]          ┤
├ 待排查批次（主表）                                           ┤
│ 阶段 | 生产日期 | 有效日期 | 到货 | 最近排查 | 检查数量 | 状态 │
├ 其他正常批次（默认折叠，显示数量）                           ┤
├ 超库存/重新确认/读取错误等紧邻事实的状态说明                 ┤
└ 草稿保存状态   [清空草稿] [修正库存]                [完成排查] ┘
```

- 返回动作靠近标题但不是 Primary；商品名是标题，条码在编码前并始终可复制，库存和待排查批次数字在身份区同屏。
- 待排查批次是页面主表，不嵌套成多个卡片；正常批次使用 `Expander` 默认折叠，标题包含数量和“正常”文字。
- 草稿保存状态固定在底部动作栏，保存中、已保存、失败和待重新确认均有文字。
- “完成排查”是唯一 Primary；它只在现有 `CanSubmit`/提交用例允许时可用，不能由视觉层自行放宽。

### 4.3 信息优先级

| 层级 | 信息 | 视觉处理 |
|---|---|---|
| 第一 | 商品名、商品条码、商品编码、当前库存、待排查批次、阶段、有效期、检查数量 | 顶部身份区 + 主批次表，始终可见。 |
| 第二 | 生产日期、到货数量、最近排查、排查人/日期、重确认原因、草稿保存状态 | 表格列、辅助元数据和固定底栏。 |
| 降权 | 正常批次、长说明、非当前状态的历史细节 | 默认折叠或次级文本，但标题、数量和展开入口可见。 |

### 4.4 组件组合与操作层级

- `BackLink` + `ProductIdentityHeader`，身份字段配复制入口/反馈。
- `InspectionMeta`，排查人、日期和当前库存事实；库存修正为次级按钮。
- `PendingBatchTable`，每行输入数量，空白/0/正数保持三态；有变化的行显示既有重确认或错误说明。
- `NormalBatchExpander`，默认收起，使用 Success 文字而非单独绿色点。
- `DraftActionBar`，状态文本、清空草稿、修正库存和完成排查。
- 操作层级：填写/检查数量 -> 必要时重新确认 -> 修正库存/清空草稿 -> 完成排查。超库存时先显示事实与确认后果，再由原生确认对话框承载。

### 4.5 状态表达

| 状态 | 页面表达 | 可执行动作 |
|---|---|---|
| 加载中 | 保留页面标题位置，显示加载详情 | 禁止重复动作。 |
| Open | 主表可编辑，底栏显示保存状态 | 输入、保存、重确认、修正、提交按用例约束。 |
| 需要重新确认 | 对应行使用 Reconfirm 色 + 文本 + 行内动作 | 只确认对应行，不能用全局按钮代替。 |
| 超库存 | WarningSurface + 当前库存/填写总量事实 | “完成排查”进入原生二次确认路径。 |
| Completed | 明确已完成，不显示可提交主按钮 | 查看事实或返回。 |
| SystemClosed | 明确系统结束原因 | 不提供提交。 |
| NotFound/Error | 结论、原因、重试/返回 | 不伪装成空表。 |

### 4.6 1024x600 与 125% 行为

- 1024 DIP 下优先显示商品身份、库存、主批次表、草稿状态和完成排查；正常批次继续折叠，辅助说明收紧。
- 底部动作栏保持可见或可通过页面末端稳定访问；完成排查不能被横向滚动或低高度裁掉。
- 125% 下输入框、数量、表头和焦点环不能重叠；条码、编码和日期完整值可通过复制/Tooltip/横向表格访问。
- Tab 顺序为返回 -> 身份可复制字段 -> 元数据/库存动作 -> 批次输入 -> 重确认 -> 底部动作；Enter 不绕过危险确认，Esc 只取消当前对话框或编辑。

### 4.7 预期视觉效果

第一眼识别商品和库存风险，第二眼逐行处理批次，第三眼确认草稿状态和唯一提交动作。页面像一张可复核的业务记录，而不是操作按钮集合。

## 5. 三页实施门禁

三页方向获得用户确认前，不进行全应用生产重构，不创建 UIUX-R02，不进入 Stage 8 实施。确认文字必须是：

> 新的整体视觉方向认可，可以按该设计系统进入生产 UI 重构。

确认后也应先按三页做最小范围真实 WPF 验收：功能结果、表格密度、条码/编码复制、加载/空/错误/危险状态、键盘焦点、1024x600 和 125% DPI。其他历史、导入、提醒、备份和对话框页面只能复用经确认的组件语言，不能借机改变各自业务边界。
