# UI/UX 设计方向

> UIUX-R01 设计治理稿。本文只定义既有原生 WPF 产品的呈现方向，不是生产实现任务，也不改变业务、数据或导航契约。

## 1. Design Read

门店工作人员在 Windows 桌面上高频使用本工具，目标是快速识别效期阶段、核对商品与批次身份、填写数量并完成可追溯排查。产品应让人感觉像可靠的内部作业工具：信息先于装饰，状态先于动效，动作明确且可复核。

设计拨盘：

| 维度 | 值 | 解释 |
|---|---:|---|
| 变化度 | 3/10 | 以稳定网格和重复的控件语言建立熟悉感，只在首页、表格和详情的任务优先级上做有限变化。 |
| 动效 | 2/10 | 只保留加载、焦点和状态切换的短过渡；不使用营销式进入动画、滚动叙事或连续动效。 |
| 密度 | 8/10 | 让商品身份、阶段、库存、日期、数量和动作在首屏可扫描；通过对齐、分隔线和留白节奏避免压迫。 |

一句话定位：浅色、中性、低饱和蓝的原生 Windows 工作台，表格优先，边框优先，风险可见，长期操作不疲劳。

## 2. 方向原则

### 2.1 业务优先

视觉只承载 Application/Domain 已返回的事实。页面不重新推导阶段、库存、草稿、任务完成、恢复成功或导入删除含义。商品名称、商品条码、商品编码、批次、库存、有效期和数量是主信息，不得因为追求简洁而隐藏。

### 2.2 表格优先

列表和批次明细使用稳定列、明确表头、可复制单元格和可判读的行状态。容器的作用是界定工作区，不是把每一行数据包装成卡片。表格要有足够分隔线帮助横向定位，但不依赖阴影或颜色块制造层级。

### 2.3 状态先于装饰

加载中、无导入数据、无任务、筛选无结果、读取错误、业务拒绝、严重失败锁定和恢复后重启是不同状态。每种状态都需要短标题、原因或结论、下一步动作；颜色只作为辅助，必须同时有文字或位置语义。

### 2.4 一个明确主动作

每个页面只保留一个当前主要动作：Dashboard 为“导入数据”或进入待排查任务，详情为“完成排查”，导入页为“确认导入”，备份页为“立即备份”。次级、危险和取消动作按风险分层，不使用同等权重的按钮墙。

### 2.5 低频控件渐进披露

正常批次、Revision、辅助说明和低频设置可以折叠或置于次级区域；商品身份、阶段、库存、有效期、草稿状态和当前可执行动作不能折叠。折叠必须有清楚的标题、数量和展开状态。

### 2.6 可信而非炫技

边框、对齐、低饱和语义色和小半径控件构成质感。阴影仅用于原生模态或确有层级需要的表面。没有渐变、玻璃模糊、发光、霓虹、营销口号或装饰性图表。

## 3. 视觉语言

### 3.1 画布、表面与层级

- 主画布为浅灰 `#F5F7FA`，工作区表面为白色，次级区可用 `#F8FAFC`。
- 普通内容由 1 DIP 边框、内间距和对齐形成层级；不要让每个区块都成为独立圆角卡片。
- 面板圆角控制在 6-8 DIP，输入和按钮控制在 4-6 DIP；不使用胶囊化的大标签或大圆角容器。
- 页面标题是 24 DIP 左右的稳定锚点，区段标题约 18 DIP，正文 14 DIP，表格 13 DIP；不使用巨型 Hero 标题。
- 页面级垂直节奏以 16/24 DIP 为主，密集工具栏和表格内部以 8/12 DIP 为主。

### 3.2 色彩

- 主色为低饱和可信蓝，用于 Primary 操作、链接、选中边界和焦点环；不把蓝色铺满整页。
- Success、Warning、Danger、Reconfirm 颜色只表达对应语义，且始终配文字、图标或位置提示。
- 普通文字使用深蓝灰，次级文字使用中灰，禁用文字降低对比但仍需可读；表格分隔线比普通边框更淡。
- 状态标签不使用仅颜色的圆点；圆点可作为辅助，但必须有“正常”“待确认”“异常”等文本。

### 3.3 字体与数字

- 中文优先 `Microsoft YaHei UI`，回退 `Segoe UI`；不引入展示型字体或外部字体依赖。
- 商品编码、条码、数量、日期和文件身份应保持稳定的数字扫描节奏，可按内容需要使用 `Segoe UI` 回退。
- 长名称、条码和文件名使用截断加 Tooltip 或表格横向访问；不通过缩小到不可读的字号解决溢出。
- 表头、正文、辅助文本的层级由字号、字重和颜色共同表达，不能单靠全大写、斜体或颜色。

## 4. 组件语言逐项契约

以下组件名称是本轮设计治理的明确范围。它们应复用同一套 WPF 语义资源和焦点语言，不代表现在要新增控件或修改生产 XAML。

| 组件 | 视觉与交互契约 | 业务/可访问性约束 |
|---|---|---|
| Navigation | 48 DIP 左右行高、左侧位置标记、文本和低饱和选中面。 | 当前页、禁用、忙碌和数据库保护锁定不只靠颜色。 |
| Page Header | 页面标题 + 一句用途说明 + 当前页一个主动作；标题不做 Hero。 | 回答“我在哪/能做什么”，不放营销话术。 |
| DataGrid | 白色主工作面、稳定表头、淡分隔线、固定优先列、可复制单元格和可见焦点。 | 不增加客户端排序或改变 Application 查询顺序；关键身份不依赖 hover。 |
| Status Tag | 小半径、低饱和语义色、中文状态文本，必要时配辅助图标。 | 阶段、正常、警告、重新确认和验证状态不能只用色点。 |
| Input | 32-36 DIP 高、清楚标签/占位、可见焦点、错误紧邻输入。 | 时间遵循 `HH:mm`；数量保留空白/0/正数三态；不以 placeholder 代替标签。 |
| Button | 36 DIP 左右、动作名明确、按风险分 Primary/Secondary/Destructive。 | Enter/Esc/Tab 行为可预测；不以孤立图标代替中文动作。 |
| Primary Button | 低饱和可信蓝实心面，单页最多一个当前主动作。 | 详情页唯一 Primary 为“完成排查”；不由视觉层放宽 CanSubmit。 |
| Secondary Button | 蓝色描边或低权重表面，靠近相关工作区。 | 用于返回、刷新、修正库存等辅助动作，不与主提交同权。 |
| Destructive Button | Danger 色实心或明确危险描边，只用于恢复、清空等不可逆风险动作。 | 后果先说、默认取消；不能以红色代替二次确认。 |
| Empty State | 短标题、原因/结论、下一步动作，位于相关工作面。 | 无导入、真实无任务和筛选无结果必须文案和动作不同；不使用大插画。 |
| Error State | ErrorSurface、可理解原因、重试/返回动作和稳定结果反馈。 | 不能伪装成空数据；严重失败锁定由 ViewModel 返回。 |
| Dialog | 原生 WPF 模态，目标和后果先说，取消为默认焦点。 | 恢复、库存归零、超库存、清空草稿和历史修改必须可复核；AutomationProperties 可读。 |
| Section | 小标题 + 数量/状态 + 必要说明，以边框/分隔和间距形成层级。 | 避免 Border 套 Border；正常批次等低频区可折叠但标题和数量可见。 |
| Toolbar | 高频搜索/输入靠前，筛选与刷新次之，清空和辅助动作靠后。 | 清空只作用于当前未提交筛选/表单；不隐藏主动作。 |
| Bottom Action Bar | 固定显示草稿保存状态，动作顺序稳定，主次权重清楚。 | 离开/提交遵守稳定保存门禁；“完成排查”唯一 Primary。 |

## 5. 页面骨架与层级

### 4.1 Shell

保持单一窗口、左侧导航和右侧工作区。左栏承担产品名、页面导航和低频设置，不承担业务数据；右侧从页面标题开始，之后是工具栏或新鲜度说明，最后进入主表面。窗口最小尺寸仍须支持 1024x600 DIP，125% DPI 不得造成主动作不可见。

### 4.2 Page Header

页面标题回答“我在哪”，短描述回答“这里能做什么”。标题区不放大段品牌话术；主动作在标题右侧或紧邻工具栏，位置在各页保持一致。返回详情时，返回动作与标题同一层级但不抢主动作。

### 4.3 Toolbar

搜索、阶段筛选、刷新、清空筛选和文件选择按任务顺序排列。高频输入先于低频菜单，清空只作用于当前未提交的搜索或表单。工具栏在窄屏时允许换行或收紧间距，但不能把主要动作藏进不可发现的菜单。

### 4.4 DataGrid / 明细表

表头、列宽、数值对齐、行高、复制反馈、选中和键盘焦点形成一个整体。商品身份优先保持可见；日期和数量右对齐或采用稳定的数字对齐；操作列保持窄而明确。详情自定义明细表也应遵守同一行高、分隔线和焦点语言。

### 4.5 Bottom Action Bar

详情页底部固定显示草稿保存状态和动作。状态文本不可只靠一个小圆点表达；“完成排查”是唯一 Primary，清空草稿和修正库存是次级动作，危险确认以原生对话框承载后果。

## 6. 交互与可访问性

- 键盘顺序遵循阅读顺序：导航、标题主动作、工具栏、表格、分页、底部动作；Ctrl+F 直接聚焦待排查搜索并全选。
- Tab、Enter、Esc 和方向键的行为在按钮、输入、表格、分页和对话框中保持可预测；焦点环使用高对比蓝色边界，不用阴影替代。
- `AutomationProperties.Name` 描述真实动作和字段，例如查看详情、恢复所选备份、确认保存数量修改；不能只读出图标或空白。
- 125% DPI 下文字、焦点、按钮文本、表头和 Tooltip 不截断关键身份；1024x600 下先保证主表和主动作，再压缩次级间距。
- 动效默认关闭或极短，仅用于加载可见性、状态切换和焦点反馈；不依赖动画传递业务结果。

## 7. WPF 实现边界

允许使用现有 WPF `Window`、`Grid`、`ScrollViewer`、`DataGrid`、`ListBox`、`Expander`、`TextBox`、`DatePicker`、原生 `MessageBox` 和已有 Style/Brush 资源。建议通过现有 `App.xaml` 资源、控件 Style/Template、Trigger、Binding 和 `AutomationProperties` 渐进统一。

禁止引入 CSS Grid、WebView、外部设计系统包、WPF 依赖迁移、Canvas/Web 动画、GSAP、浏览器模糊滤镜或新的 UI 框架。禁止把业务计算、状态机、数据库操作、导入/恢复校验塞进视觉层。本文的 token 和组件名称是治理草案，不等于现在要修改 `App.xaml` 或任何 XAML/C# 文件。

## 8. 明确禁止的方向

- Bento 网格、玻璃拟态、渐变背景、强阴影、发光边框和霓虹色。
- 所有模块卡片化、卡片套卡片、巨大 KPI 数字、Hero 标题、营销页话术和装饰性图表。
- 以大量空白换“高级感”、移动端底部导航、滑动手势优先、全屏抽屉替代桌面表格。
- GSAP、连续滚动动效、复杂转场、自动轮播和任何会延迟门店操作的动画。
- 只用颜色、图标或悬停显示关键状态；只保留产品名而隐藏条码、编码或数量。

## 9. 用户确认门禁

以下文字是进入生产 UI 重构前的唯一视觉方向确认句：

> 新的整体视觉方向认可，可以按该设计系统进入生产 UI 重构。

用户确认前，只允许修订本目录治理文档，不实施生产 XAML/C#，不创建 UIUX-R02，不进入 Stage 8 生产任务。确认后也应先以 Dashboard、待排查列表、排查详情三类代表页做最小实现和真实 WPF 验收，再决定是否扩展到其他页面。
