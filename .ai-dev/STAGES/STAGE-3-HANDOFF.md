## 四、不可违反的业务规则

### 效期算法

- 总效期 ≤270 天：剩余 >30 正常；≤30 且 >14 为 5折；≤14 且 >7 为 2折；≤7 且 >0 为收仓；当前日期 ≥ 有效日期为过期。
- 总效期 >270 天：剩余 >90 正常；≤90 且 >60 为 5折；≤60 且 >14 为 2折；≤14 且 >0 为收仓；当前日期 ≥ 有效日期为过期。
- 节点当天立即进入新阶段；任一批次任一时点只能命中一个阶段。
- 没有生产日期时仍使用 Excel 明确保质期与单位，不反推生产日期。

### 任务聚合

- 批次负责触发，商品负责排查；同商品只保留一条当前开放任务。
- 阶段优先级：过期 > 收仓 > 2折 > 5折。
- 软件离线跨阶段时只生成当前最高阶段；已有未完成任务直接升级，不并存旧阶段任务。
- 当前任务存在时新批次合并，不创建重复商品任务。

### 生命周期优先级

- Excel 仍是局部增量。未出现在本次文件的商品/批次绝不参与任何状态转换。
- 商品库存明确为 0 的规则只适用于本次实际出现、无库存冲突且库存合法为 0 的商品；优先级高于新批次、累计到货和阶段触发。
- 商品归零结束该商品全部历史/当前批次、关闭开放任务、使草稿失效并保留历史；以后库存恢复只允许真正新批次进入新生命周期，历史旧批次永久不自动恢复。
- 批次正式排查 0 只停止该批次，不等于商品归零；历史保留。
- 真正新到货只有 `当前累计到货 > 历史最高累计到货`；下降或回升到旧最高不触发。
- 仅因批次 0 件停止、商品从未归零、当前库存 >0 且累计到货首次突破历史最高时，旧批次才可恢复并直接进入当前最高阶段。
- 已有任务期间真正到货增加不重复建任务；草稿保留但必须标记重新确认。

## 五、架构与事务门禁

- 可纯计算的日期/阶段规则放在 Domain，不依赖 EF、WPF、Open XML 或系统当前时间；调用方显式传入业务日期。
- Application 负责编排 Task/TaskItem/Batch/Product/Draft/LifecycleEvent 的跨实体一致性与事务；EF 配置不实现状态机。
- 不向 `ConfirmedImportExecutor` 继续塞入完整 Stage 3 状态机。Stage 2 导入结果可作为触发输入，但状态转换必须是明确、可独立测试的后续用例边界。
- 一次商品归零、一次任务生成/升级、一次排查提交或一次恢复跟踪涉及的实体与 LifecycleEvent 必须处于清晰事务边界，不得半更新。
- 生命周期事件不是事件总线；只写五类已批准持久化事实，不建设发布订阅、Outbox 或通用规则引擎。
- 不新增 Repository/UnitOfWork、反射规则扫描、插件系统、通用状态机框架、接口加单实现或未来字段。
