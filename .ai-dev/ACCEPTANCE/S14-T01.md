## B. 最小专项自动化

1. 在人为阻塞更新检查时，主界面已显示、托盘创建已先尝试，普通业务不等待网络。
2. timeout、DNS/HTTP/限流/无效 metadata/取消/异常均不关闭主窗、不移除已成功托盘、不锁业务；默认检查超时保持合理有界。
3. 有新版时初始 UI 只有“稍后提醒 / 立即更新”；点击稍后提醒后准确显示固定文案，点击“知道了”后继续使用。
4. 提醒初始化失败时托盘仍存活、主窗关闭仍按托盘语义；托盘创建失败时主窗仍可用且提醒初始化仍被尝试。
5. 退出/关窗会取消活跃检查或下载，Dispatcher 不同步等待任务，后台异常被观察且不形成 UI 卡死。
6. 安装树其余身份合法且 `DisplayVersion != EXE FileVersion` 时通过 preflight；非法路径、AppId/名称/卸载器或不可读 EXE 仍拒绝；防降级仍有效。
7. `v1.0.4 -> 新 v1.0.5`：用旧 v1.0.4 Updater 或其精确启动契约启动候选 App；新 App 必须可靠出现真实主界面和托盘，后台检查不阻塞，不得留下“进程/Mutex 存在但无界面、无托盘”。这项证据归 App 兼容性，不归新版 Updater。
8. `v1.0.5 -> 后续版本`：新版 Updater 的 same-schema `Committed` 不会在普通应用 Loaded/ACK 前写 `Completed`；正确绑定后完成，错误/超时不伪成功；不新增 phase/协议。该证据不得反向标记 v1.0.4 -> v1.0.5 已通过。
