## 实现范围

- 使用当前用户会话命名 `Mutex` 阻止第二个应用实例产生第二套 scheduler 或托盘图标；重复启动仅提示从现有托盘打开，不引入跨进程通信框架。
- 主窗口关闭事件改为取消关闭并隐藏；应用切换为显式退出模式，托盘“打开”恢复、还原并激活同一个 `MainWindow`，不创建第二个窗口或重复初始化业务 runtime。
- 使用 Win32 `Shell_NotifyIcon` 建立最小托盘图标，提供“打开”“退出应用”和双击打开；退出时先停止 scheduler、删除托盘图标，再关闭窗口并结束应用。
- `DailyReminderScheduler` 使用单个可取消 WPF `DispatcherTimer`；启动时执行一次 S6-T01/S6-T02 流程，之后依据配置提醒时间安排检查。Timer 最多每分钟校正本地时钟，但仅到达计划检查点时访问数据库。
- 正常完成后调度到下一本地业务日；通知或登记失败、单次异常时 15 分钟后重试。scheduler 不维护第二套“今日已提醒”状态，同日幂等与时钟回拨继续由 S6-T01 决定。
- 主窗口隐藏时提醒渠道不绑定隐藏 owner，保证托盘状态下 Windows 集中提醒仍可见。
- 托盘使用 Windows 内置应用图标；未新增图片资源、NuGet、WinForms 引用或第三方 UI 框架。
