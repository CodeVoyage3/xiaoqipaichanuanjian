## 实现结论

- 新增一个具体 `ProductTaskAggregator` 和普通输入/结果 DTO；修改 S3-T01 计算器只增加唯一阶段优先级比较；新增一组真实 SQLite 测试。完整实现差异严格为三个授权文件。
- 输入只包含明确 ProductId、BatchId、canonical Stage、AttentionVersion、RequiresReconfirmation 和 UTC 更新时间；不读取 Excel、ImportPlan，不计算效期，不判断库存、新到货、恢复、日期扫描或批次停止原因。
- 聚合器验证 Product/Batch 存在、批次归属、批次 ID 唯一、阶段合法、版本非负且与当前事务可见的 Batch.AttentionVersion 一致，然后只查询该商品开放任务。
- 无开放任务时按待排查批次创建一条 ProductTask；已有开放任务时合并新批次并原地升级已有 ProductTaskItem。每个 Item 保留实际阶段，ProductTask.HighestStage 从全部 Item 重算。
- `none` 不创建 TaskItem，也不删除、降级或关闭既有任务事实；同一 Item 只允许相同输入或阶段/版本升级，降级输入整次拒绝。
- `expired > withdraw > discount_20 > discount_50 > none` 的唯一生产优先级实现位于 S3-T01 纯 Domain 类型；Application 只调用该实现，没有字符串字典序或第二套映射。
- 已有有效 Draft 时，阶段或版本升级将相关 TaskItem.RequiresReconfirmation 置 true；Draft/DraftItem 内容、时间和 ConfirmedAttentionVersion 保持不变。标记只由 false 变 true，本卡不伪造重新确认或清除标记。
- 完全相同输入不 SaveChanges，不改变 Task/Item/Draft 字段或更新时间，不增加 Task/Item。

## 事务与失败路径

- 没有外层事务时，聚合器创建并拥有一个 SQLite 事务；成功提交，异常回滚。
- 已有外层事务时，聚合器使用同一 StoreDbContext 和当前事务，执行 SaveChanges 但不提前提交/回滚调用方事务；外层回滚后 Task 与 Item 全部消失。
- 私有 mutation journal 只恢复本次聚合修改/新增的 tracked Task/Item，不管理持久化，不是 Repository/UnitOfWork，也不影响调用方其他跟踪实体。
- 真实 SQLite 触发器在 TaskItem 写入中途强制失败时，无外层事务不会留下 Task 或部分 Item；有外层事务时异常不夺取事务所有权，调用方仍可统一回滚。
- SQLite 部分唯一索引继续拒绝同商品第二条开放任务；任务项唯一索引继续作为重复批次的最终保护。
