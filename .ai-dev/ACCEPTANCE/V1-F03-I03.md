## 交付结论

- 新增单一薄 `BulkInspectionSubmissionUseCase`：严格请求门禁、全量当前事实预检、TaskId 升序、单一外层事务和批量结果归并。
- 每个正式提交均调用既有 `InspectionSubmissionUseCase.Submit`；没有复制 Inspection/Item、Task completed、Draft 删除、HandledAttentionVersion、0 件停止、LifecycleEvent、超库存判定或历史逻辑。
- 预检防御 Product/Task/TaskItem/Batch/Draft 关系、Managed policy/version 1/ScopeBaseline、Draft 完整性、Reconfirm、Attention、Stage、tracking、到货、库存和已有 Inspection；任一目标非法整批拒绝。
- 普通 Task 和超库存 Task 在同一事务内处理。首次 warning 或陈旧确认会回滚所有普通 Task 的未提交写入，并集中返回全部当前 Task/Product/库存/排查合计事实。
- 只有确认集合与全部当前 warning 的 TaskId/ProductId/库存/排查合计精确一致，才对 warning Task 再次复用单 Task Submit 并统一提交。
- 多 Task 第 N 个异常时，前序 Inspection/Item、Task、Draft、Batch、LifecycleEvent 与 HandledAttentionVersion 全部回滚。
- 全部目标由完全相同 InspectorName/CheckDate/SubmittedAtUtc 请求完成时返回 `AlreadySubmitted`，不创建第二份 Inspection；open/completed 混合或签名不一致整体冲突。
- 0 件和正数组合与逐 Task Submit 权威一致；历史查询可见正式 Inspection/Item，不产生 Revision。
