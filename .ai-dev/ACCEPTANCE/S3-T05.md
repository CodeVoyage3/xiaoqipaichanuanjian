- 真正新增到货唯一判断为 `CurrentArrivalQty > PreviousMaxArrivalQty`。现有 Batch AttentionVersion 通过 SQLite 条件 UPDATE compare-and-set 精确加一；target 重放无副作用，其他版本冲突拒绝。
- 真正新 Batch 从 Stage 2 原始默认状态启动，对齐 Product 当前 LifecycleGeneration；归零后的新键可进入新代，所有历史 existing Batch 在 Product 曾归零时永久不恢复。
- 活动新增到货与恢复均复用 S3-T01 直接计算今天阶段；Batch SaveChanges 后才调用 S3-T02，`none` 不建任务，Draft 内容与确认版本保留并标记重新确认。
- 只有 `stopped + batch_checked_zero`、Product 从未归零、当前库存大于 0、真正新增到货四条件齐备才恢复，并只写批准事件 `batch_tracking_resumed`。
- 自有事务统一提交/回滚；加入外层事务时不嵌套提交。真实 SQLite trigger 已覆盖 TaskItem 与 LifecycleEvent 中途故障，Batch/版本/Task/Item/Draft/Event 整体回滚。

## Sol 缺陷审查与修复

- Luna 初始实现仅在 new Batch 当前阶段、下一触发日和 UpdatedAt 与原请求完全相同时识别重放。若首次处理后已由 S3-T03 推进阶段或被正式排查停止，重放旧 new 请求可能降级阶段或错误恢复 Batch，因此未放行。
- 最终实现把首次 new 转换严格限定为 ConfirmedImportExecutor 新建后的原始默认 Batch 状态；一旦 generation、阶段、下一触发日、停止状态或关注版本离开默认值，同一 new 事实只作幂等无副作用处理。
- 新增真实 SQLite 回归分别锁定“阶段推进后重放不降级”和“正式停止后重放不恢复”。Sol 复查修复 diff 后重新执行全部门禁。
