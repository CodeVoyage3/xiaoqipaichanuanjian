## 二、业务与事务事实

- 每次 Submit 清洁并重读 Product、Task/全部 Item、Batch版本、有效 Draft/Item、库存及既有 Inspection，不信任 S4-T01 DTO、S4-T02 readiness、页面阶段/库存或调用方提交集合。
- 只有开放 Task、完整有效 Draft、非空 CheckedQty、合法检查人/日期、无需重新确认且 `ConfirmedAttentionVersion == TaskItem.AttentionVersion == Batch.AttentionVersion` 才能首次提交。
- 超库存首次返回当前库存/合计并保持完整业务图零写入；只有确认的两个值仍精确匹配当前重读事实才继续，库存或草稿变化会使旧确认失效。
- 首次提交创建唯一 Inspection 与全部当前 InspectionItem，各 Item 保存自身实际 Stage；0 件 Item 不遗漏并真实调用 S3-T06。
- 每个 Batch 只在正式事务内执行 `HandledAttentionVersion = AttentionVersion`；AttentionVersion 本身不变，版本相等不被用作提交凭证。
- 完成 Task 使用 canonical `completed`、ClosedAtUtc 与 UpdatedAtUtc；CloseReason 保持 null，不混入系统关闭原因。
- 正常有效 Draft 在同一事务内先删 DraftItem 再删 Draft；系统失效 Draft 保留。AlreadySubmitted 不重复业务动作，也不清理异常残留有效 Draft。
- Inspection/Item、S3-T06、Handled版本、Task完成和 Draft删除处于同一 SQLite 外层事务；自有事务失败整体回滚并清理 tracker，外部事务不被抢先提交或回滚。
