## 实现范围

- 新增离线 `DatabaseRestoreUseCase`：只接受带 S7-T01 JSON 元数据、大小、SHA-256 与 migration 身份的验证备份。
- 恢复前验证文件、元数据、SHA-256、`integrity_check`、关键 schema 与当前 EF migration；拒绝正式库自身、临时半成品、损坏、占用或 migration 不兼容的输入。
- Application 契约明确要求上层先停止数据库 runtime；本卡没有伪造在线 maintenance mode，也没有接入 WPF。
- 恢复前复用 S7-T01 一致性快照生成独立 `pre-restore` 保护备份；保护失败时不替换正式库。
- 使用正式库旁 staging 文件与 Windows 原子替换；只隔离该正式库精确对应的 `-wal`、`-shm`、`-journal`。
- 替换后重新核验字节级 SHA-256、完整性、schema 与 migration；最终验证失败时回退并复核原始 SHA-256。
- 回退失败或成功恢复后的本次副文件/临时文件清理不完整时返回 `critical_restore_failure`，不伪装 `restored`。
- 恢复与普通备份共用 S7-T01 进程内互斥；失败释放门禁并允许重试。
- 未新增 UI、schema、migration、包依赖、导出或 S7-T03 内容。
