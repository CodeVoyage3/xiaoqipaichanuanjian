## 实现结论

- 生产入口只接收当前 `StoreDbContext`，内部唯一查询 `Succeeded && !IsUndone && ConfirmedAtUtc != null`，按 `ConfirmedAtUtc DESC, Id DESC` 取一条；不存在 Import Id 参数或任意历史选择入口。
- 无候选正常返回 `no_candidate`。快照路径必须关联唯一 `pre_import/verified` BackupRecord，且路径、时间、64 位小写 SHA 均有效；文件缺失、关联错误、内容损坏、migration 或完整 schema 不一致均保守拒绝。
- 已保存快照验证只有一个三参数强入口，复用 S2-T05 的 `IsVerified(currentSchema, snapshotSchema)`，同时校验 SHA、SQLite quick/foreign-key、17 张表、列定义和 8 条 migration；Sol 删除了无调用的弱验证公开入口。
- 固定比较 `tasks`、`task_items`、`inspections`、`inspection_items`、`inspection_item_revisions`、`inventory_adjustments`、`lifecycle_events`、`drafts`、`draft_items` 九表。当前库与导入前快照逐表、逐列、双向比较，新增、修改、删除均阻断；导入前既有且未变记录不阻断。
- 草稿与草稿项明确属于阻断项。`imports`、`import_issues`、`import_workbooks`、`backups` 属于导入基础设施，不参与业务阻断；S2-T07 裁剪旧 Workbook 不会让最新 Import 天生不可撤销。
- Product/Batch 不与导入前快照直接比较，避免把候选 Import 自身增量误判；仅当 `UpdatedAtUtc > ConfirmedAtUtc` 时补充阻断。
- 结果明确区分 `no_candidate`、`snapshot_missing`、`snapshot_association_invalid`、`snapshot_invalid`、`subsequent_business_changes`、`business_state_unverifiable`、`eligible`。
- 资格判断全程不跟踪 EF 实体、不 SaveChanges；SQLite 与快照均只读打开。未实现恢复、Undone 写入、数据库覆盖、任意历史回滚、UI、备份恢复或 Stage 3+。
