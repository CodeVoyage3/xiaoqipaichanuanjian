# 关键决策

## D-001｜桌面技术栈

- 状态：已批准（2026-08-26）
- 决策：`.NET 10 LTS + WPF`，目标 `win-x64`，最终自包含发布。
- 原因：原生 Windows 桌面能力、离线运行、托盘/注册表/电源恢复事件接入直接；.NET 10 LTS 支持至 2028-11-14。
- 边界：不引入 Web 服务器、Electron、Python 运行时或跨平台 UI 框架。
- 风险：微软当前 .NET 10 支持列表不包含已结束支持的普通 Windows 10 22H2，只包含仍在生命周期内的 Windows 10 Enterprise/IoT LTSC 版本。对门店实际 Windows 10 版本必须实机验证，不能只凭编译通过宣称兼容。

## D-002｜最小代码结构

- 状态：已批准（2026-08-26）
- 决策：一个 WPF 应用项目和一个测试项目；应用内按 `Domain`、`Application`、`Infrastructure`、`UI` 文件夹分层。
- 原因：业务规则与 UI 隔离，同时避免多个空壳项目和单实现接口。
- 边界：仅在出现第二个真实实现或测试替身确有必要时抽象接口。

## D-003｜数据库与迁移

- 状态：已批准（2026-08-26）
- 决策：SQLite 单库文件，EF Core SQLite provider，版本化迁移；单进程互斥；启用外键，评估并默认使用 WAL。
- 数据：业务日期存 ISO 日期，时间戳存 UTC；数量使用整数。
- 升级：迁移前生成数据库安全副本；迁移失败保留旧库并提示，不进入主界面继续写入。
- 原因：SQLite 满足纯本地关系型数据库；EF Core 提供正式迁移历史和事务能力。

## D-004｜Excel 隔离与格式保真

- 状态：技术栈已批准；真实样表 round-trip 仍待 Stage 2 验证
- 决策：Excel 文件 I/O 集中在 `Infrastructure/Excel`，向应用层交付普通解析 DTO；领域层不引用 Excel 类型。
- 库选择：样表若为 `.xlsx`，优先用 Open XML SDK 原位回填最新原始工作簿的最后三列；不重建工作簿。
- 边界：不支持 `.xls`、宏、外部链接或特殊对象，除非真实样表证明必须支持；届时单独评估最小替代方案。
- 验收：必须对真实样表做“读取后回填并保存”的逐项视觉/结构比对，不能只做单元测试。

## D-005｜托盘、提醒与自启动

- 状态：已批准（2026-08-26）
- 决策：使用 WPF + Windows 自带托盘能力；关闭主窗仅隐藏，显式“退出软件”才终止进程。
- 自启动：当前用户注册表 `HKCU\\Software\\Microsoft\\Windows\\CurrentVersion\\Run`，无需管理员权限。
- 休眠恢复：监听 Windows 电源恢复事件并触发一次到期检查。
- 提醒：应用内集中提醒窗口，每个本地自然日最多主动出现一次；不引入推送服务或 Windows 通知平台依赖。

## D-006｜效期规则扩展

- 状态：已批准（2026-08-26）
- 决策：数据模型保存 `category_code` 与 `policy_code`；V1 代码只实现锁定的 `food_v1` 规则。
- 扩展方式：未来品类先新增策略实现与配置数据，不改商品/批次主键和历史表；V1 不建设动态 DLL 插件系统或门店可编辑规则界面。

## D-007｜安装与数据位置

- 状态：已批准（2026-08-26）
- 决策：应用程序与业务数据分离；业务数据放在当前用户的本地应用数据目录，安装覆盖和默认卸载均不删除。
- 安装器：Stage 9 使用 Inno Setup 生成安装 EXE；安装前升级备份，创建桌面快捷方式并默认配置自启动。
- 边界：V1 不做在线升级；用户已接受未签名安装包及 SmartScreen“未知发布者”限制，正式大范围分发时再评估代码签名。

## D-008｜工作簿与数据库备份

- 状态：已批准（2026-08-26）
- 决策：正式导入、恢复、版本升级前创建可恢复快照；自动备份保留最近 7 份；最近 2 份成功导入的原始 Excel 以 BLOB 形式和哈希一并保存在 SQLite。
- 原因：原始工作簿与导入业务数据可在同一事务提交或回滚，完整备份也只需复制一个经校验的数据库快照，避免数据库与外部文件半成功。
- 原则：快照先写临时文件、校验后再原子改名；恢复前先备份当前状态。
