# 门店效期排查软件 V1｜Codex 开发总纲

> 文档用途：作为本项目 V1 的唯一业务需求基线。Codex 产品经理与执行子程序均必须以本文件为准，不得自行扩展或改变业务规则。
>
> V1 范围：仅食品品类；Windows PC 本地安装软件；支持离线运行、Excel 增量导入、效期计算、待排查任务、排查反馈、历史追溯、集中提醒、导出与备份。

---

## 1. 产品目标

当前门店从系统导出《食品效期排查表》后，需要打印或直接打开 Excel 逐项排查。

V1 要把这个流程改造成：

`导入系统 Excel → 软件持续跟踪商品批次 → 自动计算效期阶段 → 到节点后生成商品排查任务 → 每日集中提醒 → 门店反馈实际批次数量 → 留存历史 → 导出最新排查结果`

软件只负责“排查确认”，暂不负责调价、收仓执行、盘亏、报废等后续业务动作。

---

## 2. V1 产品形态

- Windows 10 / 11 64 位桌面软件。
- 最终交付 `.exe` 安装包。
- 双击安装即可使用，不要求额外安装 Python、数据库或开发环境。
- 核心业务纯本地、完全离线可用；联网仅用于版本检查、获取更新说明及下载更新包。
- 无账号、无登录、无公司系统 API。
- 默认创建桌面快捷方式。
- 默认开机自启动。
- 主窗口关闭后进入系统托盘，不直接退出。
- 托盘提供“打开软件 / 退出软件”。
- 用户确认后在线升级，必须保留全部业务数据（详见第37节）。
- 卸载时不得默认删除业务数据。

---

## 3. V1 明确不做

V1 暂不开发：

- 手机端 / Web 端。
- 云端同步。
- 用户账号、员工权限体系。
- 后台无提示的静默强制升级。原“在线自动升级不做”已被2026-09-04用户产品决策覆盖，现支持用户确认后的在线升级。
- 系统 API 对接。
- 批量完成、批量填写 0 件、批量提交。
- 照片上传。
- 调价执行、收仓执行、盘亏、报废流程。
- 7～9 个月低销食品提前申请折扣特殊规则。
- 日用、美妆、家居、宠物等其他品类的正式效期规则。

底层数据结构必须预留未来多品类扩展能力。

---

# 4. Excel 数据原则

## 4.1 Excel 是“局部增量数据”，不是全量快照

这是项目最高优先级规则之一。

门店系统导出的 Excel 可以按商品范围、品类等条件筛选，因此：

- 本次上传可能是食品。
- 下次可能只上传部分食品商品。
- 未来可能上传日用或其他品类。
- 某商品或某批次本次没有出现，不代表它已经不存在。

因此每次导入只允许处理“本次 Excel 实际出现的数据”。

### 严禁

不得因为某商品或某批次未出现在本次 Excel 中而：

- 删除数据。
- 停止跟踪。
- 关闭任务。
- 修改库存状态。
- 修改历史排查结果。

---

## 4.2 V1 非食品数据

如果 Excel 中混有非食品数据：

- 食品正常导入。
- 非食品跳过。
- 不作为错误数据。
- 导入结果提示“本次有 X 条暂不支持的非食品数据未处理”。
- 不得影响数据库中已有食品数据。

---

# 5. 商品与批次识别

## 5.1 商品唯一身份

`商品编码` 是商品主体唯一识别依据。

同一商品编码：

- 商品名称变化：仍是同一商品。
- 条码变化：仍是同一商品。
- 当前商品名称、条码更新为最新导入值。
- 历史排查记录保留当时的商品名称、条码快照。

商品编码发生变化：视为全新商品，不与旧商品自动合并。

商品编码为空：该行进入异常数据，不导入。

商品名称或条码为空：允许导入，界面显示 `—`。

---

## 5.2 批次唯一身份

有生产日期时：

`商品编码 + 生产日期 + 有效日期`

无生产日期、只有有效日期时：

`商品编码 + 有效日期`

只要历史数据库中曾出现过该唯一组合，就属于旧批次；即使后来停止跟踪，再次出现在 Excel 中也不能当作“新批次”。

---

# 6. 日期与保质期字段

合法数据允许两种形式：

1. 生产日期 + 有效日期。
2. 只有有效日期。

只有有效日期时仍必须保留：

- 保质期。
- 保质期单位。

软件不反推生产日期。

有效日期缺失：异常，不参与自动跟踪。

保质期或保质期单位缺失：异常，不参与自动跟踪。

保质期单位：

- `M` = 月。
- `D` = 天。
- `Y` = 年。

内部换算：

- 1 月 = 30 天。
- 9 月 = 270 天。
- 1 年 = 365 天。

总保质期 ≤ 270 天：按食品“≤9 个月”规则。

总保质期 > 270 天：按食品“>9 个月”规则。

---

# 7. 食品效期算法

## 7.1 总效期 ≤9 个月

- 剩余 >30 天：正常。
- 剩余 ≤30 天且 >14 天：5 折。
- 剩余 ≤14 天且 >7 天：2 折。
- 剩余 ≤7 天且 >0 天：收仓。
- 当前日期 ≥ 有效日期：过期。

## 7.2 总效期 >9 个月

- 剩余 >90 天：正常。
- 剩余 ≤90 天且 >60 天：5 折。
- 剩余 ≤60 天且 >14 天：2 折。
- 剩余 ≤14 天且 >0 天：收仓。
- 当前日期 ≥ 有效日期：过期。

## 7.3 边界规则

节点当天立即进入新阶段：

- 到期前 30 / 90 天当天进入 5 折。
- 到期前 14 / 60 天当天进入 2 折。
- 到期前 7 / 14 天当天进入收仓。
- 有效日期当天立即视为过期。

任何批次在任一时点只能命中一个当前阶段。

Excel 的“是否该做临期折扣”作为导入时系统参考数据保留；后续实时阶段由软件根据上述规则持续计算。

---

# 8. 任务生成核心规则

## 8.1 任务单位

采用：

> 批次负责触发，商品负责排查。

同一商品不管有多少个临期批次，只保留一条当前待排查商品任务。

商品任务内部展示每个需要排查批次自己的当前阶段。

---

## 8.2 阶段优先级

`过期 → 收仓 → 2折 → 5折`

商品“当前最高阶段”取该商品全部待排查批次中的最高优先级。

---

## 8.3 只生成当前最高阶段

电脑关机、软件长时间未运行或任务未及时处理后，如果一个批次已经跨过多个阶段：

只生成当前应执行的最高阶段，不补历史阶段任务。

例：

正常 → 软件 10 天没开 → 当前已收仓。

只生成收仓任务，不补 5 折、2 折。

---

## 8.4 未完成任务升级

如果 2 折任务未完成，批次随后进入收仓：

- 原任务直接升级为收仓。
- 不保留一条 2 折未完成 + 一条收仓未完成。

同一商品已有未完成任务时，后续新增待排查批次直接合并进当前商品任务，不创建重复商品任务。

---

# 9. 草稿规则

排查填写过程中自动保存：

- 批次排查件数。
- 排查人。
- 检查日期。

切换页面、关闭窗口、退出软件、电脑重启后草稿仍保留。

草稿不等于正式完成。

只有点击“提交排查”才生成正式记录。

未提交草稿允许清空或放弃。

如果草稿期间：

- 效期阶段升级；或
- 累计到货数量发生真正增加；

保留已有草稿，但标记为“需重新确认”，未经确认不得直接提交。

提示示例：

`效期阶段已更新，请重新确认排查结果。`

`该批次累计到货数量已更新，请重新确认排查结果。`

---

# 10. 排查反馈规则

商品详情页对每个当前待排查批次填写“排查件数”。

含义：

- 空白：尚未检查。
- 0：已检查，确认该批次现场无库存。
- >0：已检查，现场仍有该批次库存。

同一商品当前所有待排查批次都填写后，才允许提交。

一次商品任务统一填写：

- 排查人。
- 检查日期。

排查人支持手工输入并记住最近使用人员。

检查日期默认当天，可改为历史日期，但不得填写未来日期。

---

# 11. 批次跟踪生命周期

## 11.1 排查件数 = 0

某批次正式提交 0 件：

- 该批次停止后续效期跟踪。
- 不再进入后续 2 折、收仓、过期提醒。
- 历史记录永久保留。

## 11.2 排查件数 >0

本阶段完成，但该批次继续跟踪。

进入下一阶段后再次生成新的排查任务。

例：

2 折排查 3 件 → 收仓再次提醒 → 收仓排查 1 件 → 过期再次提醒。

---

# 12. 累计到货与重新到货

每个批次保存：

`历史最高累计到货数量`

只有：

`当前累计到货数量 > 历史最高累计到货数量`

才视为真正的新到货。

历史最高 8 → 当前 5 → 6 → 8：均不算新到货。

只有变成 10 才算新增到货 2 件。

累计到货下降只更新最新系统数据，不触发任务。

---

## 12.1 当前阶段已经完成后又新到货

若该批次当前已经处于 5 折 / 2 折 / 收仓 / 过期，并且累计到货首次超过历史最高值：

即使该阶段此前已经完成过排查，也重新生成一次“当前阶段”排查任务。

不补历史阶段。

---

## 12.2 当前已有未完成任务时又新到货

不重复创建任务。

更新：

- 累计到货。
- 历史最高累计到货。

已有草稿保留但强制重新确认。

---

# 13. 商品库存总数规则

`该商品门店库存总数` 是商品级字段。

同一 Excel 中，同一商品编码对应的库存总数原则上必须一致。

如果出现多个不同值：

- 标记“库存数据异常”。
- 本次不更新该商品当前库存。
- 不执行库存归零规则。
- 其他正常批次数据仍可更新。
- 导入结果提示全部冲突值。

---

# 14. 商品库存总数 = 0

只有本次 Excel 明确包含该商品，并且库存字段明确等于 0，才触发商品级结束。

处理：

- 结束该商品所有历史及当前批次的跟踪。
- 关闭该商品所有未完成任务。
- 本次新出现的批次也不启动跟踪。
- 草稿失效，但保留系统失效记录。
- 历史排查记录全部保留。

`商品库存=0` 的优先级高于：

- 新批次。
- 累计到货增加。
- 效期阶段触发。

本次 Excel 没有出现该商品：不得做任何库存推断。

---

# 15. 商品库存归零后的恢复规则

如果商品曾经发生过商品级库存归零：

- 之前所有旧批次永久结束当前生命周期。
- 后续库存重新 >0 时，不恢复这些历史旧批次。
- 只跟踪数据库历史中从未出现过的真正新批次。

即使历史旧批次再次出现在 Excel 中，也不能当作新批次。

---

# 16. 批次 0 件后的重新到货例外

如果某批次只是因为“该批次排查 0 件”而停止跟踪，且商品从未发生商品级库存归零：

后续如果同时满足：

1. 当前商品库存 >0。
2. 该批次累计到货数量首次超过历史最高值。

则视为同一批次重新到货，可以恢复跟踪，并直接按当前日期判断最高阶段。

如果商品曾发生商品级库存归零，则此例外失效，历史旧批次不得恢复。

---

# 17. 手工修正库存

排查详情中的商品库存默认只读。

提供“修正库存”。

保存：

- Excel 原始库存。
- 修正后库存。
- 修正时间。

修正原因 V1 不强制填写。

如果修正库存为 0：

必须二次确认：

`库存修正为0后，将结束该商品所有批次的效期跟踪。`

确认后按“商品库存归零”规则执行。

下一次导入新 Excel 后，当前库存以新 Excel 为准；历史修正记录继续保留。

导出 Excel 时不得把手工修正库存写回原系统库存字段。

---

# 18. 排查件数超过库存

如果本次待排查批次反馈合计 > 当前商品库存：

弹出警告，但允许继续提交。

门店可以：

- 返回修改件数。
- 修正库存。
- 确认后继续提交。

正式提交时保存“本次排查库存快照”。

历史记录修改时，如果修改后的合计超过当次库存快照，同样只警告，不禁止修改。

---

# 19. 排查历史与修改

已正式提交的排查记录：

- 允许修改。
- 不允许删除。
- 必须保留完整修改历史。

修改记录至少保存：

- 修改前值。
- 修改后值。
- 修改时间。

V1 不强制填写修改原因。

---

## 19.1 修改对当前跟踪状态的影响

只有“该批次最近一次正式排查结果”的修改才允许改变当前跟踪状态。

最近一次 >0 改为 0：

- 停止该批次跟踪。
- 后续未完成任务自动结束。
- 对应草稿失效。

最近一次 0 改为 >0：

如果没有“商品库存归零”等更高优先级结束条件：

- 恢复批次跟踪。
- 直接根据当前日期生成当前最高阶段任务。
- 不补历史阶段。

修改更早的历史排查记录：只修正历史，不影响当前跟踪状态。

---

# 20. 系统自动结束

商品库存明确变为 0 导致待排查任务结束时：

不得记为“门店已完成排查”。

记录为：

`系统自动结束`

并保存原因与时间。

未提交草稿标记失效，不转成正式排查记录。

---

# 21. 每日提醒

默认提醒时间：10:00。

门店可以在设置中修改。

每天最多主动弹一次系统提醒。

所有任务集中提醒，不得一个商品弹一次。

提醒示例：

```text
食品效期排查提醒

当前有 28 个商品待排查
过期：3个
收仓：5个
2折：8个
5折：12个

[立即排查] [知道了]
```

“立即排查”打开待排查任务页。

“知道了”关闭提醒，当天不再主动弹第二次。

当天已经提醒过，之后 Excel 导入新增任务也不得再次弹窗，只在导入结果页提示新增任务数量。

---

# 22. 门店电脑关机 / 休眠

软件不得依赖 24 小时开机。

以下时机执行效期校验：

- 软件启动。
- Windows 睡眠 / 休眠恢复。
- Excel 成功导入后。

如果设定 10:00 提醒，但电脑 14:00 才开机：

- 启动时补算。
- 如果存在任务且当天尚未提醒，立即弹当天唯一一次提醒。

不逐日补算历史阶段，只判断当前应执行的最高阶段。

---

# 23. 高性能效期计算

禁止软件启动时扫描全部历史批次。

每个跟踪中的批次预存：

- 当前阶段。
- 下一效期触发日期。
- 跟踪状态。

启动时只查询：

`跟踪中 AND 下一触发日期 <= 当前日期`

对命中的批次直接计算当前最高阶段。

已停止跟踪的历史批次不参与启动计算。

---

# 24. Windows 日期异常保护

记录“上一次正常运行日期”。

如果本次系统日期早于上次运行日期：

提示：

`检测到当前电脑日期早于软件上次运行日期，请确认 Windows 系统日期是否正确。`

不得因为时间回拨：

- 降级任务。
- 删除任务。
- 修改历史记录。

---

# 25. Excel 导入流程

采用：

`选择文件 → 解析 → 预览 → 确认导入 → 结果`

不得选中文件后直接写数据库。

预览至少显示：

- 文件名。
- 商品数。
- 批次数。
- 新增商品。
- 新增批次。
- 已有批次更新。
- 新增待排查商品。
- 异常数据数。
- 暂不支持的非食品数据数。

完全相同的数据重复上传：提示无变化，不重复写入。

同一天允许多次上传；最后一次成功导入的文件作为“最新原始 Excel”。

---

# 26. Excel 异常规则

文件级必要列缺失：整份拒绝导入，并列出缺失字段。

行级异常：其他正常数据继续导入，异常行单独展示。

异常至少包括：

- 商品编码为空。
- 有效日期为空。
- 保质期为空。
- 保质期单位为空或不是 M / D / Y。
- 日期无法解析。
- 同一批次唯一键对应冲突数据。

同一份 Excel 中：

- 完全相同重复行：自动忽略。
- 同一批次但数据冲突：进入异常，不得擅自选一行。

---

# 27. Excel 最后三列

原始 Excel 的：

- 检查到该批次的件数。
- 检查人签名。
- 检查日期。

导入时一律不读取为正式排查结果。

正式排查结果只认软件内“提交排查”产生的数据。

---

# 28. 导出排查结果

只基于“最近一次成功上传的原始 Excel”生成。

不重新拼接历史全部批次。

尽量保持最新原始 Excel 的：

- 字段。
- 列顺序。
- 表格结构和格式。
- 原系统库存值。

只回填最后三列。

# 37. 安装与升级

2026-09-04产品决策修订：原规则“V1 不做在线自动更新”“新版本通过新版 EXE 覆盖安装”保留为历史，已被本节新规则覆盖，不再作为现行禁止项。

V1支持在线升级，核心业务完全离线可用。只有检查版本、获取更新说明、下载更新包需要联网；断网不得影响Excel导入、效期计算、待排查、正式排查、History、Reminder、Backup/Restore及其他本地核心业务。

冻结流程：发现新版→弹窗提示→用户点击“立即更新”→自动下载→校验更新包→自动完成更新→重启新版。用户可选择“稍后提醒”；不进行后台无提示的静默强制升级。后续更新不要求用户手工重跑新版安装器。

- 首个正式版本1.0.0；1.0.1为bug fix、1.1.0为新功能、2.0.0为大版本。
- 首次安装仍交付Windows 10/11 x64安装EXE；优先win-x64 self-contained，多文件程序目录允许，不强求WPF单文件，不开启危险trimming。门店无需.NET SDK、Visual Studio、Python或SQLite开发工具，目标无需另装.NET runtime。
- 当前Windows用户安装，不做全机安装；当前用户桌面快捷方式、默认开机自启动，尽量无需管理员权限，正常更新无需每次UAC。
- 更新源原则上为GitHub Release/Assets：版本、说明、更新包、SHA256；manifest/asset及信任契约由技术卡冻结。若资产需认证，不得将PAT、长期secret或仓库写权限token打包进客户端或存于门店机器；必须先解决安全分发blocker。
- 下载失败：旧版本继续使用；校验失败：禁止安装；程序替换失败：回滚旧程序；migration/升级失败：恢复升级前数据库保护备份并回到可用旧版本。不得把原本可用的软件更新成不可用。
- 升级前必须建立并验证可恢复保护备份；保留全部业务数据、草稿、设置和备份。程序与数据目录解耦；更新程序不得覆盖业务数据，卸载默认不得删除业务数据。正在运行的主WPF进程不得直接覆盖自己。
- 不新增门店身份、设备注册、版本上报、中央版本看板、在线状态、远程强制更新或中央设备管理。
- Import Undo已被用户永久取消，第30节及第34.5节、Stage2中的相关旧描述仅保留历史，不恢复执行器/UI或规划；设置页“重置数据”仍为未来独立需求，不纳入Stage9。

Stage8历史边界持续有效：结构合法外来WAL来源无法证明；严重坏当前不能生成健康保护快照时Restore fail-closed，不强制覆盖救援；真实物理断电、SSD controller、磁盘/文件系统损坏、bit rot、不可读介质未证明。

# 39. V1 关键验收用例

开发完成前至少覆盖以下用例：

1. 同一商品 5 个批次，其中 5折 / 2折 / 收仓并存，只生成一条商品任务，最高阶段为收仓。
2. 软件关机数日后启动，批次已经跨阶段，只生成当前最高阶段。
3. 某批次 2折排查 3 件，进入收仓后重新要求排查。
4. 某批次排查 0 件，后续普通时间推进不再提醒。
5. 批次排查 0 件后累计到货首次超过历史最高值，且商品未发生过库存归零、当前库存 >0，恢复当前阶段跟踪。
6. 商品库存明确为 0，结束商品所有批次；以后库存恢复只跟踪真正新批次。
7. 本次 Excel 完全没有某个历史商品，历史商品状态不得改变。
8. 本次 Excel 有某商品但缺少其某个历史批次，该历史批次状态不得改变。
9. 新 Excel 上传日用数据时，不得影响数据库中食品任务。
10. 同一商品在同一文件出现多个不同库存总数，不得执行库存归零。
11. 已存在任务期间累计到货增加，不创建重复任务，草稿保留但要求重新确认。
12. 历史排查记录修改为 0，只有它是最近一次正式记录时才影响当前跟踪。
13. 检查日期不能提交未来日期。
14. 本次排查件数合计超过库存，只警告，不禁止提交。
15. Excel 最后三列有人工值，导入时不得直接生成正式排查记录。
16. 导出只基于最新一次原始 Excel，并回填每个批次最近一次正式排查结果。
17. 10:00 电脑未开，14:00 开机后当天只补一次集中提醒。
18. 同一天已经提醒过，再导入产生新任务也不弹第二次系统提醒。
19. Windows 日期回拨不得导致任务降级。
20. 10 万批次 + 30 万历史记录下，首页和待办查询保持流畅。

# 40. 最终不可违反的 12 条原则

1. 商品编码是商品唯一身份。
2. Excel 是局部增量数据，不是全量快照。
3. 未出现在本次 Excel 的商品或批次不得因此改变状态。
4. 一个商品只保留一条当前待排查任务。
5. 只生成当前应执行的最高阶段。
6. 批次正式排查 0 件后停止跟踪。
7. 商品库存明确为 0 后结束该商品全部批次生命周期。
8. 商品级库存归零后的历史旧批次不得自动恢复。
9. 正式排查记录不可删除，只能修改并留痕。
10. 软件不得依赖电脑 24 小时开机。
11. 启动不得全量扫描全部历史数据。
12. 后续扩展日用、美妆、家居、宠物时不得推翻现有数据架构。
